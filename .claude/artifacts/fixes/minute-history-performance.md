# Bug: 历史K线获取及数据修正反复回扫近期历史

> Status: FIXED（源码；运行环境尚未加载）
> Mode: --deep

## Symptom / Expected

用户报告本地一个月1分K预计十几分钟，ECS同类操作数小时。
期望先核对实际范围和阶段，再减少已确认的重复取数，保留数据及任务契约。

## Reproduction

新测试`backend/tests/test_minute_history_request_budget.py`经过完整rustdx分页、
周期服务及临时Parquet写盘，断言一个闭区间自然月只需一次近期历史回扫。
原实现连续3次均2 failed / 1 passed，月度请求70次而预算13次。
真实小样本为同8证券、2026-06-17至2026-07-17，原实现7窗口、1344请求。

## Root cause / Fix

调用链为`/api/kline/sync_period→kline_periods.sync_period→fetch_period
→RustdxProvider.get_minute→_bar_records→RustdxClient.bars→TDX`。
TDX按相对最新数据的偏移量分页，服务每5天重新从0回扫；历史越早，重复前缀越大。
第一阶段将1分K分段上限改成32自然日，每批100证券不变，包含最长自然月的两端边界。
全面检查确认`repair_daily missing→kline_gaps→fetch_period`以及日K/指数/ETF、
历史复权因子也共用从0开始的分页。最终在`RustdxProvider._bar_records`按实际页时间
指数探测及二分定位结束边界，连续读取至起点；探测页只在当前调用中复用，
不同调用重读源，以支持历史数据修正。最大页数仍约束全局偏移，不增加源历史深度。
异常探测回退原保护的顺序扫描，所需页失败和协作取消不吞掉；
日/周K包结束整日，分钟仍按北京时间精确过滤。
遗漏仍仅请求连续缺口、仅补写缺失键，原价格口径、分区锁、
并发重读、视图/缓存失效与任务契约保持。本地派生周期不新增远程请求。

## Pattern analysis

搜索`days_per_chunk = 5|start=page * _PAGE_SIZE`命中周期调度与rustdx分页两处。
两处均为已修复根因：服务减少月内重复分段，Provider减少每个旧窗口的近期前缀下载。
直接最新分钟/报价和目录验证使用短偏移，不经过历史分页；
5/10/15分K及服务周/月K本地生成，无需远程补丁。
更长窗口仍分段且TDX只提供有限近期页；未增加跨任务缓存或猜测停牌/交易日偏移。
