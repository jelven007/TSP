# Bug: S02旧日期缺结果及选名单遮住买入记录

> Status: FIXED
> Mode: default
> Severity: P1
> Last updated: 2026-11-06

## Symptom / Expected

用户选择自定义s02及2026-11-04时整日结果为空；2026-11-05的买入页签显示待确认。
应该读取同一租户、稳定策略ID、所选日期已保存的信号归档，保留原参数与真实时间。
资格名单只能在没有实际扫描归档时作为预选结果显示。

## Reproduction

真实浏览器登录、在策略池添加s02、点击策略日期选择4日和5日。
4日没有每日结果页签；5日为卖4、选574、买待确认。
独立生产源码副本的新回归测试连续三次为3 failed；候选同测试通过。
测试路径：`backend/tests/test_screener_signal_history_regression.py`。

## Hypotheses & diagnosis

| 假设 | 判断 | 证据 |
| --- | --- | --- |
| 数据库归档被删除 | 排除 | 原始归档仍保存4日买4/选281及5日买40/卖4/选574；只读SQL与明细API均可读取 |
| 当前依赖版本阻断历史查询 | 根因 | 90秒改60秒使依赖指纹变化；摘要只查当前指纹及资格日键，4日无匹配、5日退回资格记录 |
| 前端日期切换或迟到响应 | 排除为此次根因 | 不经页面直接GET两个日期，服务端同样返回缺失或仅预选 |

## Root cause / Fix

归档写入使用计算身份，历史查询却也按当前身份取记录。定义更新后旧扫描不可见，
稳定日键的资格记录只能补选名单，不能替代实际扫描。
普通分钟信号策略的日期摘要现在按稳定ID/资产/周期及日期主键范围查询，
优先实际扫描，再按started_at选择最新记录；成功空扫描同样优先。
API明细使用摘要选定的record_id，摘要/明细保持同一份归档。
预置连续组合、普通日线与默认仓库read调用保持原身份语义。
没有SQL迁移、历史重算、删除归档、参数写入或新策略执行。
