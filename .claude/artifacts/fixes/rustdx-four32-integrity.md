# 四站32的差异与漏采修复

Status: VERIFIED（工作区连接修复；四站来源校验为隔离实验，未部署）
Date: 2026-10-29
Severity: functional

用户要求：“为什么有1945条数据不同且缺数据？排查原因并修复”。
候选保持四站每站8、总32；单站8仅作为既有对照。

## Root cause

- 旧复用槽位只比较TCP配置，未检查健康。心跳失效后读取peer地址在macOS报EINVAL，
  映射为终止性的InvalidInput，在0行情请求时跳过整只证券。
- 旧完整候选的1,945条差异涉及44证券。独立原始报文解码证实跨主站的原始量额位模式、
  价格和记录字节已有差异；固定endpoint及connection_id不足以证明数据版本等价。
  本轮连接修复后的冷/热数据差异为2,253/2,363，均来自非117来源。

## Fix

正式工作区仅在复用入口增加`Tcp::is_reusable()`检查，先关闭失效会话，
再重建连接；既有SourceChanged机制丢弃旧页并从头完整重采。vendor/core保持不变。

隔离四站方案保留实际32连接，逐证券完整校验本次窗口；冲突时使用固定117来源的
本次完整重采结果，空参考或重复键拒绝返回。参考数据来自真实行情请求，
旧parquet仅用于验收哈希对照。实验未注册为生产插件。

## Regression test

`backend/tests/test_rustdx_stale_source.py`通过真实POSIX socket shutdown注入心跳失效状态，
覆盖首个新请求和已固定来源的分页。旧wheel重复RED，新wheelGREEN，旧wheel反向RED。

四站来源校验6项测试覆盖值冲突、候选缺键、参考缺失、重复键和公共采集入口。
在子进程绕过来源校验后测试失败，正式代码未被临时反转。

## Verification

- 主工作区实际构建wheel；14个受影响Python模块201 passed。
- 主工作区Rust7 passed；Clippy、rustfmt和Ruff通过。
- TCP容量门实际32、每站8，错误来源0请求拒绝。
- 100证券/2026-08-03至08-31，来源校验冷/热两轮各504,000分钟行、2,100日线行；
  缺键、额外键和值差异均0，哈希与冻结对照相同。
- 校验版总耗时53.95/42.67秒；完整参考采集增加36.15/31.19秒。
  冷启动首个快照约19.95秒，当前不能宣称四站已整体提速或达到生产发布标准。
- 109个vendor文件与冻结基线一致；版本v0.4.38保持；未提交、推送、部署或写行情。
