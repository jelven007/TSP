# 行情状态请求超时修复

## Triage

- 用户症状：`请求超时（30s）· /api/intraday/status`。
- 期望：多标签页读取状态和接收告警持续可用。
- 环境：本地 v0.4.34、Vite HTTP/1.1、Chrome，同一浏览器上下文六个页面。
- 范围：前端全局行情 SSE 传输；不改变 API、超时值、行情采集和用户配置。
- 开发在固定主线提交的隔离源码完成，再仅移入四个流相关源码/测试文件，保留并行改动。

## Hypotheses and diagnosis

1. 后端状态读取、认证或缓存处理慢：若成立，独立 HTTP 请求也应持续高延迟。
   本地独立请求约 2–3ms，线上约 33–35ms，单页面浏览器请求均成功。
   历史路由指标未出现对应 30 秒执行，不能解释已捕获的浏览器排队。
2. 浏览器长连接耗尽：若成立，同一 HTTP/1.1 上下文六页各持有 SSE 后 REST
   排队，关闭额外页立即恢复。真实 UI 复现 11 条行情状态请求在约
   30.000–30.002 秒中止，并显示同类提示；关闭五页后剩余页面恢复 200。
   该路径 confirmed，首次引入连接占用的位置是每页独立创建全局 EventSource。

这是可确定的复现路径，未读取或关闭用户原有浏览器标签页。

## Fix

- `sharedQuoteStream.ts`使用 Web Locks 选出唯一连接持有页，用 BroadcastChannel
  传递事件、连接状态和游标，身份包含账户、租户及 auth_version。
- 持有页取得锁后才请求新票据；关闭、卸载、账户变化时释放连接/锁/通道，
  丢弃迟到票据和旧身份事件。票据请求尚未返回时卸载也立即释放锁，
  不能让其他页面等待已放弃的授权请求。
- `useQuoteStream`保留原告警、实时刷新开关、精确查询失效及指数退避。
  从共享游标重连，保留晚加入页接管后再次换票的进度。
- 无 Web Locks 或 BroadcastChannel 的浏览器保留原单页连接行为。
  此路径仍受 HTTP/1.1 多连接上限约束。
- 其他任务进度 SSE 未包含在本次修改中。

受影响缓存层只有前端事件驱动查询；后端仓库缓存、行情发布和持久化不变。

## Regression and verification

- 原始实现连续三次运行新回归：3 失败、1 通过，每次六页建六条连接。
- 修复后：共享回归 10 项通过，连同已有流和账户回归 17 项通过。
- 临时撤掉共享选举逻辑：共享回归重新失败，六页变回六条连接；
  恢复相同代码后 10 项再次通过。
- 补充授权在途卸载回归：初版失败（第二页无法取票）；修正后通过。
  最终共享回归11项，连同已有流和账户回归18项通过。
- 最终隔离源码完整前端测试：84 文件、448 项通过。
- 隔离源码 `pnpm lint`通过；`pnpm build`通过，保留原有大 chunk 提示。
- 最终工作区集成后：18 项定向回归、`pnpm lint`、`pnpm build`、
  `make check`和`git diff --check`通过。文档检查31文件，应用版本仍为0.4.34。
- 首轮真实浏览器：257条状态请求无失败或超时；六页、正常换票、持有页关闭
  接管均只有一条连接，接管后五页状态均200。行情状态最慢约472ms；
  数据状态最慢约2.898s。候选依赖软链的字体请求出现403，因此整页QA判失败。
  已在候选Vite配置中仅允许该依赖目录，字体HTTP探测恢复200。
- 字体修正后的完整真实浏览器验收：六页共享、正常60秒票据轮换和关页接管
  均通过。260条状态请求中259条成功，一条是导航时正常取消；
  无非预期失败或30秒超时，行情状态最慢约467ms，控制台无错误。
- 最终候选补充短流程：客户端触发到期事件，但换票、SSE和REST使用真实接口；
  23条状态请求无非预期失败，换票及关页接管后仍只有一条连接，
  剩余五页状态均200，没有框架覆盖层或超时提示。截图检查1440×900和390×844。
  GitHub版本检查返回403/CORS，已按来源识别为外部检查失败；
  本地接口及运行时无非预期错误，不把该流程称为所有外部资源均成功。
