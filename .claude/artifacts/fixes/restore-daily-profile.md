# Bug: 日K画像被误改为本地生成

> Status: FIXED
> Mode: default
> Severity: functional
> Last updated: 2026-10-27
> Baseline: ded70245 / v0.4.33

## Symptom / Expected

用户反馈数据总览中日K功能改错，要求恢复之前的功能并参考1分K。
日K画像应提供历史数量、月/年与“获取数据”，获取后继续原除权/指标流程；
按日K生效数据源能力及数据任务状态控制提交。

## Reproduction

`KlineSyncConfig.test.tsx`新增/调整日K历史控件、请求、说明、运行中禁用及失败保留用例。
旧实现连续三次均出现6项失败、10项通过，日K缺少历史输入和获取按钮。
隔离副本在修复后恢复HEAD的旧组件，定向用例重新失败；恢复当前组件后通过。
原工作区未stash、回滚或覆盖并行修改。

## Hypotheses & diagnosis

| 假设 | 优先级/置信度 | 结论 | 证据 |
| --- | --- | --- | --- |
| 日K被广义“非1分K”条件误归入本地生成 | 1 / 高 | confirmed | `generate = period !== '1m'`同时隐藏历史控件、豁免能力、改为仅传period和“生成数据” |
| 后端历史获取能力已被删除，必须重建接口 | 2 / 中 | eliminated | 显式1d/value/unit仍委托extend_history；服务保留日K→除权→指标，新增月/年任务及能力拒绝用例通过 |

## Root cause / Fix

离线生成调整把所有非1m周期作为同类，而日K是Provider基础数据。
界面只传period时后端进入兼容的本地重算路径，因此不能再获取更早的原始日K。
共享组件改用既有`isLocalDerivedPeriod`定义，1m/1d提交显式历史范围；
恢复日K后续除权及指标说明。5/10/15分钟、周K仍按原本地生成契约执行。

L3局部接线，无新增API、schema或配置。后端生产源码未改；
旧无范围日K API兼容保留，前端日K画像已经使用历史接口。
用户同步开关和时间、历史数据、修正入口的全量/遗漏功能不需要迁移。

## Pattern analysis

git grep检索generate的周期判定：前端共享表单已使用准确派生周期集合；
后端`sync_period`仍支持旧无范围日K生成，这是显式范围之外的兼容入口，
此次不删除它，不改变全局日K能力路由。
六类生命周期文档和操作说明同步区分日K历史获取与派生周期生成。
