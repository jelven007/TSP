# 分钟采集失败与性能修复

用户要求修复本地1分K失败、检查同类问题，并严谨验证本地/ECS采集性能。
基线v0.4.37，不修改版本，不自动提交或推送，保留已有与同期修复。

## Confirmed causes

- 排队和传输共用单次超时：同槽占用2.2秒、实际传输1.1秒时稳定失败。
- 遗漏补采按交易日/连续片段重复定位页：100证券单月42窗口、38,100请求。
- 全闭市尾段仍请求全市场。
- 已解码行重复JSON编码/解码；24万行解析1.497秒。
- 派生分钟读取混合schema失败，跨标的批次进度倒退。
- 必需坏页被当成可正常终止分页，发布部分历史。

## Fix

沿原客户端、Provider、周期服务、分区锁和缓存链修复。
排队/重连由60秒请求预算约束，实际传输仍用用户套接字超时。
遗漏按100证券/32自然日请求，多日响应只保留精确缺口；单日连续缺口保留。
仅跳过日历确认的闭市段；复用兼容扫描和已解码数组；拒绝坏页的单证券历史。
同期逐证券隔离及持久缺口报告纳入整合，取消/写盘/批次失败不被吞掉。

  最新TCP回归本地/Linux各14项通过，文件/目录分页预算继续保持。
- 基线服务反向加载11失败/2通过，当前整合定向227项通过。

  各方案504,000行且规范内容SHA256一致。
- ECS遗漏480.378→12.591秒，38,089→1,400请求；旧492,000行逐值相同，
  新补12,000行与旧全量及本地一致；最新候选各504,000唯一键、remaining=0。
- 最终全量后端4,650 passed / 162 skipped / 173 warnings，exit 0；
  Linux候选原生验收及清单校验已通过。

  Ruff42项既有、0新增。
