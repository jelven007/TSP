# 策略结果批量操作实施计划

**目标：**落实用户指定的同排批量自选／持仓入口、当前结果页范围、新建自选分组和持仓批次默认值。

**架构：**策略页控制当前每日结果页签，两个操作共用当前页股票；复用现有批次表单和服务端交易日历。历史风险参数读取归档快照，未归档结果读取有效策略设置。仅为 L3 前端内部改动，沿用已有 API 和查询键。

1. 先补 `Screener.test.tsx`：卖／选／买范围、空页、日期切换、批量持仓入口。
2. 先补 `strategyLotDraft.test.ts`：成交字段、缺失及零值、百分数换算、历史覆盖优先、显式取消阈值。
3. 先补自选菜单和策略批次测试：新建后加入、失败保留输入、成交预填、节假日日期、迟到日历不覆盖手选、保存失败。
4. 运行新增测试确认缺失行为；实现当前页签控制及两个按钮的同排布局。
5. 提取共享 `LotBatchDialog`，接入策略草稿；手动新建批次仍保留原先的空日期默认值。策略入口先载入快照及批次号，失败支持重试。
6. 自选菜单通过可选新建入口打开共享 Modal，沿用名称长度、分组颜色及创建 API，成功后更新分组缓存并执行加入。
7. 执行定向测试、前端全量测试、lint、build、文档及差异检查。同步六类主手册、操作说明和工程追踪。

异常边界：缺成交数量／均价留空提示补填，不用行情价伪造成交；未知交易日历允许手选；历史快照读取失败不套用最新参数；保存失败保留草稿和幂等请求 ID。

范围：本地源码实现和验证；不提交、不推送、不部署、不递增版本，不覆盖已有工作区改动。
