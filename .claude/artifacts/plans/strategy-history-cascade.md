# 删除策略同步清理历史结果

来源：用户要求“策略被删除，则相关产生的历史结果数据也要同步清理”。
本次为 L3 内部生命周期变更，沿用策略删除 API 和现有稳定 ID；不新增公共扩展接口。

1. 按稳定 ID 清理所有日期、名称、参数、周期、逻辑版本的选股历史，保留其他 ID 和租户。
2. 删除源、历史与持久化删除世代共同提交；失败不返回成功。SQLite 与文件间使用补偿恢复，
   Full 使用现有租户业务事务。保存时核对捕获的世代，禁止旧执行快照写回。
3. 同步删除直接引用该 ID 的研究任务及附件、研究候选、本地回测溯源清单；
   任务删除撤销提交资格。冻结公共研究输入可能被其他试验共用，不作为策略结果删除。
4. 重建相同 ID 时重新启用当前世代，新执行可保存，旧执行不能污染新历史。
5. 更新删除确认文案和相关前端查询；模拟交易成交/持仓账本继续按账户保留。
6. 先运行真实存储失败测试，再最小实现，验证删除失败、回滚、权限、跨租户、
   迟到写回与同 ID 重建；执行相关回归、Ruff、前端构建和文档检查。

范围：修改并验证源码，不部署、不提交、不改版本、不对现有运行数据追溯批量清理。
