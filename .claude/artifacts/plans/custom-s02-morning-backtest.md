# 自定义s02早盘清仓收益回测 Implementation Plan

> 执行方式：本会话逐项实施，沿现有用户授权完成本地修复；不创建提交、推送或线上部署。
> 开发流程：回归先红再绿，逐步实施并检查实际结果。代码、数据和设置均保留已有修改。

**Goal:** 自定义通用分钟s02使用当前尾盘入场、日线叠加及早盘清仓规则运行连续资金收益回测，不再被“早盘清仓暂不支持收益回测”硬拒绝。

**Architecture:** 复用`MinuteSignalReplayer`的同源入场路径和`morning_liquidation.evaluate`的纯出场规则，
新增范围明确的通用持仓分钟撮合模块。模块持有本次研究的现金和实际买入批次，
按时间顺序处理出场/入场并输出现有`StrategyBacktestResult`，不读取或修改模拟账户。
原预置s02专用执行及未选择早盘清仓的通用分钟回测保持原路由。

**Tech Stack:** Python、Polars、现有MatcherConfig费用/数量规则、React/Vitest、已有本地Compute和Playwright。

## 已确认事实与范围

- `StrategyBacktestService.run`当前首先拒绝任何早盘清仓；通用分钟分支还拒绝`overlay_filter`，
  并把入场分钟转成日线网格，不能按次交易日的分钟卖点成交。
- 当前自定义s02：沪深主板、ST/停牌排除、流通市值50～500亿元、前日涨幅0.5%～6%；
  已完成20日均成交额≥1亿元；涨跌幅100%高值评分；
  尾盘走强14:30、0.4%～4%、全池上涨≥60%、7个1分/4个5分MA5严格递增；
  早盘振幅≥6%或10:30截止。固定/移动退出及最长持有关闭。
- 保留回测页面现有初始资金、仓位/暴露、佣金、最低佣金、过户费、印花税和滑点输入。
  不借用预置s02的资金、买价、参与率或冻结账本。
- 初始支持A股连续组合模式和通用分钟策略；专用分钟执行、独立全量模式、
  混合未支持的其他出场、冻结日线入场风险、环境过滤及额外固定/移动风控须明确拒绝，
  不静默忽略。当前自定义s02不使用这些冲突功能。
- 只运行隔离合成行情的收益撮合验证和本地界面检查，不擅自新增真实行情收益回测或Excel研究报告。

## 正确性约束

| 必须保持安全 | 依据与验证 |
| --- | --- |
| 买入当天不能卖，同一批次仅在精确下一交易日进入清仓判断 | 已发布交易日历、买入日期和周末/节假日样例 |
| 不读取当日未完成日K来判断日线准入/均额，不以最终选股快照替代触发分钟 | 同源回放器、未来值反例和真实模板样例 |
| 全池广度分母只受股票范围/流通市值约束，不能被其他数值或均额过滤缩小 | 全池与候选分离测试、symbols子集仍加载全池 |
| 未成交不能记现金/费用/盈利；现金不得负，卖出不能超剩余数量 | 整数股数、最低佣金、逐次现金守恒、剩余批次断言 |
| 振幅使用原始昨收，成交量单位为手、股数单位为股 | 原始/复权不同、分钟容量与股数反例 |
| 缺前缀分钟、重复分钟、缺原始昨收不能伪造首次触发或成交 | 明确数据失败，不回退其他日 |
| 截止后仍有到期持仓须保留实际分片/余股并返回失败，不能认证完整收益 | 零量、跌停和容量不足反例 |
| 入场优先级及预算只用当时已知数据，不能先花未来卖出现金 | 按事件时间排序、多个候选、暴露/持仓限制测试 |

有足够可成交容量时，已触发清仓应持续处理余股直到当日截止；有限区间末日新买入可作为未平仓估值，
不能强制当日违反T+1卖出。缺数据的未知状态保持为失败，不能改写为成功零成交。
本模块是单次纯研究状态，不存在真实委托重试、外部资金转移或跨进程所有权。

## 撮合约定

- 入场仍沿`META.minute_entry_fill`：默认信号分钟收盘，声明next_minute_open时使用紧邻下一分钟开盘，
  缺该分钟不成交。保留成交时间和信号时间。
- 早盘纯指标只由已完成分钟确认；收益撮合采用触发分钟收盘价，
  振幅提前触发后余股沿随后分钟持续处理，截止10:30不使用10:31价格。
  该约定明确记录在结果config/strategy_info中，不混同日K的close_t/open_t+1。
- 原始价格先施加各方向不利滑点，费用计算使用无额外滑点的现有MatcherConfig，避免重复扣滑点；
  卖出按实际日期执行现有历史印花税口径。
- 仅使用实际分钟成交量作为容量上界（最多100%，不虚构预置策略参与率），入场不足可部分买入；
  清仓不足保留余股并失败。结果须明确该容量上界，不把它宣称为实盘可执行参与率。
- 相同股票研究批次遵守现有通用持仓限制；当天卖后重新入场沿现有通用撮合的限制，
  不因新增模板悄悄放宽仓位/再入场策略。

## 方案选择

1. **采用：同源入场回放＋有界分钟持仓账本。** 少量新模块保护本次规则，不修改所有策略的矩阵内核。
2. 扩展日线矩阵内核加入逐持仓分钟回调。可统一未来出场，但改动核心撮合范围较大。
3. 建立任意信号/秒级通用事件引擎。表达能力更宽，本次没有该范围需求。
