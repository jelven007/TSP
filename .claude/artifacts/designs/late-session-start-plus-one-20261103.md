# 尾盘建仓启动后一分钟检查设计

用户已纠正：加1分钟是等待14:30 K线完成，不是把数据窗口移到14:31。
本设计以用户此次纠正为准，先前“1m截至14:31”的解释废止。

## 用户口径

- 启动时间默认14:30，可设置。
- 可计算时间固定为启动时间+1分钟。完整当日股票池上涨占比用启动分钟完成截面，
  下限默认60%，可设置；分母保持股票范围与流通市值约束的完整池。
- 涨幅上限默认4%，下限默认0.4%，均可设置；按启动分钟完成原始收盘价
  相对精确原始昨收计算，包含上下限。
- 启动分钟1分钟MA5连增数量默认7，可设置。数量是MA5值的数量，
  7个值对应6次严格递增；默认比较14:30至14:24，在14:31才可计算。
- 截至启动时点最新完成5分钟MA5连增数量默认4，可设置。
  默认比较MA5(14:30)>MA5(14:25)>MA5(14:20)>MA5(14:15)，共3次严格递增。
- 六项条件为且关系。等值不算递增；缺完整池报价、昨收、连续完成K线时不触发。
- 启动整分钟支持13:00—14:59，保证+1分钟仍在当日午后交易时间；
  保持MA5不跨午休/日期的现有约束。

  当前时间同时用于行情截止、广度、1m/5m窗口和池公告观察。
- `strategy/engine.py::_inject_intraday_signal_columns` 当前将信号标在`time`分钟。
- `services/late_session_replay.py` 当前返回`parameters(sig)["time"]`。
- `backtest/minute_replay.py` 复用引擎及模板评估，真实触发分钟决定信号收盘买价。
- `services/screener.py` 与回测共同调用`pool_cutoff`。
- 编辑器为`frontend/src/components/signals/CustomSignalDialog.tsx`，
  类型/默认值/摘要分别在`lib/api.ts`、`lib/customSignals.ts`。

## 方案与取舍

推荐在现有模板加入内部可选`evaluation_delay_minutes`，新保存定义写入1。
既有六项参数ID保留；界面仅展示用户要求的六项，不新增可编辑延迟选项。
历史冻结定义缺该字段时按0兼容，保持原14:30语义；新HTTP保存与新编辑器
统一写入1。编辑旧定义时说明保存后升级为启动后一分钟，不改变历史归档。

另外两种方案是直接整体改模板时点、或新建另一模板。前者会改变旧冻结
定义解释，后者增加模板及注册接线。本方案复用现有模板和列名，
只增加时间契约的明确版本标记。

`evaluation_time(sig, day)`返回可计算时点，实时门闸及池公告观察使用它；
`bar_time(sig, day)`返回启动数据标签，价格/广度/1m截止用它，5m向下对齐该标签。
脉冲附着启动标签的真实行，携带`entry_evaluated_at`；回放分别保留数据及计算时间。
默认14:31才可确认14:30结果，任何14:31未完成行情不能改变条件。
next_minute_open按14:31真实开盘；旧signal_close保留参考价口径，事件不得提前。

此为L3聚焦行为修改，没有新增Provider、SQL迁移、通用策略或自动交易接口。
现有s02源、出场涨跌6%及10:30/10:45、日线叠加、账户资金和仓位保持。
旧回测文件及原执行输入保持。

## 完成标准

- 六项默认值、顺序、保存和刷新回显正确；启动时间控件与说明一致。
- 14:30不可确认，14:31才计算；数据行仍14:30，不伪造或借用14:31行。
- 14:31与14:30上涨比例不同的夹具证明采用14:30完成截面。
- 精确验证5m四个MA5值对应用户示例，不多要求一次递增。
- 验证1m七值、等号、缺口、重复、未来行、时区、午休及自定义时间。
- 引擎、API回放、分钟回测、池公告观察和现有旧定义回归通过。
- 前端相关测试、生产构建、增量lint/文档/空白检查通过。
- 本地运行安装按既有完整发布单元验证，活动配置和源已有修改先保护。
  实际运行状态与源码/测试分开记录；收益回测须用户另行指定。

没有占位字段；变更只围绕启动+1分钟语义。
