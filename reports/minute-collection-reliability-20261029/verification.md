# 分钟采集失败与性能复核

日期：2026-10-29。基线：v0.4.37 / f4d8c11b。
两端隔离真实取数、候选Linux验收及最新全量后端回归已通过。
源码修复、真实取数结果和常驻服务升级分别记录。
当前没有提交、推送或升级常驻服务，不递增版本。

## 已确认的根因

1. 原生桥接把连接排队、节点资格检查、重连和实际传输压在一次套接字超时内。
   本地模拟同槽财务请求占用2.2秒、分钟传输1.1秒，传输本身小于2秒超时，
   旧桥接仍连续三次失败。新实现以60秒请求预算约束排队和重连，
   入槽后才启动原配置的传输超时；没有调高用户配置，也没有增加连接上限。
   随后在除权单次请求复现相同故障并修复共用入口。
   显式股票目录/行情元数据/财务文件仍使用各自分页或整批预算；
   不把多页文件总时限压成单页传输时限。
2. 全量已使用32天窗口，但遗漏模式仍按每天的连续缺口调用Provider。
   同100证券/21交易日产生42次逻辑获取，反复定位同一批历史页。
   现在遗漏模式也按100证券、最多32自然日扫描及请求，多日共享一次定位，
   返回记录与精确缺口相交，锁内只补缺失键；单日仍保留连续缺口和午休边界。
3. 全量的休市尾段仍对所有证券定位历史页。现在仅跳过公布日历已确认全闭市的段，
   未知日历继续取数，不用周末估算或未知日期冒充休市。
4. 带来源/计数的响应已经解码，Python随后又把rows编码、解码一遍。
   现在直接验证已解码数组并复制记录，继续保留结构校验、请求计数、
   来源检查、时间和零值转换。24万行独立解析分析从1.497秒降到0.829秒；
   这是解析样本，不是全市场耗时或稳定SLA。
5. 派生分钟K仍用裸Parquet扫描，混合额外列/缺列可报SchemaError。
   遗漏和全量派生均接回scan_parquet_compat；跨100证券的进度不再倒退。
6. 必需历史页重复或缺少有效时间时，旧代码只停止分页并返回已累积的部分记录。
   现在拒绝该证券的不完整历史，写明证券和分页错误；探测失败安全回退、
   短历史及真正空页继续沿既有规则处理。

工作区同期的逐证券隔离契约一并验证：健康证券继续采集，来源变化完整重采一次；
持续失败的证券不提交不完整页，remaining、warning及持久CSV反馈未补齐记录。
批次异常、取消、写盘和本地派生失败仍是失败。新增字段与专项授权记录见
[逐证券契约](../minute-301110-20261029/skip-and-backfill.md)。
