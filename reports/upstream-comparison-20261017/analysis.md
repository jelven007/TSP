## 3. 第一批：正确性与执行安全

这里的 P1/P2 表示建议处理优先级及实际影响；本报告不是某个 PR 的合并审批。

### A1 · P1：吸收策略代码校验加固

**证据：**当前 [ai_generator.py:371–415](../../backend/app/strategy/ai_generator.py#L371-L415)
主要检查危险函数的直接调用和固定 dunder 名称。
临时静态验证发现 `eval`、`getattr` 的别名引用、拼接字符串下标以及
`DataFrame.write_csv` 引用均被接受。
[engine.py:401–408](../../backend/app/strategy/engine.py#L401-L408)
还保留校验异常后继续加载的宽泛异常处理。

**影响：**单机/桌面路径会导入用户 Python 策略，校验不能有效限制这些绕过形态。
多租户私有策略已有一次性无网络、只读、限资源容器，影响范围不能等同于主 API
执行，更不能据此宣称多租户主机已被攻破。

**上游：**[b22a970](https://github.com/shy3130/tick-stock-panel/commit/b22a970097f99bdece126bc1d9e93e6ad71beaed)
及 [当前安全回归](https://github.com/shy3130/tick-stock-panel/blob/5825c7b53798d9f45841cec8fee31a260d58a350/backend/tests/test_strategy_safety_validation.py)。

**改进：**封堵危险引用、别名、拼接、模块句柄和文件原语；加载层无法验证时拒绝。
保留合法矩阵/Polars 策略兼容，并继续使用已有 Compute Broker 隔离。

**验收：**恶意静态样例全部拒绝，现有合法策略全部可描述/执行；单机与多租户入口
分别回归。本次只执行静态检查，没有执行命令、外传或文件破坏载荷。

### A2 · P1：统一模拟盘日线读取，避免 schema 差异关闭交易校验

**证据：**[paper.py:1189–1249](../../backend/app/strategy/paper.py#L1189-L1249)
三处读取仍直接 `pl.scan_parquet`。构造三个日线分区，其中一个多出
`quote_ts` 后，昨收预期 `10.71` 实际返回 `None`；当日 OHLC 也返回 `None`。
异常是 `extra column in file outside of expected schema: quote_ts`。

**影响：**涨跌停校验拿不到昨收，开盘/收盘结算把存在的行情当作缺失而顺延，
基准净值也可能无法生成。

**上游：**[b7892e4 / #463](https://github.com/shy3130/tick-stock-panel/commit/b7892e49e256322efa1b9b9f9972d834430c77da)。

**改进：**三处统一使用当前已经存在的 `scan_daily_parquet`；
同时区分读取失败和真正无行情，不能让不可验证的价格限制自动跳过。

**验收：**股票、ETF、指数的混合新旧分区都返回正确价格；结算与涨跌停负例通过。

### A3 · P1：统一北京日期缺省值

**证据：**[backtest.py:134](../../backend/app/api/backtest.py#L134)、
`factors.py`、`regime.py`、`market_mainline.py`、`regime_builder.py`、
`repair_daily.py` 仍有 `date.today()`。
把北京日期入口固定为 `2026-03-02` 后，回测缺省终点仍取测试机日期
`2026-10-17`，证明没有走项目北京日期入口。
这是日期入口验证，不是实际修改服务器时区后的全链路验收。

**影响：**在非北京时间服务器上，缺省研究窗口、修复窗口和环境更新可能错日。
当前 K 线和盘后部分路径已经修复，不能认定全链路都未处理。

**上游：**[fbf9c8b / #429](https://github.com/shy3130/tick-stock-panel/commit/fbf9c8b767aa23b5369843039c509bede80fe1c3)。

**改进：**业务日期统一从 `cn_today()` 获取，显示时间、UTC 日志和计时器分别处理。

**验收：**UTC、美西、北京时间以及北京午夜/跨日样例，REST 与 SSE 默认窗口一致。

### A4 · P2：缓存换代后有界重建

**证据：**[repository.py:488–522](../../backend/app/tickflow/repository.py#L488-L522)
预热线程只刷新一次；换代异常被刷新函数记录后返回。
注入换代异常后实际刷新一次、线程退出、warming=false、历史缓存仍为空。

**影响：**启动预热撞上数据发布/实时刷新时，可能长期走冷缓存按请求计算。
本次没有量测用户实际延迟，不把它写成既有生产性能故障。

**上游：**[95e1519 / #480](https://github.com/shy3130/tick-stock-panel/commit/95e151999430e87149d455ea1df7a922d95091ea)。

**改进：**区分成功、换代和其他失败；只让后台预热在新 generation 下有界重建。
继续保留当前失效和发布保护，前台不能变成无限重试。

**验收：**首次换代后恢复、持续换代达到上限、磁盘错误不反复重算；
按同一数据规模记录缓存命中和请求耗时。

### A5 · P2：固定自动卖出按可卖余额封顶

**证据：**[paper_auto.py:207–218](../../backend/app/strategy/paper_auto.py#L207-L218)
固定 sell 规则直接按金额换算数量。
实际持有 500 股时，大金额规则请求卖 1,000,000 股，被整单拒绝；
已有待卖 200 股时也没有生成剩余 300 股卖单。

**影响：**用户用较大金额表达清仓，实际没有卖出。
当前 `side=auto` 已有退出待办、重试和去重，是另一条较完整的路径，不能覆盖退回
上游早期自动退出实现。

**上游：**[#462](https://github.com/shy3130/tick-stock-panel/pull/462)。

**改进：**仅固定 sell 路径取 `min(金额换算数量, T+1 可卖数量 − 已占用卖单)`，
保留当前自动退出待办、事件去重和账户事务。

**验收：**超额金额清剩余可卖仓、部分卖出、当日不可卖、待卖占用和重入幂等。

### A6 · P2：板块分钟异常价格治理

**证据：**[sector_rotation.py:165–169](../../backend/app/services/sector_rotation.py#L165-L169)
以及扩展维度分时计算只检查价格正数/有限。
临时样本昨收 100、分钟 close 1800，仍产出 `17.0`，即 **+1700%**。

**影响：**小板块均值、排名、轮动和主线判断会被单只异常数据放大。

**上游：**[d118d3f / #473](https://github.com/shy3130/tick-stock-panel/commit/d118d3fe99966f31887a9da8f9f506b55d4f8204)。

**改进：**统一复权基准、证券状态与价格规则，隔离异常点，反馈剔除数量和覆盖率。
上游固定 ±30% 过滤不能直接当作所有交易日的物理限制；沪深新股无涨跌幅限制阶段
可能合法超过此值，应按当前 `price_limits` 和交易日判断，并保留未知状态。

**验收：**错误倍率/基准、合法普通涨跌停、新股无价格限制、全异常板块、
剔除后成员覆盖率；避免把异常钳制成看似正常的收益。

## 5. 第三批：当前路线自身需要完成的工作

这些是两库对比后应保留并完善的工程事项，不宣称上游已经解决。

### C1 · P2：严格研究的历史股票池和原公告版本

当前已有历史 ST/SCD2、历史股本、财务归档 revision 和历史税率，不能再笼统建议
“增加 PIT/历史印花税”。

剩余边界是：首次四板有效股票同步解决当前在市范围，不代表已经纳入历史退市证券；
财务 revision 记录 `first_observed_at` 且 `publication_time_verified=false`，
也不能证明原公告时点的值。
[research_preflight](../../backend/app/backtest/governance.py#L66-L73)
明确没有认证幸存者偏差或完整输入快照。

建议补历史上市/退市样本和行情、财务原公告/修订可见时间，并在报告显示未知比例。
已有多租户不可变公共发布和按 release ID 执行应继续复用；
单机研究补等价输入固定、全窗口文件指纹和版本保留策略。
跨周期复测应证明输入版本一致，而非仅比较同名策略。

### C2 · P2：模拟盘公司行为与费用口径

当前与上游都继承了用 `ex_factor` 调整持仓数量/成本、现金分红不入账的模型。
当前 rustdx 算因子时已经拿到分红、送转、配股信息，但统一输出只保留价格复权因子。
价格因子不能代替实际送转数量或现金红利。

建议在标准数据契约中拆出公司行为事件，把现金分红、送转、配股及生效日各自入账；
同时明确模拟账户固定税率与研究历史税率的差别，保持存量账户兼容。
验收以现金、持仓股数、成本和总权益守恒为准。

### C3 · P2：真实数据链路与生产验收

当前已经有 rustdx 默认安装、节点备选、前后台连接调度、时间戳来源标记和基准脚本，
不应把旧报告中的“无节点切换/无优先级”再次当作当前缺失。

需要完成的是行情请求→标准化→写入→指标→网关→页面的分段持续量测，
确认完整覆盖、新鲜度、09:25、午休及盘后状态。
`received_at` 与源端实际更新时间要分别展示，不能用接收时间认证源端终态。

二期 Step 1/2 已有本地百人证据，真实 Nginx/容器 SSE、完整交易日、72 小时、
进程重启和联合恢复仍待签收。新原生产物已有 Linux arm64 本地证据，
