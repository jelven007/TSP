# rustdx 获取2026年5月1分钟K线的覆盖率核验

## 实测结论与范围

2026-10-30实测，当前可连接的rustdx通达信种子节点不能满足5月真实1分钟K线覆盖率至少99%的要求。普通分钟K档案存在已确认的整月缺口；按日期的分时和历史成交接口确实可以返回5月数据，但不能据此认证完整OHLC、成交量和成交额。证据来自部署中的原生Rust客户端、独立原始协议响应和线上源分区/公共发布分区复核。[1](#evidence-1)[2](#evidence-2)[3](#evidence-3)

结论限定于本次测试的41个既有节点，其中17个可连接、24个连接失败。未测试的节点、以后新增或恢复的档案，以及另行取得的真实历史文件，不在本次否定范围内。不同端点可能共享通达信底层档案，不能将其当作17家独立供应商。

## 实际覆盖率和99%门槛

沿用项目现有交易日、上市日期和240分钟键口径：5月18个交易日，应有22,406,400键。59只缺口见证证券在全部18天均有成交日K，已在最终复核中直接确认1,062个证券日，不能将这些整月缺口归因于整日停牌。[1](#evidence-1)

| 指标 | 实测或计算值 |
| --- | ---: |
| 线上源分区实际行数 | 42,960 |
| 公共发布分区实际行数 | 42,960 |
| 实际覆盖率 | 0.191730934% |
| 实际缺失键 | 22,363,440 |
| 达到99%所需有效键 | 22,182,336 |
| 在现有数据上还需增加 | 22,139,376 |
| 普通接口已确认不可返回的键下界 | 254,880 |
| 普通接口最乐观覆盖率上限 | 98.862467866% |

上限按“除59只见证证券外，其他所有股票都能完整获得”计算：
`(22,406,400 - 59 × 18 × 240) / 22,406,400`。
254,880个确定缺失键已超过99%允许的224,064个缺失键，超出30,816键。这个98.8625%是普通接口的理论上限，不是已经采集到的覆盖率。[2](#evidence-2)

最终线上复核时间为北京时间2026-10-30 07:10:08。源分区哈希与初始复核完全一致，公共发布文件哈希与源文件完全一致，重复分钟键为0。公共发布身份仍为`0477f15a7a3b4d4382e097b35f0a82cc`。[1](#evidence-1)

## 普通分钟K档案

初始核验覆盖41个种子端点，并用部署中的`RustdxClient.bars_json`及独立TCP解码核对两种1分钟类别8/7。随后对五类板块各选20只、合计100只股票，在17个可连接节点进行扩大核验；样本均在5月18天有成交日K且现存5月分钟键为0。[3](#evidence-3)[4](#evidence-4)

100只样本在所探测的普通K分页中返回5月行数为0。为避免把短页或固定探测偏移误认作档案末尾，对所有节点均有非空尾部的59只证券进一步按“请求偏移＋实际返回条数”推进，直至观察到空页，两个1分钟类别均完成核验。59只证券的最早档案日期落在2026-06-03至2026-06-11，全部晚于5月。[2](#evidence-2)

初始固定偏移测试只认证了2只证券的整月缺失，不能单独推出全市场99%不可达；最终254,880键下界来自上述59只证券的完整尾部核验。其余41只样本不计入此下界，保持保守口径。证券清单及每个交易日的缺口见缺口见证清单（附件保存在受控归档）。

## 按日期接口及重建校验

`0fb4`历史分时、`0fb5`历史成交和`0fc6`增强历史成交在17个节点上均返回平安银行5月6日、11日、29日的数据，共153个非空按日期响应。因此，“rustdx完全取不到5月任何数据”不符合本次实测。[5](#evidence-5)

历史成交重建完成了3只证券、3个日期、3个端点的交叉核验：其中8组证券/端点完成全部3日的分页，另1组在解码非法记录时被拒绝。每页价格累加器从0开始，保留参考价但不把它加入累计价格；偏移按原始条数推进至空页，状态8集合竞价快照不计作实际成交。9:25开盘撮合、正常交易和盘后状态分别处理。[6](#evidence-6)

最终分钟对账改用真实`052d`类别8源K，明确按股口径核实成交量。初步报告曾直接把线上存量分钟`volume`当作股数，产生了单位差异；这一探索性结果不用于最终结论，最终依据为`refined-reconstruction.json`。存量文件没有被修改。[7](#evidence-7)

| 日期与证券 | 源统计 | 完整成交记录或重建统计 | 判断 |
| --- | --- | --- | --- |
| 2026-05-06，600000.SH，全天 | 日K最高9.29元 | 成交记录最高9.28元，3个节点均复现 | 成交响应漏掉真实极值 |
| 2026-05-29，600000.SH，全天 | 日K最高9.38元 | 成交记录最高9.37元，3个节点均复现 | 同类差异可重复 |
| 2026-05-29 09:33，688496.SH | 分钟K最高1.05元，成交量266,000股 | 重建最高1.04元，成交量同为266,000股 | 成交量对齐仍不能恢复最高价 |
| 同一分钟，688496.SH | 源成交额277,225元 | 价乘量估算276,633元 | 估算金额不能替代源金额 |
| 2026-10-29 09:55，000001.SZ | 分钟K最高11.45元 | 重建最高11.44元 | 近期正向对照也存在极值损失 |

按日期返回的事件包含分钟时间、价格和量，不保证每次真实成交价格都保留，也没有源分钟成交额。`0fb4`只提供每分钟价格/量点，不能恢复分钟开高低和源成交额。项目Rust核心对`price × quantity`的金额本来就定义为估算，不能用它替换供应商报告的金额。[8](#evidence-8)

重建也缺少若干没有实际成交事件的分钟。这里没有对它们填零、沿用前值或令OHLC全部等于分时价格。236/240或218/240等匹配条数只描述样本中的保守重建结果，不能外推成全市场准确率或覆盖率。[7](#evidence-7)

## 可行路径及交付状态

现有节点上的重复普通分页采集无法消除已确认的5月整月缺口。达到99%的可行前提，是取得覆盖5月的真实分钟历史档案，或找到能实际返回该窗口完整源K的新节点/数据源，再按全市场键、单位、价格基准和源成交额完成覆盖验收。此类档案或新节点尚未在本次工作中取得，不能宣称已经满足99%。

本次完成的是实测可行性判断和证据交付，没有把重建估算写入行情库。线上有效覆盖率仍为0.1917%，99%采集目标未达成。
