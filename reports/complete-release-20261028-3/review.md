## 2. 产品与数据契约

- 数据总览删除独立「数据修正」入口。
- 1分K和日K卡片使用统一日历选择起止日期；全量和遗漏均严格使用所选闭区间。
- 遗漏模式先扫描本地真实缺口；无缺口时不解析Provider且不发上游请求。
- 1分K按最多32自然日、100证券分块；网络取数期间不暂停实时行情，仅写盘临界区协调。
- 5/10/15分K只从本地1分K生成，周K只从本地日K生成。
- 周K读取兼容日K分区渐进增加 `quote_ts/quote_time_basis` 等元数据列。
- 指数页默认60根，以实际数据封顶；日期控件同行，修正终态5秒后自动收起。
- rustdx固定为v2.0.4和桥接API3，保持七项Provider路由及8业务+1探测连接预算。
- ETF采集、存储、查询、研究、监控、回测和交易入口退役；股票及指数契约保持。

## 5. 生产就绪评审

结论：**未发现源码合并阻断项，可以进入PR和远程质量门；生产升级仍受下列门槛约束。**
这是作者自审及命令读回，不代表独立人工审批。

| 领域 | 结论与门槛 |
| --- | --- |
| 架构 | 沿用Provider、JobStore、Platform单写、公共发布和共享查询键，没有平行数据路径 |
| 数据 | K线schema向后兼容；ETF为显式退休迁移，指数必须逐目录和symbol保持 |
| 性能 | 历史分页同环境请求数显著下降；全市场耗时和正式P95仍须运行验收 |
| 安全 | 不写入真实SMTP授权码或其他秘密；账号、权限和租户schema不迁移 |
| 兼容 | 旧修正API、旧任务记录、已有Parquet和用户配置保持可读 |
| 恢复 | 两端升级前必须完成文件、双库和release manifest备份及真实恢复对账 |
| 产物 | 只提升main质量门通过后同一SHA的镜像；Runtime和Compute身份必须一致 |
| 可观测 | 核对健康、功能ready、任务终态、数据目录、业务记录和下一轮不再生 |

## 6. 发布流水线

1. 推送候选分支并创建PR，核对完整差异和远程质量门。
2. 合并到 `main`，等待CI自动提交唯一版本递增并创建同SHA标签。
3. 等待Docker工作流从 `ci-revision` 构建同一SHA，核对多架构镜像和清单摘要。
4. 同步主线并清理已合并分支；脏工作树先归档、核对哈希和Git引用，不丢失用户工作。
5. 本地先停写、备份、真实恢复验证、升级和ETF迁移；通过后再处理生产。
6. 生产重复同一流程，使用相同源码SHA和正式镜像；完成后再次独立读回。

任何阶段出现主线变化、CI失败、标签/镜像/SHA不一致、备份不可恢复、关键健康失败、
用户配置漂移、ETF再生或指数指纹变化，立即停止提升并保留旧服务。

## 7. ETF迁移与回滚

本地升级前指数基线为3,284个文件，
`3875cadbea47a205302d21475450f2543292ea3add08d619873629de80c5fe65`；
生产指数基线为491个文件，
`f8474e85ba4b582405c2710db6c8e58e6b66b5dc194c2fd6b9fd8bc69e1ea4d7`。

升级顺序：

1. 等待采集和研究任务终态并停止所有行情写入者。
2. 备份ETF目录、全部指数目录、身份库、业务库、受控配置和当前release manifest。
3. 在临时位置恢复双库并按表计数、业务摘要和管理员登录做对账。
4. 先加载已删除ETF再生路径的新代码，再删除四个独立ETF目录及对应generation/manifest。
5. 清理秒级混合表、自选、监控、持仓提醒、模拟交易、策略结果和研究输入中的ETF记录。
6. 重建DuckDB视图、缓存和公共不可变release，再按Platform先于消费者启动。
7. 核对ETF目录/业务记录为零，指数目录、symbol集合及指纹保持；下一次实时轮、
   盘后轮和再次重启后重复核对。

回滚必须同时恢复匹配的旧源码/镜像、公共数据release、双库及受控配置；
不能只回滚代码后继续使用已删除ETF记录的数据集，也不能用旧备份覆盖升级后新增业务。
