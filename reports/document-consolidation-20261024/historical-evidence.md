### 核心契约

- 保留完整前端路由、原页面和业务计算契约。
- 系统角色为管理员与租户；预置 `admin/Admin123` 支持改密，重启不重置。
- 管理员业务租户下拉框显示空间所有者的用户名或邮箱；无所有者的空间使用原租户名称。管理员目录新增 `display_name`，原 `name`、租户 ID、数据归属及普通租户目录保持原契约。
- 租户注册保留中文注册口令、邮箱验证码，成功后自动获得个人租户并进入看盘首页。
- 租户无法使用“数据”和非账户设置；服务端独立校验权限。
- 全角色移除数据源、大模型、实时行情的三个侧栏展示/快捷入口。
- 身份、业务状态、任务和权限版本持久化；私有数据、缓存、文件与事件按租户隔离。
- 平台行情继续共享，由唯一采集角色管理；新租户不初始化平台数据或配置源端。

#### 2026-10-14：AI 迭代、助手工具与报告隔离

- 原策略迭代器保持生成、回测、诊断和修改流程，草稿写入本租户 SQL 源码记录并保留 `research_only` 发布门槛。源码描述由受限计算服务执行；返回代码与最终持久草稿 ID 对齐。模型工具与最终补测使用持久研究队列，不生成全局回测文件。
- AI 助手明确区分公共行情目录与租户私有存储，自选、信号、策略参数、持仓提醒和回测不再读取旧全局业务文件。并发重复加入自选不覆盖已有备注和排序；创建信号只清理本租户策略缓存。
- 助手确认卡写入 SQL，绑定用户、权限版本和会话摘要；另一用户或另一会话即使拿到 `call_id` 也不能确认。不同 API 进程可读同一待确认卡；确认、超时、断连均回收条目。租户工具目录及快捷指令隐藏数据管理操作，服务端独立拒绝越权调用；AI 未配置时引导租户联系管理员。

### 时点一致性与可复现性边界

首板数量、连板梯队和 `consecutive_limit_ups` 是市场统计或通用策略输入，
不能仅凭这些字段断言实现了某个特定交易战法。具体策略以实际代码和领域
验收为准; 本轮发布与健康检查修复不对工作区新增“一进二”策略作效果结论。

1. **竞价历史**：09:25 是交易所时点，系统收到终态快照的时间通常更晚。
   当前只从启用日起归档服务端时间、接收时间、覆盖率和上一交易日匹配率。
   rustdx 不能补齐启用前的竞价终态，分钟 OHLC 不能替代该历史。
2. **执行时点**：信号形成后不能使用已知时点之前不可获得的价格回填成交。
   日线和分钟回测分别保留既有成交时点、T+1、涨跌停、停牌、费用和缺口约束。
3. **历史维表**：名称、ST/风险警示和上市状态从首次成功目录同步开始按 SCD2
   积累。`instrument_status_known=false` 的旧日期不能宣称满足严格
   Point-in-Time。
4. **可复现性**：成功的数据发布写入全局 release manifest；回测结果记录
   release ID、enriched generation、配置哈希和策略源码哈希。manifest 用于追溯
   发布状态，不把可变数据目录转换成不可变快照；generation 不一致会明确标记。
