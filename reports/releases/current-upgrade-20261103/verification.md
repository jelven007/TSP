# 最新现场兼容升级记录

本轮从正式 v0.4.48 `38b809c973e5d30d36e6a143b647a00c4c56f44d` 建立独立候选，
继续已授权的统一发布与双端升级。候选不手工加版本；
正式版本、产物、双端身份及清理由主线 CI 和后续验收分别签收。

## 本轮边界

- 本地保留已有固定过户费支持。隔夜容量撮合的可选 `transfer_fee_fixed`
  按每方向每笔汇总委托收取；分片仅记累计费用增量，零成交零费用，
  含费买入预算预留固定金额。金额必须有效非负，历史缺字段继续使用原比例费用。
- 线上此前已独立退役内置 `s01`、`s02`，相关业务清理已有受控备份与回执。
  本轮保留该状态，不重建策略结果、监控或自动交易规则。
- 新增默认空的部署设置 `RETIRED_BUILTIN_STRATEGIES`（JSON 字符串数组）。
  策略引擎在重复 ID 校验前，仅跳过来源为 `builtin` 且 ID 被列出的定义。
  本地保持空；线上 Runtime 与 Compute 同步设置 `["s01","s02"]`。
  API、任务与 Compute 共享此发现边界，自定义/AI 同 ID 源仍可加载。
- 已撤回的自定义 S01、相关专用信号及其候选不纳入本轮；此前该候选测试仅是历史证据。
- 固定配置、凭据、SMTP、私有策略、实际账户资金和费表保持。
  不新增收益回测，不追溯改写历史研究；后续新研究沿用户三档资金及双向固定 10 元要求。

同一正式源码和镜像供双端使用，线上差异由受控部署配置表达；
没有新增公开插件接口或本轮 SQL 迁移。
基线 v0.4.48 已包含的 schema 8 升级须独立备份、临时恢复演练后执行。
旧内置策略定义仍在正式源码中，退役配置只控制发现，不作为数据删除工具。

## 调用链与兼容

`Settings` → `StrategyEngine._load_all` → API / Full 任务 / Compute 目录。
Broker 的 `env -i` 沙箱显式传入此非敏感数组，不能继承整个宿主环境；
Runtime 与 Broker 配置不同会导致发现不一致，必须一起核验。
共享隔夜 `parameters` → `order_fee` → `fill_order` → 有界隔夜组合结果配置。
固定金额与比例字段分别记录；仅改变显式传入固定金额的执行。
启动配置需要在 Runtime 和 Compute 同步生效并重启；
不把瞬态信号扫描当作委托、成交或收益验证。

## 切换与回退门禁

切换前再次采集源码、配置、11 组用户业务摘要与退役状态；
独立备份两库、行情、配置、源码与镜像，并实际恢复临时库核对行数及 schema。
先本地完整角色，再线上同 SHA；复核登录、深度健康、公共绑定、历史查询、
真实瞬态 Compute、完整股票池、退役 ID 不可用与自定义策略保持，
桌面/窄屏及完整重启后重复验收。

最近两版恢复单元须逐文件及无网络导入验收；仅已合且无写入分支/目录可清理。
正式发布后才按引用清理本项目旧镜像和可重建缓存。
新版本观察重新起算；6 小时、整交易日、持续容量及未执行安装包验证分别列为待完成。
失败时保留新写入，使用匹配源码/镜像/配置恢复；
不得通过恢复旧库或取消退役配置丢弃最新业务状态。
上一正式版不识别新增退役数组；线上回退须采用本轮切换前已核验的退役运行单元，
不能直接启用上一版的原内置目录。两正式版恢复单元与切换前受控运行备份分别保留。
