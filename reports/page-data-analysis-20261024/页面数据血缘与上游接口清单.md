## 1. 阅读口径

页面数据要沿四层区分：

**页面数据块 → 浏览器调用的TSP API → 本地表/文件/内存缓存 → 原始数据源接口或本地计算。**

“表”在当前应用中可能是DuckDB读取Parquet的视图、Parquet分区、JSON/JSONL文件、PostgreSQL业务表，也可能只是内存计算结果。它们不能全部当成关系数据库实体表。

当前代码默认八项能力均路由到rustdx，但用户可以分别选择TickFlow、fuyao或自定义源。读取既有表时，不会因为更改当前配置就把全部历史记录自动变成新源数据。本次没有取得运行实例的能力矩阵、源试拉与历史发布清单，因此下面给出**默认来源、实际路由规则及已经实现的上游接口**，不将它们认定为某个线上实例当前启用的来源。

本次只读取源码和文档，没有调用供应商、启动采集、修改运行数据、检查密钥或执行应用测试。对应代码路径引用用于核对实现，不表示供应商接口本次实测通过。

来源：[前端路由](../../frontend/src/router.tsx)、[八项路由注册](../../backend/app/data_providers/capabilities.py)、[系统架构](../../docs/architecture.md#current)。

下列路径相对运行时`data_dir`。多租户的公共数据可以来自不可变发布目录，而非项目源码根目录下的`data/`。

## 3. 原始数据源接口字典

本节把后文的“日线源”“实时源”等展开到已实现的供应商接口。表里的rustdx接口是TCP原生调用，不是HTTP URL。TickFlow按源码可确认的SDK方法列出，未从项目代码确认的SDK内部HTTP路径不推测。

### 3.1 日线、目录、实时、分钟与盘口

| 数据能力/路由 | 默认rustdx接口 | TickFlow分支 | fuyao分支 |
| --- | --- | --- | --- |
| 股票/ETF/指数目录；跟随`daily_data_provider` | `get_instruments`→`RustdxClient.stocks(market)`→`stocks_json` | `tf.exchanges.get_instruments(exchange, instrument_type=...)` | 当前无`get_instruments`目录实现，切换后目录可能继续使用本地旧表 |
| 股票上市日/股本等目录元数据 | `get_instrument_metadata`→当前财务`finance`→`finance_json` | 目录ext字段及已有补充路径 | 无对应完整目录元数据适配 |
| 日线；`daily_data_provider` | `iter_daily/get_daily`→`bars(frequency=9)`→`bars_json`；指数在线路层映射frequency=4 | `tf.klines.batch(..., period="1d", adjust="none")` | dump下载或`GET /api/a-share/prices/historical` |
| 除权；`adj_factor_provider` | `get_adj_factors`→`xdxr`→`xdxr_json`，结合原价构造事件比值 | `tf.klines.ex_factors(...)` | adjustment-factors dump+日线配价推导 |
| 实时股票/ETF；`realtime_data_provider` | `get_realtime`→`quotes`→`quotes_json` | `tf.quotes.get_by_universes(...)`及按标的`tf.quotes.get(...)` | `GET /api/a-share/prices/snapshot` |
| 实时指数；使用所选实时源的指数补拉 | `get_realtime_indices(symbols)`→同一`quotes/quotes_json` | `tf.quotes.get(symbols=核心指数及规则指数)` | `GET /api/a-share-index/prices/snapshot?thscodes=...` |
| 历史/单股分钟；`minute_data_provider` | `get_minute`→`bars(frequency=8)`，1分钟 | `kline_sync`直接调用`tf.klines.batch(period="1m")`；单日分支还可用`intraday_batch/intraday/get` | 当前未适配 |
| 盘中全量分钟；`full_minute_data_provider` | `get_intraday_batch/get_intraday_latest`及带请求计数变体→`bars/bars_with_count(frequency=8)` | `tf.klines.intraday_universe(...)` | 当前未适配 |
| 五档；`depth5_data_provider` | `get_depth_batch`→`quotes/quotes_json`提取五档 | `tf.depth.batch(symbols)` | 当前未适配 |
| 公司行为；`corporate_actions_provider` | `get_corporate_actions`→`xdxr/xdxr_json`，独立事件标准化 | 当前无适配 | 当前无独立适配 |

fuyao的HTTP基址是`https://fuyao.aicubes.cn`。日线与除权dump下载流程为：

- 日线近端：`GET /api/dump/market-dumps/daily-k-10d/download-url`。
- 日线深历史：`GET /api/dump/market-dumps/daily-k/download-url`。
- 除权事件：`GET /api/dump/market-dumps/adjustment-factors/download-url`。
- 获取预签名URL后下载真实文件；对象存储请求不携带fuyao鉴权头。

rustdx默认行情节点由`RUSTDX_SERVER`及备选节点控制，源码缺省为`117.34.114.13:7709`；财务归档节点由`RUSTDX_FINANCIAL_SERVER`控制，缺省为`120.76.152.87:7709`。这两个地址是源码默认值，不是本次确认的运行节点。TickFlow源码定义免费/付费缺省地址为`https://free-api.tickflow.org`与`https://api.tickflow.org`，也可配置端点。

### 3.2 五张财务表

| 本地表/视图 | 页面读取API | 默认rustdx原始接口 | TickFlow接口 | fuyao HTTP接口 |
| --- | --- | --- | --- | --- |
| `financials_metrics` | `GET /api/financials/metrics` | `financial_history`，FINVALUE字段映射 | `tf.financials.metrics(symbols, latest=...)` | `GET /api/a-share/financials/indicators`；EPS还取利润表，BPS由估值/价格快照推导 |
| `financials_income` | `GET /api/financials/income` | 同一财务归档，利润字段映射 | `tf.financials.income(...)` | `GET /api/a-share/financials/income-statements` |
| `financials_balance_sheet` | `GET /api/financials/balance-sheet` | 同一财务归档，资产负债字段映射 | `tf.financials.balance_sheet(...)` | `GET /api/a-share/financials/balance-sheets` |
| `financials_cash_flow` | `GET /api/financials/cash-flow` | 同一财务归档，现金流字段映射 | `tf.financials.cash_flow(...)` | `GET /api/a-share/financials/cash-flow-statements` |
| `financials_shares` | `GET /api/financials/shares` | 同一财务归档，总/流通股本字段映射 | `tf.financials.shares(...)`，需SDK实际具备方法 | 当前无股本接口，返回空表 |

rustdx历史财务的真实链路为：

`get_financials(table)` → `RustdxClient.financial_history` → 原生`report_file("tdxfin/gpcw.txt")`取得目录 → `report_file("tdxfin/<目录文件名>")`下载归档 → 校验和解析 → 标准字段 → `financials/<table>/part.parquet`。

fuyao BPS补充使用`GET /api/a-share/valuations/snapshot`与`GET /api/a-share/prices/snapshot`。这条路径只补充字段，不意味着财务页所有估值字段或历史BPS都来自完整公告原文。

财务页GET读取本地表，不会每次打开都实时拉五张上游报表。`POST /api/financials/sync/{table}`才触发后台同步。

## 7. 多租户页面到公共数据的中间链路

完整多租户模式并非每个API进程直接连rustdx：

1. Platform负责采集，执行上述Provider/SDK/TCP/HTTP取数，写公共数据并发布。
2. 部分公共读请求通过平台读代理转发到相同TSP API路径，源接口仍由Platform侧维护。
3. 实时消费者通过`PublicMarket.snapshot()`调用内部`GET /internal/cell-market/snapshot`，由`PublicQuoteBridge`安装股票/ETF/指数快照和盘口状态。
4. API/Research/Realtime等角色读取公共发布及租户私人SQL数据。

内部`/internal/cell-market/snapshot`属于TSP服务间接口，不是第四家金融数据供应商；公共release也不会改变原始数据来源。

来源：[公共读路径及代理](../../backend/app/multitenancy/platform.py#L15-L115)、[服务间快照](../../backend/app/multitenancy/market.py#L59-L82)、[实时桥接](../../backend/app/multitenancy/quote_bridge.py#L62-L143)、[公共发布](../../backend/app/multitenancy/publication.py)。

## 8. 来源判断时必须保留的边界

| 容易误判的情况 | 正确判断 |
| --- | --- |
| 目录或Python模块名含tickflow | 不能证明数据当前来自TickFlow；仓库历史命名沿用 |
| unified视图中的`source='tickflow'` | 当前统一视图有固定历史标签；不能直接作为真实供应商追溯证据 |
| 当前日线路由已切换 | 既有表可能还保存先前来源内容，需对应同步/发布证据 |
| 页面最新价格 | 可能来自实时内存覆盖；不能仅查盘后Parquet判断UI值 |
| 页面MA/MACD/信号列 | 部分运行时计算；窄存储表没有全部列不代表页面无数据 |
| 指数实时接口成功 | 日K兜底、实时缓存和源补拉需分别判断，不把日K推导当实时 |
| 行业/概念排名 | 分类标签与成员行情为两套来源，排名是本地聚合 |
| 显示“资金流” | 只有配置并选定扩展字段后才有该来源；成交额不等于资金净流入 |
| 有秒级归档 | 不代表所有页面使用秒级归档；当前常规页面主要消费快照/分钟/日线 |
| AI报告有新闻/财务论述 | 只认真实输入表与接口；生成文字不是事实来源 |
| 五档或公司行为能力可用 | 不认证同日盘口证据、历史覆盖或公司行为业务日期 |
| 历史主线已保存 | 当前成员快照回看仍可能有历史归属漂移 |

来源：[统一视图固定source标签](../../backend/app/tickflow/repository.py#L300-L357)、[运行时指标](../../backend/app/indicators/pipeline.py)、[资金列读取](../../backend/app/services/sector_rotation.py#L102-L136)、[AI输入限制](../../backend/app/services/market_recap.py#L224-L239)、[主线API说明](../../backend/app/api/regime.py)。
