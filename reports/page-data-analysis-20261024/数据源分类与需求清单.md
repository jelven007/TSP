## 1. 范围与主要结论

系统的数据需求可以分为 **16 个业务类别**，并由“衍生计算”和“质量、版本、可得时间”两层贯穿管理。这个分类是需求整理口径，不是现有接口数量。

当前设置页真正独立路由的标准数据集只有八项：`daily`、`adj_factor`、`corporate_actions`、`realtime`、`minute`、`depth5`、`financial`、`full_minute`。证券目录跟随日线源；行业、概念走扩展数据；龙虎榜、短线风向标使用 fuyao 专用服务；交易日历和交易规则还有本地版本化定义。不能用“八项能力已实现”概括全部金融数据需求。[能力注册表](../../backend/app/data_providers/capabilities.py#L47-L119)、[目录调用链](../../backend/app/services/instrument_sync.py#L180-L240)、[当前实现索引](../../docs/architecture.md#capabilities)

当前覆盖范围以沪主板、深主板、创业板、科创板股票为核心，另支持沪深 ETF 和指数。北交所、B 股、港股、美股、期货、期权、债券与可转债不应计作现有股票主链路的覆盖资产。[市场范围](../../docs/reference/integrations.md#rustdx)

本次没有调用供应商接口、检查密钥、运行采集任务或盘点生产数据覆盖，也没有运行应用测试。下文的“已接入”表示代码有接入和消费者，不表示当前环境已有全部证券、年份、字段和修订版本。供应商历史性能记录不作为本次验收结果。

### 1.1 状态与必要性

| 标记 | 含义 |
| --- | --- |
| 已接入 | 已有取数、标准化或存储/消费路径；实际可用性仍受来源配置与覆盖影响 |
| 部分接入 | 有一部分能力，历史深度、资产范围、字段或可得时间证据不完整 |
| 适配层支持 | provider 能取到，但没有完整接入系统的同步、存储、API和界面 |
| 可扩展 | 现有扩展机制能承载此类数据，尚未确认存在默认完整数据源 |
| 未接入 | 本次未发现独立、完整的当前接入链路 |
| 基础必需 | 当前市场数据、指标、筛选、回测等基础流程依赖 |
| 功能必需 | 使用财务、盘口、竞价、模拟交易等具体功能时必需 |
| 可选增强 | 当前基础闭环不依赖，用于扩大研究或信息能力 |

## 3. 证券主数据与历史状态

### 3.1 当前证券主数据

| 子类 | 字段/内容 | 更新方式与用途 | 当前边界 |
| --- | --- | --- | --- |
| 证券身份 | `symbol`、`code`、`name`、`exchange`、资产类型 | 目录定期刷新；所有关联的基础键 | 必须同时确认资产类型，不能把裸代码当唯一身份 |
| 交易板块 | 沪主板、深主板、创业板、科创板 | 价格规则、股票池、过滤 | 当前四板范围有代码身份校验 |
| 上市资料 | `listing_date`、地区、上市状态 | 上市年龄、新股过滤、无涨跌幅窗口 | 真实上市日期不能用首根K线日期代替 |
| 价格和数量规则 | `tick_size`、交易单位、最小申报量/增量 | 价格舍入、撮合、下单数量 | 部分来自维表，部分来自现有本地交易规则 |
| 当前股本 | `total_shares`、`float_shares` | 当日换手、市值和过滤 | 保存来源和字段采集日期；缺失不以0冒充 |
| 当前价格限制 | `limit_up`、`limit_down` | 当日涨跌停和盘口验证 | 日级字段须按交易日期使用，不能无限沿用旧值 |
| 元数据出处 | `as_of`、`snapshot_source`、字段级`*_source`/`*_as_of` | 判断目录和字段是否陈旧 | “刷新了目录”不代表每个字段当天都成功更新 |

| 子类 | 需要保存的内容 | 当前状态 |

## 4. 实时行情、盘口与秒级/逐笔

### 4.1 实时快照字段

| 字段组 | 需要的数据 | 主要用途 |
| --- | --- | --- |
| 价格 | `last_price`、`prev_close`、`open`、`high`、`low` | 当前行情、涨跌停、盘中日K |
| 累计交易 | `volume`、`amount` | 当日交易统计、累计均价、量比 |
| 涨跌信息 | `change_amount`、`change_pct`、`amplitude` | 排名、阈值监控、市场分布 |
| 换手 | `turnover_rate`及其股本基准 | 换手分析，缺字段时需明确推导依赖 |
| 交易状态 | `session`、资产类型、同日归属 | 竞价/连续竞价/收盘区分 |
| 源端时间 | `source_time`、`source_timestamp`、`timestamp_basis` | 判断源端新鲜度、交易日与定版证据 |
| 本地时间 | `request_started_at`、`received_at` | 请求耗时、接收延迟、归档 |
| 可复现出处 | 数据源、`provider_version` | 源切换隔离、秒级回放质量门禁 |

实时快照的量额是当日累计值，不是这1秒的成交量/成交额。计算短窗增量必须使用同日、同源、连续的累计值端点，并识别回退或缺口。默认1秒轮询是调度目标，不证明供应商每秒产生新快照，也不证明全市场一轮能在1秒完成。

rustdx当前把本地接收毫秒写入`timestamp`，同时明确`timestamp_basis=received`；其`source_time`是不带日期的单证券最后事件时间。这个时间不能单独证明当日收盘已经定版。[实时字段契约](../../docs/reference/integrations.md#plugin)、[rustdx报价映射](../../backend/app/plugins/rustdx/provider.py#L735-L809)、[时钟测试](../../backend/tests/test_collection_contract_fixes.py)

### 4.2 盘口与精度分层

| 数据形态 | 关键字段 | 当前能力 | 不能据此宣称的能力 |
| --- | --- | --- | --- |
| 买卖一档 | `bid1`、`ask1`、`bid1_volume`、`ask1_volume` | rustdx报价同轮保留；秒级执行使用 | 不包含完整委托队列 |
| 五档盘口 | `bid_prices[1..5]`、`ask_prices[1..5]`、对应数量、时间戳 | `depth5`独立路由 | 不等于完整历史盘口事件流 |
| 封板证据/日级归档 | 同日盘口与原始涨跌停价、验证结果 | 已有连板验证和`depth5`日分区 | 不等于全市场全时段五档逐次归档 |
| 秒级快照归档 | 轮次、接收/源端时间、OHLC累计值、量额、买卖一档 | 可选、追加式`quote_second` | 不等于真实逐笔；启用前历史不能恢复 |
| 逐笔成交 | 交易所时间、价格、成交量/额、序号、方向证据 | 未见完整历史标准接入 | 不能由分钟K或快照还原 |
| 逐笔委托/撤单 | 委托时间、单号、买卖方向、价格、数量、撤单、关联成交 | 未见完整标准接入 | 五档变化不能还原完整委托 |
| 完整盘口事件 | 事件序号、档位/订单变化、源端时钟、恢复基线 | 后续精细执行研究需求 | 不能仅凭秒级采样认定无丢事件 |

五档数量单位是手。封单额换算须乘100变为股。盘口失败不自动跨源拼接；原始价格和同日数量证据不足时应返回待确认状态。[盘口契约](../../docs/reference/market-data.md#depth)、[盘口服务](../../backend/app/services/depth_service.py)、[秒级schema](../../backend/app/services/second_quote_archive.py#L1-L160)、[秒级方案与限制](../../docs/reference/market-data.md#second)

## 5. K线与分时：完整周期需求

### 5.1 时间周期矩阵

| 周期 | 建议数据标识 | 原始来源或生成方法 | 系统当前状态 | 主要用途 |
| --- | --- | --- | --- | --- |
| 1秒 | `1s` | 真实逐笔/连续事件聚合；或单列“采样快照统计” | 有可选秒级快照，无完整真实秒K通路 | 精细回放、执行研究 |
| 5/10/15/30秒 | `5s/10s/15s/30s` | 真实基础事件或已验证秒K聚合 | 未接入标准周期链路 | 高频信号、执行 |
| 1分钟 | `1m` | 当前分钟源 | 已接入同步、分区、分时、信号与回测 | 当前分钟基础 |
| 5分钟 | `5m` | rustdx原生取数，或完整1m聚合 | 适配层支持；主链路没有完整多周期路由 | 多周期技术策略 |
| 15分钟 | `15m` | 同上 | 适配层支持 | 短线趋势 |
| 30分钟 | `30m` | 同上 | 适配层支持 | 盘中波段 |
| 60分钟 | `60m`；适配层也接受`1h` | 同上，按交易时段锚定 | 适配层支持 | 盘中/日线共振 |
| 2/3/10/120分钟等 | 明确自定义频率 | 完整1m聚合或新增源适配 | 未见当前标准支持 | 可选定制周期 |
| 日 | `1d` | 当前日线源的原始OHLCV | 已接入 | 指标、筛选、日频回测 |
| 周 | 约定后的周标识 | 按自然周分组实际交易日的日K | 未见完整周K通路；可扩展聚合 | 中周期研究 |
| 月 | 无歧义的月标识 | 按自然月分组日K | 未见完整月K通路 | 长周期趋势 |
| 季 | 无歧义的季度标识 | 按自然季度分组日K | 未见完整季K通路 | 季度趋势 |
| 年 | 无歧义的年度标识 | 按自然年分组日K | 未见完整年K通路 | 长期研究 |

月线标识必须与分钟明确区分，不能将`m`同时解释为minute和month。表中的周/月/季/年标识需要在新增契约时统一，不是当前已经存在的API参数。

rustdx的`_MINUTE_FREQUENCIES`明确支持1/5/15/30/60分钟，但`sync_minute_batch`调用`freq="1m"`，当前分钟仓库和API没有以周期作为完整隔离键。provider能直接返回5分钟，不表示把该结果放入现有1分钟分区是安全的。[周期映射](../../backend/app/plugins/rustdx/provider.py#L39-L53)、[分钟provider](../../backend/app/plugins/rustdx/provider.py#L659-L723)、[同步调用](../../backend/app/services/kline_sync.py#L1080-L1142)、[分钟仓库](../../backend/app/tickflow/repository.py#L1798-L1882)、[分钟API](../../backend/app/api/kline.py#L931-L1045)

### 5.2 每根K线应有的内容

| 字段组 | 内容 | 要点 |
| --- | --- | --- |
| 唯一身份 | 证券、资产类型、周期、交易日、开始/结束时间 | 多周期接入必须把周期纳入键 |
| OHLC | 开、高、低、收 | 原始价与复权投影分开 |
| 交易量额 | `volume`、`amount` | 基础数据保持真实量额；缺成交额保持空 |
| 参考价格 | 昨收/前收、价格基准 | 日涨跌幅与除权日基准需明确 |
| 柱状态 | 未完成/完成、截至时间、是否盘后定版 | 当前日柱与分钟暂定柱不能冒充历史完成柱 |
| 来源与质量 | 来源、取数时间、版本、缺失/异常覆盖 | 聚合应保留基础数据缺口 |

上述“周期、开始/结束时间、柱状态、质量”是完整多周期契约应补充的需求，不能全部宣称已经存在于现有Parquet字段中。当前标准列清单、enriched存储列和API参数分别核对。[标准schema](../../backend/app/data_providers/schemas.py)、[enriched列](../../backend/app/indicators/pipeline.py#L119-L205)

### 5.3 聚合和复权规则

1. 5/15/30/60分钟可从1分钟聚合：开盘取窗口首个有效开盘、最高/最低取窗口极值、收盘取末个有效收盘，成交量/额求和。但存在基础缺口时只能标为受限/部分聚合，不能认证完整。
2. 分钟聚合须按交易时段锚定，明确边界标签，不能把午休算进一个普通连续交易桶。当前源可能保留09:30/13:00开盘标签，历史多从09:31/13:01开始；不得机械平移。
3. 周/月/季/年按对应自然周期内的实际交易日聚合，不能以固定5/20/60/250个交易日替代。60日均线是均线，不是季度K线。
4. 不完整的当前周/月/季/年柱需要保留暂定状态；周期未结束时不能在历史策略中提前使用完整周期收盘值。
5. 聚合复权价格前须先统一价格基准。跨除权事件的周/月K不能直接对混合原始价做高低比较后再简单乘一个因子。
6. 秒级快照记录中的`high/low`是当日累计极值，不能当作该1秒的高低。稀疏采样不能还原间隔内真实高低、成交路径或逐笔序列。

这些为接入与聚合建议，依据现有时间、价格和未知值契约整理，不是已实现聚合器的说明。[分钟时间与缺失值契约](../../CONTRIBUTING.md)、[分钟口径](../../docs/reference/integrations.md#rustdx)、[分钟复权](../../backend/app/services/minute_adjust.py)

| 互联互通/持股 | 可获得的成交/持股数据、范围、披露时间、版本 | 可选扩展；不能假定任何时段的完整披露均可取得 |

“融资融券”“沪股通”等概念标签是成员标签，不等于接入融资余额或资金流明细。龙虎榜是日级信息，也不能替代盘中资金流。当前服务会标记未发布/无源/回退上一期状态，应同时展示请求日期与实际榜单日期。[龙虎榜服务](../../backend/app/services/dragon_tiger.py#L1-L150)、[字段类型](../../frontend/src/lib/api.ts#L653-L686)、[资金流扩展消费者](../../backend/app/services/sector_rotation.py)

### 9.3 公告、新闻、股东事件与宏观

| 子类 | 推荐字段/内容 | 必要性与当前状态 |

| 股东与治理 | 十大股东/流通股东、股东户数、质押、增减持、解禁 | 事件策略增强；需报告期与披露时间 |

## 10. 交易日历和历史交易规则

| 数据 | 内容 | 当前实现与补充需求 |
| --- | --- | --- |
| 交易日历 | 日期、开/休市、前后交易日、覆盖年份、来源、版本 | 当前有2026公布日历版本；未覆盖年份需源证据 |
| 交易时段 | 盘前竞价、连续竞价、午休、收盘阶段 | 北京时间固定规则；观察窗口不能当全程成交窗口 |
| 价格限制 | 板块、ST、交易日、上市窗口、涨跌停价、舍入 | 当前有按日期版本规则及源端价格字段 |
| 可交易状态 | 停牌、上市、退市、无涨跌幅限制、未知状态 | 历史状态和行情共同约束 |
| 数量规则 | 最小买入量、数量增量、单笔上限、价格步长 | 部分本地规则已实现，不应统一只按100股推定 |

| 历史规则版本 | 生效日期、来源、规则版本 | 研究须使用当时规则，不直接套今天规则 |

这类输入可以由本地规则文件或配置提供，不一定每次访问外部API，但仍应纳入“系统所需数据”。目前日历版本为`SSE-2026-20251222`，未覆盖年份不能仅用周一至周五认证交易日。[日历定义](../../backend/app/market_time.py#L46-L115)、[交易日探针](../../backend/app/services/trading_day.py)、[价格限制规则](../../backend/app/price_limits.py)、[历史成本/数量规则](../../backend/app/backtest/costs.py)

## 11. 衍生数据：通常无需另买同名数据源

| 衍生数据 | 基础输入 | 当前情况/依赖 |
| --- | --- | --- |
| 涨跌幅、振幅、均价 | 同基准价格、昨收、量额 | 当前已有计算；参考价格和单位需一致 |
| 换手率 | 成交量、当时流通股本 | 已有；历史股本降级需标明 |
| MA/EMA/MACD/BOLL/KDJ/ATR | 对应周期OHLC和必要预热窗口 | 已有日线指标；多周期要在对应K线上重算 |
| 动量、波动率、量比、VWAP乖离 | 历史OHLCV、成交额、交易分钟数 | 当前多类因子已有 |
| 前复权/后复权投影 | 原始价、单事件因子、基准 | 当前前复权已实现；后复权可扩展 |
| 周/月/季/年K | 完整日K、日历、周期边界、复权基准 | 聚合需求；不必为每个周期单独采购 |
| 5/15/30/60分钟K | 完整1分钟、时段、边界、缺口状态 | 可聚合，也可原生源对账；当前未形成完整多周期链路 |
| 涨跌停、连板、炸板 | 原始价、历史规则、ST/上市状态、同日盘口 | 已有计算与质量判定 |
| 板块强弱、RPS、轮动 | 成员关系、行情/分钟、排序分母与窗口 | 已有；历史成分漂移会影响历史结论 |
| 市场情绪、阶段、主线 | 股票范围、量价、连板、板块关系、规则版本 | 已有市场分析；全覆盖与历史定义须另核验 |
| 财务因子与估值 | 已公告财务、历史股本、同基准价格 | 部分基本面因子已有 |
| 回测绩效和归因 | 固定输入、信号、成交、成本、持仓、基准 | 系统计算结果，不是供应商行情事实 |

常用技术指标和板块统计的名称不应都变成独立“外部数据源”。应优先保障基础事实与计算口径，避免同时取供应商指标和本地指标后混用。[指标流水线](../../backend/app/indicators/pipeline.py)、[因子注册](../../backend/app/factors/registry.py)、[市场与板块消费者](../../docs/architecture.md#capabilities)

### 12.2 不在八项矩阵内的来源

| 数据 | 当前来源/入口 | 需要注意的边界 |
| --- | --- | --- |
| 股票/ETF/指数目录 | 跟随日线provider；可选元数据补充方法 | 缺目录接口时保留本地表，不能自动混入别源目录 |
| 历史状态 | 目录观察积累SCD2；ST治理脚本 | 不保证首次采集前历史完整 |
| 行业/概念 | 默认扩展HTTP预设；可替换上游 | 当前快照不等于历史成分 |
| 竞价终态 | rustdx专属采集 | 启用前历史不能用日K补造 |
| 秒级归档 | 复用当前行情轮询结果、本地追加归档 | 不增加真实逐笔信息 |
| 龙虎榜/短线风向标 | fuyao专用方法与本地日级缓存 | 不属于通用provider能力矩阵 |
| 日历 | 本地公布版本+当前来源证据 | 未覆盖年份可能未知 |
| 资金流、事件、宏观等 | 用户扩展表/文件/结构化行 | 有接入框架不等于已有数据 |

不存在一个已接入来源能同时认证“十年完整股票池、全精度行情、原公告历史修订、完整公司行为日期和历史板块成分”。组合来源时应按数据集分别核对身份、交易日、复权基准、历史范围和证据，而不是按供应商名称简单拼接。[当前可信度边界](../../docs/architecture.md#capabilities)、[扩展契约](../../docs/requirements.md#req-02-data-management)

## 15. 完善优先级建议

下表是依据当前业务依赖提出的建议，不表示已经授权实施，也不改变现有路由或采集任务。

| 顺序 | 数据工作 | 原因与完成标准 |
| --- | --- | --- |
| 1 | 核实日线、1分钟、实时、目录、因子、财务/股本的实际范围 | 按资产×交易日×证券×字段列明覆盖，不能只看能力灯 |
| 2 | 补公司行为业务日期证据 | 事件账务模拟交易需要登记/到账/缴款/上市日及可追溯公告 |
| 3 | 治理历史退市池、ST、股本与财报原修订可得性 | 直接影响严格回测，不应以当前快照或首次观察替代 |
| 4 | 接通多周期K线契约 | 先基于1分钟/日线聚合，周期进入存储/缓存/API键，验证午休、除权、未完成柱和缺口 |
| 5 | 完善指数分钟持久历史与历史成分/权重 | 指数分时请求可用不代表具备长期研究输入 |
| 6 | 保存行业/概念历史成员版本 | 避免用今天成分解释过去板块表现 |
| 7 | 完善实时源端时间和归档丢失/覆盖标记 | 秒级调度、接收新鲜和真实源事件新鲜分别判断 |
| 8 | 按实际产品需求接公告/新闻、资金流、两融、ETF净值/PCF | 当前不是全部基础流程必需，选择明确消费者后再接入 |
| 9 | 需要精细执行时再接真实逐笔/盘口历史 | 与现有采样快照另立精度、时间、序号、覆盖与恢复契约 |
