# 本地历史版本两版保留清理

日期：2026-10-31。按用户“历史版本，最多保留2个就可以，多余相关的，也全清理”
要求，当前支持集合保留 **v0.4.39 和 v0.4.38，共两版**。
本轮在此前镜像、缓存和多项目清理之后执行，不重复计算此前释放量。

## 实际清理

| 对象 | 本轮结果 |
| --- | --- |
| 正式运行镜像 | 删除v0.4.37的Compute及runtime-host两个镜像；8个降至6个，均属于v0.4.38或v0.4.39 |
| 应用发布副本 | 删除无源码差异的v0.4.37；正式releases目录由3份降至2份 |
| 前端副本 | 删除已不被启动配置引用的v0.4.34独立构建；当前frontend-root指向v0.4.39 |
| OCI镜像导出包 | 删除9份v0.4.23～v0.4.37的旧Compute导出包；保留v0.4.38的匹配恢复包 |
| 完整源码包 | 删除18份超限或重复包，包括旧六版恢复集合；当前归档保留v0.4.39和v0.4.38 |
| 旧源码差异 | 8份运行源码包改为仅保存差异、删除清单和固定Git基线，总计14,849,904字节 |

实际删除24个文件系统目标及2个镜像。逐路径、删除前文件指纹、镜像ID、
保护项和执行结果见机器记录（附件保存在受控归档）。
旧v0.4.38中转源码包与当前恢复集合采用不同归档前缀，本轮删除的是重复旧集合。
原有的v0.4.38发布任务源码包仍属保留版本。

以执行清理前、VM已启动时的`df -k`为基线，至完成虚拟盘回收后的测量，
可用空间由326.10 GiB增至333.28 GiB，**净增加约7.18 GiB**。
其中VM数据盘分配块减少2.075 GiB；不能再将镜像逻辑大小或目录统计加到整盘增量中。
APFS共享块、快照与其他会话写入会影响此整盘测量，不能认定每个字节均来自本轮操作。
`fstrim`报告3.5 GiB可丢弃区间，不代表额外释放3.5 GiB。

## 保留与恢复边界

当前正式发布目录为：

- `~/.local/share/tsp-dev/TSPP/releases/v0.4.39-bac72d9a83c0`
- `~/.local/share/tsp-dev/TSPP/releases/v0.4.38-5b273174f2e2`

源码归档身份与SHA-256见当前恢复清单（附件保存在受控归档）。
这两份归档的哈希保持不变；Git历史、源码标签和已有工作树保持。

旧完整运行源码包先与不可变版本标签比较，仅保存不同文件和删除清单，
逐文件核对字节、SHA-256及权限后才删除原包。差异包位于受控目录：

`~/.cache/tsp-dev/TSPP/backups/version-retention-20261031/`

父目录0700、文件0600；可能包含旧运行配置，不能上传或提交。恢复时先从包内
`.cleanup-source-delta.json`记录的固定Git提交取基线，再应用差异及删除清单。
它们是唯一差异保护材料，不是额外的完整应用版本。

数据库、行情、财务、自选、用户策略及身份/SMTP配置保持。旧部署备份中的双库和
数据文件继续保留，但已退役的`previous-compute.tar`和`previous-runtime-source.tar.gz`
不能再按原历史清单作为完整运行回滚包使用；源码需由对应标签和差异重建。
当前v0.4.38的匹配导出包未删除。

有未提交代码的旧工作树、已有源码差异包、冻结报告及Git bundle继续保护。
9份bundle的广告提交中存在当前Git引用不可达的历史工作，不能认定为无用重复包。
这些未完成工作及数据恢复材料不按正式发布版本计数。

## 规则与验证

`scripts/release/source_recovery.py`改为最多两版，政策为
`latest_source_plus_one_prior_version`。生成器只选择当前及一个已合入历史版本，
核验器拒绝旧三版政策、空集合、超限清单及额外包。
贡献、发布、运维、测试、版本基线、工程和交付入口已同步。
正式发布副本和镜像在每次升级后按同一上限人工核对；本轮没有建立定时删除任务。

实际验证：

- 修改前原工具28项测试通过；新限制测试在旧实现上出现6项预期失败。
- 修改后源码恢复工具30项测试通过，Ruff检查通过。
- 工具全目录初次147项通过、1项因报告尚未生成而失败；补齐报告后受影响的
  文档及恢复工具46项复验通过。`make check`和含历史报告的211份Markdown检查通过。
- `source_recovery.py verify --output deliverables/version-recovery`确认2版，
  两份归档哈希与此前记录一致。
- 删除目标均不存在；6个保留镜像ID保持，容器/卷为0，构建缓存为0 B。
- 79个受保护文件的SHA-256一致，包括配置、双库备份及保留源码包；Git引用逐字节一致。
- 当前启动脚本及frontend-root保持指向v0.4.39。
- Colima恢复执行前的`Stopped`状态。本轮检查前本地应用端口已无监听，
  清理后仍无应用监听；未启动服务，不声称本轮完成在线业务验收。

本轮没有提交、推送、远程清理或递增应用版本。
