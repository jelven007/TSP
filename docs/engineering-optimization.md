## 开发源码入口

从可信工具目录调用 `scripts/release/check_source.py --root <源码目录>
--version 0.4.67 --revision caf63b1b6e20ce5ee2aed663b7a39ea835b24af2`。
默认要求指定目录正好是 Git 工作树根目录、HEAD 完整提交及工作／提交内 VERSION 均匹配，
并报告暂存、未暂存及未跟踪状态。不联网、不修改分支或部署。

没有 Git 历史的恢复副本必须额外指定 `--recovery-set <可信恢复集合目录>`；
复用 `source_recovery.py verify` 校验归档，再逐个比较归档成员的 SHA-256。
归档中的新增、修改、缺失和符号链接差异单独报告，依赖／缓存／数据目录只从
未跟踪扫描中排除；归档本身包含的成员始终检查。JSON 明确记录排除范围。
恢复集合必须来自已确认的来源；归档校验和与自报提交不是签名，也不是远端身份认证。

退出码 0 为匹配；1 为源码差异；2 为版本／身份错误或无法核验。
开发中可加 `--allow-dirty` 允许差异并保留报告，不能绕过版本、提交和归档错误。
当前候选已从远端正式 `main` 建立独立 Git 分支，核对完整父提交并接入前轮补丁；
`--allow-dirty` 检查明确记录父提交和未提交差异，不把工作树修改冒充已发布提交。
Git／恢复归档模式均不认证线上运行版本。

## 公共查询边界

`PublicQueryCache` 保留 128 项 LRU、世代失效和同键加载合并，默认同一缓存最多
16 个在途加载，跟随加载的请求最多等待 30 秒。调用者可传更短的 `wait_timeout`；
默认驻留载荷预算 32 MiB，加载预算 30 秒，可用 `max_bytes`／`load_timeout` 调整。
可选 `cancel_event` 让等待者和加载检查点合作式退出，现有 HTTP 路由尚未接入断连取消事件。

等待超时不移除加载者，也不启动替代扫描；失效后的旧加载仍占用并发槽直到退出。
达到容量立即拒绝新增加载，已命中的缓存仍可读取。应用将缓存容量拒绝和等待超时
映射为 HTTP 503、`code=public_query_unavailable`、`Retry-After: 1`。
请求方应保留重试间隔，避免密集自动重试。

载荷按基础值、容器、日期及缓存键的深层大小估算，循环引用去重；每项另计固定管理开销。
超过预算的单个结果返回给调用者，但不驻留；不支持可靠估量的原生对象同样不缓存。
LRU 同时遵守条目数和估算字节预算，失效／替换会释放计量。调用方不得修改已发布缓存值。
这不是进程 RSS 硬上限，未覆盖加载中的临时分配和 Python 分配器保留内存。

加载前后及存储目录扫描之间调用 `public_query_checkpoint`，超时／取消结果不入缓存；
嵌套加载不能延长父截止。同步 I/O 已开始后仍须底层单独保证截止，本缓存不会强杀线程。
精确画像预计算、原生查询中断和生产容量参数仍需后续实测。
不得将过期行情用于绕过交易输入新鲜度保护。

## 可汇总的观测

`/api/observability` 保留已有计数与 P50/P95/P99，并新增：

- `process.instance_id`：HTTP 计数实例／重置身份。
- `runtime_process`：阶段计数独立的实例／重置身份。
- `duration_ms.histogram.bounds_ms/counts`：固定上界及互不重叠的桶计数；
  最后一个计数为超过最大上界的溢出桶，桶计数总和等于样本数。
- `public_query_cache`：命中、实际加载、合并等待、超时、取消、拒绝、失败，
  条目与在途数量、估算驻留字节／预算、超大及不可缓存数、加载超时、
  LRU 淘汰数，以及累计加载／等待毫秒数。没有 key、路径或用户标签。

窗口统计必须对同一个计数实例的前后桶计数作差。重启或主动 reset 后，不跨身份相减。
跨进程先对相同桶边界的窗口计数求和，再估算分位数；不能平均各进程 P95，
也不能从两次累计 P95 相减。当前最大值不能作差得到窗口最大值。
现有累计分位数继续保留，采集端必须区分累计与窗口口径。

离线 HTTP 汇总工具：
`python scripts/performance/summarize_observability.py --pair start-a.json end-a.json --pair start-b.json end-b.json`。
输入必须是同一观察窗口内每进程各自配对的快照；普通轮询负载均衡入口不保证命中同一进程。
工具拒绝重置、重复实例、倒退计数和不同桶边界，输出分位数所在桶区间；
溢出桶上界为 null。没有样本时分位数为 null。它不认证采集端窗口对齐或样本覆盖率。

四类 Worker 的实际调度进度文件新增 `captured_at` 和该进程的 `observability`；
计数由真实调度进程写出，沿用原有健康写入成功与进度时效约束。Broker 的受控 Unix
socket 支持 `{"kind":"observability"}`，直接返回 Broker 阶段快照，不启动 Compute。
此接口沿用 socket 文件权限，不新增公网入口。
Platform 进程可通过 `/internal/cell-market/observability` 读取计数，
沿用内部行情 token 鉴权，仅返回汇总计数与缓存水位，不包含路由、配置或数据库池细节。

`scripts/performance/collect_observability.py --config <私有配置> --output <私有目录>`
每次采一个窗口端点。配置含 `targets`（唯一 `name`、只读采集 `argv`、
可选 `max_age_seconds`）及 `max_gap_seconds`。多进程 API 适配器须返回
`process_samples` 数组，并以 `expected_processes` 核对完整进程数；
采集器按进程实例 ID 配对，缺少进程或重复实例时明确失败。
单进程 API 使用现有会话，Worker 读取其 progress.json，Broker 读取其 socket。
采集器保存失败样本，拒绝陈旧／角色错配的 Worker，进程重启、计数倒退、
缺样或超时窗口标为 discontinuous，不跨窗口拼接。私有配置变更须另开输出目录。
可选 `business_clock_argv` 同步读取业务时点，输出
`captured_at/trading_date/calendar_source/quote_at/minute_at/pool_date/public_release_id`；
空水位保持为空。采集成功不等于行情新鲜度、完整交易日或五日验收通过，
这些仍须以真实交易日历、采样连续性和业务覆盖率独立判定。
可选 `is_trading_day/pool_dates/minute_clock_kind` 保存日历判定与各策略池日期；
`public_release_completion` 仅指分钟公共版本完成时间，不认证每股分钟覆盖率。

## Compute 分段

Broker 原有 `queue_ms` 和完整 `sandbox_ms` 保留，新增宿主观测：

| 字段 | 起止范围 |
| --- | --- |
| `spawn_ms` | 启动计时至 `Popen` 返回，包含命令准备，不等于容器就绪 |
| `first_output_ms` | 启动计时至读到首个 stdout 数据块；无输出时不记录 |
| `process_ms` | 启动计时至进入最终清理，包含等待退出／诊断 |
| `cleanup_ms` | 最终清理、回收与释放预算的耗时 |

这些字段相互包含，不能全部相加。首个输出不代表 Python 导入完成，也不保证是真正
计算开始。结果中的宿主计时会覆盖沙箱传来的同名字段。
监控任务按既有 `_compute_timing` 路径携带计时，其余任务保留结果契约，通过阶段指标观测。
无网络、无凭据、只读行情、取消清理、租户预算、报价新鲜度和实时入场截止不变。

Worker 终态协议增加独立的 `worker_timing`：`input_ms` 为读入／JSON 解码，
`imports_ms` 为入口注册依赖导入，`registry_ms` 为隔离注册表与临时目录准备，
`execute_ms` 为执行（包含执行分支内的延迟导入），`total_ms` 从 main 进入至终态组装。
不含 Python 解释器与模块入口导入、结果序列化／写出或容器退出，不代替宿主计时。
计时位于协议外层，业务 `payload`、金融结果和原输入复测契约不变。

## 共享职责

扩展列解析、最新分区读取和投影移至 `services.ext_values`；API 保留旧导入名称，
告警直接使用服务层。自定义信号引用校验移至 `strategy.custom_signals`，
后台管道直接依赖公共缓存服务。现有最新盘、空值、日期范围、SQL 标识符与缓存失效语义保留。

前端财务数据查询、同步和报告 CRUD 的客户端与类型移至 `lib/api/financials.ts`。
原 `api` 方法和类型重导出保持兼容，继续复用统一请求器；财务分析流暂留原入口。
此项仅缩小维护边界，不宣称减少首屏体积或请求耗时。

`lib/api/taskState.ts` 统一后端 9 种任务状态；研究历史响应在入口拒绝未知状态，
避免误归为可删除的已结束任务。旧 `pending` 兼容归一为 `queued`；
`cancelling`、`cancelled`、`interrupted` 保持区分，空值与零资金不被改写。

## 测试反馈

五份GitHub工作流的12种外部Actions固定至完整40位提交，
原标签与固定提交登记于`.github/action-pins.json`。
工具门禁逐个核对所有外部引用，禁止浮动标签、未登记提交与闲置锁项；
既有发布测试仍精确匹配所登记提交，不按Action名称模糊匹配。
Runtime／Compute 构建要求 SBOM 和 `mode=max` provenance，构建输入分别记录
Python、前端与 Rust 锁文件摘要。镜像身份门禁读取两种架构的证明清单，校验
清单／blob 的大小和 SHA-256，要求 SPDX 包清单及 SLSA 来源证明都指向对应镜像
manifest；缺失、损坏或 subject 不符会阻止通过。回执明确 `signature_verified=false`：
这是仓库内容与来源绑定检查，不是签名验证或漏洞扫描。实际新产物须待正式 CI 签收。

CI 保存后端和前端 JUnit 报告，后端同时打印耗时最长的 30 个用例。
前端使用 `pnpm run test` 显式转交 Vitest 的 reporter/outputFile 参数。
暂不改变测试分片、并发或跳过规则；这些报告用于建立后续反馈速度的对照基线。

新增[真实浏览器验收](../scripts/acceptance/browser/README.md)，在 1440×1000 和
390×844 下执行五条业务旅程：行情／自选、数据画像／同步、
策略归档日期与空结果保护、实际研究回测、模拟账户创建及冻结／解冻。
同时检查零资金禁用、未选择策略禁用、登录和退出保护。
CI 使用同提交的前端 dist 和临时后端 fixture，保存截图、JSON/JUnit 和失败 trace；
正式标签与镜像提升新增浏览器依赖。账号与行情均为隔离样本，自动更新检查使用本地响应。

验收暴露窄屏搜索框聚焦扩宽触发工具栏滚动、进而关闭搜索弹层的问题。
搜索弹层改为随锚点滚动和尺寸变化更新位置，锚点离开视口才关闭；
保持点击外部与 Escape 退出，以及弹层内部滚动。
日期／时分共用弹层同样修复焦点引发的祖先滚动提前关闭问题。
共用弹层始终根据触发器矩形生成位置，避免零尺寸布局期间没有位置而无法渲染。
窄屏点击当前路由也会关闭导航抽屉，重复访问不残留遮罩。
每条旅程记录一次浏览器冷缓存和两次热缓存入口耗时；后端复用同一隔离数据，
不把它标成服务端冷启动或生产 P95。

发布回执新增[离线汇总](../scripts/release/summarize_timings.py)，按区间并集合并双端
执行时间，并保留失败重试及协调耗时。新回执补记流水线入参验证准备、前置探针、
后置验证、resume 和 reconcile 检查，包括失败耗时；相互重叠的区间只算一次。
启动流水线前的准备及旧回执未覆盖时间仍标为未归因，不视为空闲。
不改变部署重放规则，不从工具测试推断三轮实际发布耗时。

备份年龄检查对原生双库备份增加 dump SHA-256 与附加文件／目录内容核验，
能拒绝同等大小损坏和缺失摘要；完整哈希属于维护检查，不能放入高频健康探针。
历史 `tsp-public-graph-v1` 压缩表示须使用匹配的图校验器检查逻辑目录和实体 blob，
不能用普通目录哈希代替，也不能把普通年龄检查的失败直接解读成图备份损坏。
