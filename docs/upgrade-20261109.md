## 方案、开发与兼容

历史读取链为 `StrategyResults.save → strategy_day_views → screener day-view API →
独立历史查询键 → 完整列表虚拟渲染`，原归档及旧缓存API保留。
分钟跟单链为 `Monitor → FullWorker → paper_auto → paper_minute`，
账户事务追加委托/成交，分钟内核共用容量和累计费用，避免旧普通撮合再次消费。
秒级发布在 `publication.py` 采集冻结成员，由 `platform.py` 与 `repository.py`
沿实际generation发布；追加成员留至下一轮，原证据不可变要求保持。
全页布局复用现有PageHeader、主题和页面内容入口，不新增未定义插槽。
无需新增SQL迁移；已有迁移文件校验和及可选API兼容保持。
盘后读端仅在既有`post_close_signal_review_v1`来源、当前运行身份及成功买分区/
成功复核均匹配时，不叠加原盘中expired状态。来源、身份或成功状态不匹配仍沿原
过期路径，读取不改原尝试与历史归档。前端复用既有execution_status/entry_data_quality。
开放面新增可选 `execution_mode` 请求/响应字段，缺省 `orders` 保持旧撮合；
开放端点集合不变，OpenAPI冻结快照随此次加法扩展有意识同步。

## 测试、运营与运维

先执行 `make check-release`、受影响Ruff和关键回归，再执行完整后端（含真实隔离
PostgreSQL）、工具、前端测试/lint/TypeScript/生产构建；最终同SHA的CI矩阵分别签收。
两端专属验收包括深度健康、管理员登录、完整股票池、实际Compute、相关桌面/窄屏、
备份双库实际恢复、业务/配置前后差分及完整重启复验。候选测试不能认证生产容量；
100租户1秒、完整交易日和重启后的观察窗口须单列证据或待完成状态。

追加回归的未修复API为1失败/4通过，失败为成功复核被expired覆盖；
前端先复现成功原因缺失，再复现完整行情下市场说明缺失。修复后受影响
测试文件、构建与正式CI分别采集新证据，不以原0.4.57矩阵认证追加候选。

正式发布固定应用版本/完整SHA/tag/源码摘要，Runtime与Compute各两架构联合质量门后提升。
使用版本化pipeline/preflight/OCI工具，按digest缓存及真实引擎ID核验；先本地后线上切换。
每端保留最近两份完整已恢复验证的部署备份集合，另保留最新及上一版匹配恢复单元。
正式发布和双端关键验收通过后才清理精确清单内的过期备份/镜像/项目缓存，
保留不可变审计与用户资料，记录文件系统实际可用字节变化及清理后复验。
未知业务差分、源变化、恢复失败、身份或健康不一致均阻断后续切换/清理；
回退先保护新业务增量，不恢复旧库覆盖新账本。
