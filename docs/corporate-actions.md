# 公司行为数据与模拟盘账务

本功能把价格复权和账户权益分开。`adj_factor` 继续供指标与回测使用；
`corporate_actions` 是独立路由的数据集，供模拟盘记录现金、实际股份及配股缴款。
它不会从价格因子反推分红和送转数量。

## 数据来源与可信度

设置页的「公司行为」能力默认路由到 rustdx。盘后日线管道同步该能力，再进行
模拟盘结算及公共数据发布；请求失败保留上一份数据并记录阶段错误，不跨源回退。
新数据进入 `corporate_actions/all.parquet`，公共发布保持只读版本目录。
同一证券、资产类型、除权日只能有一份聚合事件；跨源同日冲突拒绝写入。
单次失败或重复 ID 不接受为完整批次。当前上限 100,000 个事件。

rustdx 的 TDX category=1 只提供除权日期及每十股分红、送转、配股数量和配股价。
适配器把数量转换为每股口径，保留未知的登记日、支付日、上市日。
**rustdx 当前这些日期没有认证证据，不能直接完成真实分红账务。**
事件会显示待补证；缺少事件记录也不能证明没有公司行为。

Python Provider 可声明 `corporate_actions` 并实现：

```python
get_corporate_actions(symbols, start_time, end_time, asset_type="stock") -> pl.DataFrame
```

请求失败必须抛错，空帧仅表示该范围无事件。自定义 HTTP 源也可配置此数据集，
复用字段映射、限流和重试；任何批次错误拒绝整轮发布。字段契约以
`backend/app/data_providers/corporate_actions.py` 的 `CorporateAction` 为准：

| 字段 | 口径 |
| --- | --- |
| id / symbol / asset_type / source | 稳定事件 ID、沪深证券代码、stock 或 etf、来源 |
| ex_date / record_date | 除权日、权益登记日；登记必须早于除权 |
| cash_per_share / cash_pay_date | 每股税前现金红利（元）、到账日 |
| bonus_per_share / bonus_listing_date | 每股新增送转股份、上市可卖日 |
| rights_per_share / rights_price | 每股可认购数量、每股缴款价（元） |
| rights_start_date / rights_end_date / rights_listing_date | 缴款起止日与上市日；缴款可早于除权 |
| dates_verified / evidence | 日期是否有可核验来源及其引用；不能只把除权日复制到其他日期 |

需要的日期/价格为空、无日期证据或出现零碎股且缺少确切分配规则时，暂停相关
事件入账及撮合，不写当日定版净值。已登记事件被源端修订时同样暂停，
账本保留原事件快照，不能通过覆盖源文件改写已发权益；需核对并作显式冲正。
当前未提供自动冲正界面或事件修订审批流程。

## 账户行为

新账户保存 `corporate_action_mode=events`。存量账户缺该字段时沿用
`legacy_factor`；旧 `corp_action` 记录仍能原样重放。
不会把已按因子调整的账户自动切到事件模式，避免同一次权益重复计算。

新账务追加 `kind=corporate_action`、`action_id`、`stage`：

1. 登记日收盘后记录当时持仓，或从历史台账重建登记日收盘持仓。除权日新买入
   不享受本次权益；卖出后仍保留此前已登记的红利。
2. 除权日撮合前确认应收红利和实际送转股份。红利进入应收资产，不计可用现金；
   送转股进入持仓但在上市前锁定。现金到账日转入可用现金。
3. 配股默认不认购。用户在有效缴款期主动选择数量，一次缴款，不能借用其他
   账户资金或占用已为待买订单预留的资金。不允许修改已缴款数量；相同请求重试
   不重复扣款。冻结账户不能认购。
4. 已缴配股在上市前作为应收股份：除权前按缴款成本估值，除权后有行情则按
   原始价估值，缺行情按成本估算。上市日转持仓并可卖，成本增加实际缴款。
5. 可卖批次按上市日期与买入 T+1 分别约束。FIFO 卖出跳过尚未上市批次；
   零股可随全部持仓一次卖出，不允许分拆零股卖单。

现金金额按十进制四舍五入到分。送转摊薄每股成本但保持总成本；配股增加总成本；
现金分红保留原持仓成本并单独列入现金收入。总资产为现金、持仓市值和应收资产之和。
应收股权计入组合仓位占用，应收现金不供下单消费。未认购配股权未估值，
因此不能把放弃配股前后的资产差异当作账务守恒证明。

已有配对片段/持仓周期统计继续统计交易价差；`stats.corporate_income` 单列已到账的
税前红利，不把红利作为一笔独立赢单。总资产收益包含这笔收入。
账户印花税仍为固定 `stamp_tax_pct`，只影响新成交；与回测按历史日期选税率不同。
个人持有期限相关红利税、零碎股代售收入、配股撤回/退款暂未模拟，不能把
税前模拟结果当成券商实际清算单。

## API、恢复与缓存

- `GET /api/paper/corporate-actions?account=...` 返回当前账户交易范围相关事件、
  已入账阶段、认购资格及阻断原因。
- `POST /api/paper/corporate-actions/subscribe?account=...` 接收
  `{action_id, qty}`，复用原模拟盘写权限及租户事务。
- 台账仍是唯一事实源。现金、持仓、应收均可重放；文件模式在台账追加后发生中断，
  下轮根据最后完成标记重建。多租户在原 PostgreSQL 事务中整体提交或回滚。
- `(action_id, stage)` 保证每账户一次入账；旧 `(symbol, date)` 因子键保留。
  原租户导入也支持两种账本，成交分页不把公司行为计入成交笔数。
- 源文件按时间戳/大小缓存并按证券索引，最多保留四份读取快照。同步写入后清理
  该缓存；行情热路径不访问 Provider，不在无变化轮询中重写持仓。
- 前端认购成功使原 `paper` 查询前缀失效，刷新现金、净值估算、持仓与权益记录。
  日内已确认事件随原模拟盘行情入口推进；未知或尚未调整的事件暂停相关风险判断。

回退代码前应先停止新写入并备份账户数据。旧版本不认识新账本类型，不能直接
用旧程序读取包含 `corporate_action` 的账户；应恢复同一备份时点的代码及私有数据。
