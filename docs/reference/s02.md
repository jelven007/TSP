## 股票范围与盘后选股

当日完整池采用`strategy_scope_v4`，等于策略自身股票范围完整列表；
板块和自选分组取并集，保留该范围的ST／停牌选择。
当前为沪主板、深主板，排除ST和停牌，无自选分组。
行情缺失、数值过滤、排名、最终命中、展示上限均不参与缩池。

显式开启监控后，源交易日21:00～22:00为精确下一交易日生成“选”资格。
数值取目标日精确T-1的已完成日线，边界含等号：

| 选股条件 | 当前保存值 | 单位 |
| --- | --- | --- |
| 收盘价 | 4～150 | 元 |
| 换手率 | 1～11 | % |
| 当日涨幅 | 0.5～6 | % |
| 流通市值 | 50～500 | 亿元，存储为元 |

`entry_prior_ex_date_exclusion=True`在ATR排名前排除除权日期为T-1的股票。
源交易日D晚为下一交易日T选股，因此参考除权日就是D，不再向前挪一天。
盘后选股重复日线、收盘冲突、必需收盘分钟缺失或定版时钟异常须逐股记录并隔离；
有效股票继续，完整范围保留。不能定位到单股的整份证据错误明确失败；
全部成员无有效数据不能记为成功零命中。盘中缺分钟的等待及证明门槛见
[输入异常矩阵](#子计算异常与结果处理)，不能把盘后单股坏日线与盘中待补数据混同。

盘后及次日状态刷新按公开、生效日期处理停复牌和ST变化：
确认停牌／ST可移出对应池及资格投影，复牌／摘帽只按范围恢复入池，
不自动补成“选”命中；原始选股证据及历史冻结数据不回写。

## ATR与排名

`enrich_selection`只为已合格行补充ATR，不重新增删资格。
从T向前解析精确15个交易日，末日必须为T-1；一致复权OHLC提供14个TR：

```text
TR = max(高 − 低, |高 − 前收|, |低 − 前收|)
ATR14 = 14个TR的简单均值
排名指标 = ATR14 ÷ T-1复权收盘价
```

共享因子为`atr14_sma_pct`。按指标降序、同值按代码升序编号1～N；
排名分为`100 × (N − rank) ÷ (N − 1)`，N=1时为50。
N只计可计算ATR的资格成员。缺ATR仍保留资格及真实买信号，
保存`atr_metric_error`，未知顺位排末尾，不用零值代替未知。
共享路径已有`score`时预选富集保留它；买名单明确读取冻结的`atr_rank_score`。

预选冻结原始昨收、ATR、比率、参考日、顺位、排名分及总体N。
盘中买名单复用这些值，不重算ATR、不压缩顺位空档、不按当天涨幅重排。
展示涨幅为触发价÷冻结未复权昨收−1，返回小数；例如0.02表示2%。

### 买任务执行顺序

当前源码声明`entry_phase_policy=independent_v1`及`entry_breadth_observation=True`：
广度与个股各自取数、修复、计算及冻结，个股内部按下表顺序执行。
广度是独立观测：读取完整池14:30有限正价格及精确T-1原始昨收，
上涨严格大于0，真实占比为上涨人数÷有效人数×100；当前只展示。

| 步骤 | 输入及判断 | 结果 |
| --- | --- | --- |
| 个股输入 | 同策略T日、精确T-1来源的冻结预选；实际启用条件的全部窗口 | 无归档等待；已验证空预选正常零结果 |
| 涨幅 | 14:30价格÷冻结原始昨收−1，按%比较0.8～4 | 边界含等号和计算容差，范围外正常淘汰 |
| 1m MA5 | 14:20～14:30的11根1m收盘价，得到14:24～14:30的7个MA5 | 所有相邻增量须大于`1e-10` |
| 5m MA5 | 前步通过者的13:51～14:30共40根1m，聚合8根完整5m | 14:15、14:20、14:25、14:30的4个MA5严格递增 |
| 整理候选 | 每股首次真实触发，复用冻结ATR顺位和排名分 | 未知顺位末尾；保留原排名空档 |
| 汇合及发布 | 当前只要求个股正常完成；核对配置、世代、授权、租约及截止 | 正常通过发布买信号，正常拒绝发布零买入 |

一分钟统一北京时间，同股同分钟按请求版本保留最后一条；
只用已完成分钟和完整五分钟桶，不跨午休、交易日或补造缺行情。
广度等待、失败、取消或过期不改变当前买任务终态和已发布买名单。
用户若另行保存广度下限，必须等两侧均进入正常终态；两侧都通过才发布候选，
任一正常拒绝才形成零买入，等待／失败／过期不能冒充正常零结果。

### 计算进程、排队与本轮返回

当前Full Runtime持有`PhaseInbox`。Worker按策略、阶段派发请求，
本轮只收取已完成回执，不等待仍在执行的广度或个股Future；
后续tick把完成回执合入最新状态。因此空广度下限下，
广度在途不阻塞已完成个股回执的提交。线程只负责传输，Broker为请求启动独立Compute任务容器。

广度使用可信`kind=monitor_breadth`，剥离用户源码注册。
当前两端自动监控已启用权威冻结输入：广度／个股Compute从绑定清单获得全部必要帧，
不另读全局SQL视图或两端各自的分钟行情；意外市场读取明确失败。
隔离并发派发、收取和确认只由`PhaseInbox`实现；
单机、串行策略及可信广度仍可调用共享阶段计算内核，不使用并发编排入口。

每次派发记录自身“派发时刻+60秒”的绝对期限；
执行预算取60秒、请求预算、动作剩余窗口和该期限的最小值。
Broker排队默认2秒、允许配置0～30秒，排队占用同一预算；
客户端另给传输等待25秒容器回收及错误返回，不延长业务窗口，
也不是移除Worker尚未提交的Future回执。
工作日14:25～14:55按有效并发保留最多两个实时槽，其中一个供个股／汇合请求；
物理并发仍受资源上限约束，一个有效槽不能保证并行。

按策略、阶段、动作和配置签名去重在途请求；跨日、配置或监控世代变化取消旧请求。
回执只合并本阶段所属字段，不让旧全状态快照覆盖另一侧的已完成结果。
非空候选需要两侧门控且汇合通过时，可派发`monitor_phase=joined`复用通知路径，
只使用已冻结名单，不重算资格、ATR或MA。
Worker事务提交后才`ack`移除Future；回滚后同一完成回执仍可重试提交。

### 子计算异常与结果处理

当前权威输入先区分可用、待补、已证实不可用和单股非法数据，再允许Compute：

| 情形 | 处理及终态 |
| --- | --- |
| 必需分钟／昨收／已知ATR原始日线缺失，但无完整采集证据 | `pending / waiting_input`，请求缺失依赖；不能凭采集完成时间跳过 |
| 同股同日至少两次不同请求序号的成功完整响应，范围覆盖必需窗口后仍缺数据 | `unavailable`，保存证明及原因；其余有效成员继续，完整池不缩小 |
| 单股价格非正／非有限、原始日线冲突或定版时钟异常 | `invalid`，保存逐股错误、覆盖及代码，其他有效成员继续 |
| 冻结ATR、昨收、排名或原始除权证据不一致 | 按可定位单股错误隔离；整份身份／语义校验错误明确失败 |
| 完整成员中无一个可用 | `no_valid_input`，不能封存成功零命中；修复或到期明确失败 |
| 精确归属的成功空预选 | 个股输入可`ready`，正常零买入，不做个股MA |
| 有效输入全部不达涨幅或MA阈值 | 正常拒绝并冻结，不修复阈值不通过 |
| MA或执行内核异常 | 整个个股阶段未完成；重试从涨幅开始，不逐子步骤冻结 |
| 沙箱、排队、容器、网络、返回或发布异常 | 保存真实失败及首错；未完成侧按期限重试，保留另一侧终态 |
| 取消、世代／配置变化、权限／租约失效或截止已过 | 拒绝旧任务提交，不发布新买信号或次日依赖 |

冻结单位只有`breadth`和`stocks`；涨幅、1m MA5、5m MA5是一次个股计算内的诊断步骤。
共享内核仍支持未启用权威输入的逐股缺窗兼容行为；
当前两端先经过清单的完整窗口和采集证据门禁，不能将兼容分支当成当前输入规则。

### 输入修复、冻结与提交

线上保存`TSP_S02_INPUT_AUTHORITY=publisher`，本地保存`receiver`。
Publisher从不可变公共发布读取原始日线、除权因子、分钟及精确昨收，
重算核对已知ATR、排名分及原始参考；已冻结未知ATR不在盘中补排名。
个股要求当前40根必要分钟窗口，广度只要求14:30分钟；
仅修复缺失的股票、日期和分钟依赖，不重建盘后资格。

输入共同身份包含策略、T、精确T-1、14:30标签、保存定义摘要、
计算实现摘要及信号参数。阶段语义摘要还覆盖完整池、冻结预选、
原始输入、覆盖、可用／非法成员及状态；真实采集、发布和环境时钟另存。
算法摘要包含相关源码文件字节和数值依赖，改注释也会改变该摘要。
S02保存定义摘要使用`s02_bound_definition_v2`：保留自身源码／覆盖对应的
`runtime_identity`、解析后的参数、覆盖、资产类型及周期；租户全部策略信号的
目录版本不参与该输入身份。默认关闭的新增信号选项仅将缺省与显式null归一，
非空值及其他参数的缺省／关闭仍区分。两端须同步计算调用链和算法摘要；
旧日期已封存清单及原定时任务回执保留，不以新身份重写历史结果。

任一阶段首次`ready`时排他封存共同`baseline.json`及该阶段清单，
不要求另一阶段先ready；另一阶段就绪时封存自身清单并复用首次基线。
后来的修订不能重开已封存输入。
Mac只接收同一权威包，不在缺同步时回退为本地独立结果。
传输调用受控[package_transfer.py](../../scripts/release/package_transfer.py)，
接收先验同一SHA-256、解包和文件树，再重算清单语义、原始证据及算法身份。
晚于接收截止的包只保存诊断，不入实时阶段。

输入服务在Platform后台线程修复及轮询，不占Compute槽位；
每次尝试结束后最早3秒再推进，实际完成仍受调度、数据和发布影响。
落盘、公共发布、输入封存、接收绑定、计算和业务事务提交各有证据，
任一前置成功都不能替代策略成功。

广度计算、修复及实时接收要求严格早于14:55:00；
个股和新买信号提交允许14:55:00整秒，超过即拒绝。
Broker还要求派发时剩余预算大于0，整秒允许提交不承诺能新启动计算。
同一事务保存任务、归档、通知事件及成功买信号的次日卖依赖；
截止守卫移除迟到新买事件，保留完成证据。事务失败不得局部发布或提前确认回执。

明确历史回放按独立诊断入口执行，固定信号仍读启动分钟；
盘后数据可用不证明原盘中成功，不用后续价格补造启动信号。
当前S02历史日或`now > T日14:55:00`的手动重载保存`diagnostic_only / review_only`
身份及原盘中回执，不覆盖实时成功或失败，也不生成实时新买入、通知及次日卖依赖。

### 页面与排障回执

页面按卖／选／买展示，固定保留上涨占比、涨跌幅、1分钟MA5、5分钟MA5四项。
无摘要、缺归档、历史日期及部分缺阶段时也保留，未知显示未知，
不由浏览器时钟推断完成。当前广度标注“仅展示，不参与买入筛选”。
任务最终买数在未发布时为“未确认”，内部候选数不是最终买数。

排障依次核对名称与稳定ID、保存定义／算法摘要、T日完整池与精确预选、
输入覆盖及修复证明、权威封存／镜像接收、两阶段及三项个股步骤、
最终发布与提交记录，最后核对重载后的持久化。
`run_evidence`分别记录输入摘要、结果语义摘要和采集／发布／派发／Compute／接收时钟；
`strategy_run_commits`补充已提交输入身份。相同语义摘要不要求环境时钟相同。

API独立观察器每秒巡检，不取行情、不计算策略、不向外发送消息。
计划后5秒开始识别漏触发，派发超过60秒识别阻塞；
启动后1分钟识别输入／计算延迟，截止后识别未完成过期，并核对Worker心跳。
`strategy_operational_state`保存当前异常，`strategy_operational_records`
按日期、世代、配置、信号、阶段及异常类型保留首次观测；
仅展示广度异常仍按阶段记录，不能混作买任务失败。

## 预选个股进程保障

`minute_priority.build_plan`向Platform发送完整范围及冻结预选子集。
独立监督线程管理一个`spawn`预选采集进程，最多一个在途批次；
全市场继续完整采集，预选网络等待和全池轮次分开。
子进程沿同一受控数据源、时标规范化、请求序号及分钟分区锁写入，
迟到请求不能覆盖更新分钟；父进程负责公共发布，子进程不改运行指针。

目标日快发布沿已验证的完整历史基线和唯一`current`指针；
预选完成、全市场完成及公共可读时间分别记录。
当前Compute消费已绑定清单；源文件存在不证明已发布、镜像已接收或阶段已完成。

## 出场信号

关联信号为`s02_早盘清仓 / morning_liquidation`，
列名为`csgi_morning_liquidation`。关注同策略精确上一交易日成功买信号的股票，
从买入后的精确下一交易日开始，独立于当日入场或预选失败。

| 出场参数 | 当前保存值 | 作用 |
| --- | --- | --- |
| `start_time` | 09:30:00 | 开始检查 |
| `rise_pct / fall_pct` | 6 / 6 | 相对卖出日精确未复权昨收达到+6%或−6% |
| `time` | 10:50:00 | 未提前触发时以时钟生成出场信号 |
| `fallback_time` | 13:30:00 | 卖出停止边界，余股不重开该窗口 |

优先检查已完成分钟；新鲜报价可补充首次真实触发，
须为当日且时间差在未来2秒至过去15秒内。每股只保存首次触发。
当前涨跌阈值的基准是昨收。确认停牌按公开证据保留并沿复牌退出处理，
不能凭缺行情推断停牌。原买入日期派生精确次交易日的首次退出日；
已确认停牌可跨日保留，复牌直接生成`holding_exit / reason=resume`的退出信号，
这是独立的停复牌处理。普通余股不会因为缺行情自动延长原时钟窗口。

## 卖／选／买结果与监控

选择策略或加入策略池不自动开启监控；显式开启后分别规划每日卖、选、买任务。
取消推进世代并撤销未完成任务，在途提交仍校验配置、权限、租约及截止。
选为冻结资格，买为真实入场信号，卖为前日成功买信号派生的关注名单；
均不等于实际成交。成功零买入、未执行、未确认、失败和过期分别持久保存。
次日空卖名单必须有同策略、日期及定义的成功零买入证据，缺归档不能补造。

归档、日期指针、正文、有界缓存、按日API和页面查询沿统一链路发布。
权威分钟输入的展示名称取同份冻结预选，行情价格及指标保持分钟口径。
旧买归档缺名称时，按日视图只用该归档同策略、同目标日的冻结预选补充名称；
已有名称保持，未知名称仍未知，不读取最新证券目录或改写原始计算归档。
历史GET、切日和卖／选／买切换只读；页面“重载”是主动重算动作，
其历史／盘后行为按上文诊断隔离契约处理。
当日实时窗口内主动重算沿API执行及保存入口，保留已有首次回执；
本文权威输入门禁描述自动监控，重载不删除或重开已封存输入文件。
手动结果、自动任务回执和自然窗口执行须分别核对。
账户、仓位、自动跟单、费用及成交限制在各自配置维护。
