## 1. 策略、参数与执行规则

策略是选股引擎、回测、监控的基础。本文介绍策略体系与三种扩展方式。

完整策略开发规范(AI 生成与手写)见 [`backend/app/strategy/prompts/strategy-guide.md`](../../backend/app/strategy/prompts/strategy-guide.md)。

<a id="strategy-内置策略"></a>
### 内置策略

**22 个公开内置策略**,各自保留独立 ID 和参数,通过 `matrix_native` 矩阵协议执行
(`backend/app/strategy/builtin/`)。策略池可按以下六类交易逻辑筛选和批量加入:

| 类型 | 策略 |
| :--- | :--- |
| 趋势跟随 | MA 金叉 · MACD 金叉放量 · 均线多头 · 低波动龙头 |
| 放量突破 | 量价齐升 · 布林突破 · 放量创60日新高 · 平台整理突破 · 均线粘合突破 |
| 趋势回踩 | 缩量回踩 · 均线回踩反弹 · RSI 中轴回踩 |
| 超跌修复 | 新低反转 · 超跌反弹 · 超跌反转 · 长下影反击 · MACD 零下回升 |
| 强势延续 | 高换手拉升 · 强势高开 · 逼近涨停 |
| 涨停生态 | 涨停基因活跃股 · 连板股 |

分类仅表示交易意图,不表示多个策略可以独立分散风险。两套 RSI 超跌和两套
MA20 回踩共用计算,保留各自的确认、评分、退出及历史参数单位。
自定义、AI 和旧版响应中没有分类的策略仍可从“未分类”选择。

MA 金叉默认增加“要求MA60近5个交易日不下降”过滤,按该证券的有效交易日
计算并预热65根K线。参数 `require_ma60_non_declining=false` 可恢复原入场规则,
其他旧参数和用户主动关闭的状态继续生效。该过滤仅有探索性历史样本中的
相对改善证据,五年连续回测仍亏损;不能视为可独立盈利或已通过实盘验证。
完整数据限制、22策略诊断、失败试验及分期结果见
[五年研究报告](../../reports/default-strategies-five-year-20261017/analysis.md)。

2026-10-11 精简了三个重复变体：

| 已删除 ID | 家族代表 | 原因 |
| :--- | :--- | :--- |
| `trend_breakout` | `breakout_new_high_60d` | 同为60日收盘新高加放量，主要区别是门槛、评分与基础过滤 |
| `limit_up_momentum` | `consecutive_limit_ups` | 连板阈值变体；代表策略的 `min_boards` 可表达首板与多板研究 |
| `broken_board_recovery` | `consecutive_limit_ups` | 实际仅筛放量涨停，没有实现断板及反包历史结构 |

代表策略默认参数不变，旧 ID 不自动重定向。历史回测记录保留；重跑已删除策略需使用原版本源码。
升级前应检查自定义叠加策略、监控和模拟交易自动规则是否引用旧 ID，显式解除或改写后再热重载，
避免不同条件被静默替换。两种 RSI 超跌、两种均线回踩以及不同突破机制仍分别保留，
因为其实际候选与触发时点存在明显差异。策略保留不等于已经验证可盈利。

<a id="strategy-可选入场候选"></a>
#### 可选入场候选

19项内置策略提供 `entry_variant` 参数，默认 `original` 保留原版。首轮共31个
候选，覆盖首次触发、平台均价、回踩/新低的延后确认、收盘位置和零轴分层；
每策略最多两个，不能解释为已验证盈利的推荐配置。完整清单及研究边界见
[升级实施记录](../../reports/strategy-optimization-20261019/implementation.md)。

新低和回踩的两阶段候选先冻结形态日高低点，随后1—3个市场交易日内收盘
突破高点才确认；影线候选只等待下一交易日。跌破低点优先取消，停牌计入到期，
确认日不重新要求新低或缩量。信号确认后仍按所选成交时点执行，保留T+1、
开盘封板拒单和统一退出优先。旧仓位继续沿用入场政策快照。

平台候选的高、低、收盘价和成交量使用同一组完整有效K线；缺任何必要字段
就整根跳过，历史有效根数不足时不产生平台信号。原版定义保持兼容。

低波动龙头的宽基相对强度和一进二分钟承接尚无完整冻结数据；当前连板策略
仍表示收盘后的接力观察。入场形态候选沿用原退出、评分和仓位，默认规则
不会因为一轮历史胜率较高而自动更新。

<a id="strategy-可选成交与风险政策"></a>
#### 可选成交与风险政策

策略设置的「交易参数」新增入场风险控制，保存在 `overrides.entry_risk`。
缺省全部关闭；配置通过现有参数缓存、回测/优化配置和监控事件快照传递。
这是核心撮合能力，不是新的公共插件接口。

| 配置 | 单位及行为 |
| --- | --- |
| `max_entry_premium_pct` | 小数制，例如0.03；实际拟成交价格不超过信号观察价格的103%，不满足即放弃本次入场 |
| `stop_atr_multiple` | 信号日14期ATR的倍数；入场时冻结保护位＝成交价格−倍数×信号日ATR |
| `stop_signal_low` | 冻结已确认信号日低点；两阶段入场使用确认日，不是之前的形态日低点 |
| `risk_per_trade_pct` | 小数制，例如0.005；计划价差损失不超过权益的0.5%，只缩减现有资金/仓位规则允许的数量 |

新增保护位与原固定/移动保护共同执行，以更严格的价格为准。持仓后不随ATR变化
放宽；若入场价已低于结构保护位、参考值无效或缺失，拒绝该笔交易。
复权历史矩阵在同一复权尺度内计算，最终申报数量仍以当日原始价换算。
交易明细新增 `raw_frozen_stop_price`，保留原始保护价格便于复核。
独立候选模式不分配账户资金，风险金额限制只用于组合仓位和模拟交易。

模拟交易需开启「跟随策略风控」。监控逐证券保存信号时观察到的价格、ATR和低点，
换算为原始价格并随订单/成交留档；成交时再次检查溢价和风险数量。
已知除权事件用于同步价格尺度，参考日期无效时拒单。成交台账重建保留冻结保护位；
已有持仓不加仓，避免新旧政策混用。旧持仓不补写当前政策。
日线政策不支持分钟策略的当日最终OHLC参考；缺少前一信号日参考时拒绝成交。

风险金额指计划价差损失，不含费用，也不能保证跳空、T+1或跌停后实际损失不超额。
六项优先策略分别登记ATR2倍、信号日低点和0.5%风险三个单主题；强势高开单独
登记3%/5%溢价上限。连同31个形态候选及22个原版共73次，未验证前不自动改默认。

<a id="strategy-买入资格与退出优先"></a>
#### 买入资格与退出优先

- `exclude_st=true` 在信号日筛选，并在实际成交日按历史证券状态再次复核。
  次日买单缺行情或受停牌/限价约束时不延续到复牌日；已持仓证券仍可估值和卖出。
- `exclude_new_days=N` 按正式上市日期计算自然日年龄，上市当天为 0，
  年龄达到 N 才允许入场。设为 0/空值或关闭基础过滤可禁用；开启时上市日期缺失不放行。
  上市日期取证券维表的正式 IPO 日期，不能用行情窗口起点或旧 ST 回填记录的首条行情日期。
  此项仅适用于股票，指数自动中和。
- 同一根信号 K 线上入场和退出同时成立时，退出优先，先删除入场再评分、延迟成交。
  该规则用于矩阵策略、Polars 策略及叠加回测；退出通知继续保留。
- 成交日复核仅使用证券资格，不用当天收盘价、成交额等未来信息复核次日开盘买点。
  分钟回放中的价格指标仍来自 T-1，证券资格使用 T 日状态。
- 历史 ST 状态不完整时，兼容模式仍保留原有回退并报告治理缺口；
  `strict_research=true` 拒绝状态覆盖不足的回测。成交资格拦截计入 `execution.buy_ineligible`。
  矩阵磁盘缓存升级为 v8，上市日期变更会使缓存失效。
  回测配置记录 `entry_policy_version`；旧规则产生的选股缓存和“今日曾命中”缓存自动失效。

<a id="strategy-开盘限价与待卖"></a>
#### 开盘限价与待卖

股票日线撮合按成交价格检查当日涨跌停价。开盘涨停后盘中打开，不能证明开盘买单
成交；该买单记为 `buy_limit_up`，不延续为后续日期的买单。开盘跌停的卖单和跳空
止损同样不能按开盘价卖出，记为 `sell_limit_down` 并保留退出意图待后续可成交时处理。
盘中止损价高于跌停价时，不因后来收盘跌停而拒绝该次退出。

组合按开盘跳空风控、开盘计划卖出、开盘买入、日内风控/收盘卖出、收盘买入
的顺序处理。日内卖出不能释放资金或仓位供当天开盘使用；配仓估值使用当时
已知价格。分钟价覆盖/日线分钟细化没有完整账户事件顺序时，先预留买入额度，
不借用同日时序未知的卖出收入。收盘或分钟买入不继承入场前的日最高价作为
移动保护峰值；当天新仓继续受T+1约束。

限价从原始参考价计算，再转换到回测 OHLC 的复权尺度。适用历史 ST 规则、注册制
新股窗口和当日有明确日期的权威限价；未来或无日期的证券最新限价不覆盖历史。
矩阵加载时保存这些约束，窗口切分和缓存读取继续保留。已有分钟回放使用其成交时点
校验。指数不套用股票的新增限价检查。结果配置记录
`execution_model_version=raw_price_frozen_entry_risk_v6`，与旧模型结果区分。

下一根市场K线缺少该股票数据时，买单过期并计入 `execution.buy_expired`；
卖出意图继续保留。受阻天数按日期去重，同根K线不重复提交已经被拒的退出。
独立候选模式的期末未平仓记录保存在 `stats.unclosed_positions`，另列数量和
未实现盈亏，不强制构造一笔无法成交的平仓，也不计入已实现胜率/PF。

旧数据无法建立参考价时仍保留原收盘封板标记的兼容约束；历史状态未知和上市窗口
缺完整日历的兼容近似不能作为严格成交验收证据。日线 OHLC 本身不证明排队成交。

<a id="strategy-最低佣金与入场申报数量"></a>
#### 最低佣金与入场申报数量

策略回测、矩阵回测、分钟策略的日线账户撮合及优化任务共用
`minimum_commission`（每笔每边，元）和 `transfer_fee_pct`（双边小数费率）。
二者默认0兼容旧配置；按实际券商费表填写，佣金已包含的规费不得重复计入。
买入配仓先预留最低佣金及其他买入费用；卖出税费只影响卖出腿。
结果记录 `cost_model_version=cn_stock_tax_minimum_commission_v2`。

入场数量用当日原始价格计算：科创板至少200股、以1股递增、单笔限价申报最多10万股；
其他现有沪深股票按100股递增。依据为[上交所科创板申报数量说明](https://edu.sse.com.cn/tib/qa/)。
当前研究与回测执行资产为股票，并按对应板块规则计算。
`raw_entry_shares`、`raw_entry_price`保存入场申报量与原始价；旧`shares`和
`entry_price`继续作为复权收益模型的等价单位，供历史消费方使用。
回测持仓和收益沿用连续复权序列，并非包含分红税、配股和逐笔股份变动的实物交割账本；
这些结果不能替代实际账户交割验证。

<a id="strategy-价格评分与交易统计"></a>
#### 价格、评分与交易统计

绝对价格、总市值和流通市值过滤使用信号日 `raw_close`；趋势和收益指标继续使用
复权价格。股本沿用数据层按公告时间提供的历史值及既有降级规则，不在策略层替换成
最新股本。旧输入完全没有原始价列时兼容使用 `close`，这不表示满足严格历史研究要求；
已有原始价列中的空值不回填为复权价。启用市值限制但股本缺失时拒绝入选。

有非零权重的评分字段都必须可计算。整列依赖缺失明确报错；个别股票的空值、
NaN 或无穷值会排除该股票的入场资格，并在其余候选的归一化前剔除。
真实零分仍可入选。上述规则由选股、普通回测、矩阵回测共用，缺评分不会删除
持仓估值行或已有退出信号。升级会失效旧的选股与“今日曾命中”缓存，
保留历史回测记录和用户参数。

新执行回测返回以下明确指标，优化器和步进优化也可选择对应目标：

| 字段 | 定义 |
| --- | --- |
| `profit_factor_amount` | 已平仓净盈利金额总和 / 净亏损金额绝对值总和 |
| `payoff_ratio` | 平均盈利交易收益率 / 平均亏损交易收益率绝对值，零收益不计入两侧均值 |
| `net_expectancy` | 全部已平仓交易净收益率均值，包含零收益 |
| `n_wins` / `n_losses` / `n_flat` | 净收益率大于 / 小于 / 等于零的交易数 |

金额缺失时不会用收益率伪造金额 PF；没有亏损时分母为零，比例显示为缺失值。
旧 `profit_factor` 为兼容保留原算法（非正收益参与亏损均值），界面优先展示新的
`payoff_ratio`，旧结果不追溯改写。CSV 分列导出两种口径。胜率的分母始终包含
零收益已平仓交易；浮动持仓另由账户净值体现。历史净期望不是未来盈利承诺。

<a id="strategy-滚动验证的窗口与持仓边界"></a>
#### 滚动验证的窗口与持仓边界

步进优化页面新任务默认训练504、测试126、步进126个交易日，并隔离30个交易日。
`window_unit=trading_days` 按本地 enriched 日线分区日期的条数切窗，跳过节假日；
日期列表与哈希写入结果 `window_policy`。它是观测日历，不能证明全市场缺失分区、
退市股票或历史状态已经补齐。没有足够真实日期时拒绝任务，不推算工作日。
服务器范围保护继续按实际自然日跨度限制单折内存规模。

旧配置缺少 `window_unit` 时保持 `calendar_days`，按原闭区间自然日跨度计算；
例如旧 `train_days=252` 表示相隔252个自然日的两个端点，不是252个交易日。
`purge_days` 默认0，单位与窗口一致，隔离期内不选参也不计算测试收益。

训练折和测试折均使用组合仓位模式，只使用各自窗口内的行情。旧请求中的 `full`
会明确记录为请求模式，实际模式记录为 `position`，不向后借行情平仓。
期末可成交才退出，无法退出的持仓留在本折净值和未平仓统计中。
组合输出未平仓数量、未实现盈亏和待卖数量；缺行情尚未生成退出意图的持仓
也计入未平仓，轻量优化结果保留这些诊断字段。
独立候选回测也按市场交易日计算持有期限；个股最后一根行情不能代替全市场期末，
后续停牌或缺行情的仓位保留为未平仓，不倒退到最后有行情那天强制卖出。
撮合结果版本为 `raw_price_frozen_entry_risk_v6`。

仅日期完整、测试窗不重叠、所有窗口末尾没有未平仓时计算独立折复利。
其他情况保留逐折收益与退化，复利收益为null，附不可聚合原因。
独立折复利不代表真实连续换参账户。已参与策略开发的历史区间即使滚动计算，
仍属于探索性诊断，不能重新宣称为未使用的样本外证据。

内置目录 `backend/app/strategy/builtin/` 还包含一个仅供挖掘 worker 使用的受控因子排名研究模板。它不出现在普通选股列表，也不能通过普通策略 API 直接运行或保存 override；挖掘结果发布时会生成独立策略。详见 [因子与策略挖掘](#mining)。

内置目录 `backend/app/strategy/builtin/` 由项目维护,**AI 生成的策略不会落入此目录**。

<a id="strategy-实时事件与模拟交易自动退出"></a>
#### 实时事件与模拟交易自动退出

实时监控复用一次策略计算，分别输出通知和逐证券执行事件。通知超过 5 只时仍汇总，
执行事件保留每只证券的 `strategy_id`、`type`、`symbol`、`price` 和信号；
通知冷却不会吞掉新的执行边缘。同根 K 线信号去重、首次快照基线以及监控规则
`notify_events` 选择继续生效，Worker 重启后恢复监控状态。

模拟交易 `side=auto` 把卖出信号或出池事件保存为全平待办。T+1、已有待卖单、
缺行情和撮合失败时保留目标，后续轮询无需新信号即可重试。待办绑定当前持仓周期；
再次建仓、自动规则停用/删除或修改执行配置会使旧待办失效。
详细状态、取消与成交时刻契约见[模拟交易实现说明](trading-ai.md#paper-5-运行时挂点全部复用现有引擎)。

逐证券执行事件同时携带评分、原始交易价格和当时有效的风控参数快照。
模拟交易新建策略跟单规则可按评分优先分配名额，并设置单股和账户总仓位上限；
待买单、手动持仓和加仓计入额度。开启“跟随入场时策略风控”后，
止损、止盈、移动风控和交易日持有期以该持仓周期首笔成交政策为准，
后续调整策略不会改变已有持仓政策。无入场快照的旧持仓从下一轮新开仓生效。
回测和模拟交易共用风险触发线，实时退出依赖实际观察到的价格和随后可成交的行情；
完整日线 OHLC 与实时采样产生的执行差异见[风控政策说明](trading-ai.md#paper-风控政策候选排序与开盘入账第二批)。

<a id="strategy-策略组实时求值与组合裁决"></a>
#### 策略组实时求值与组合裁决

独立行情服务中的策略监控已使用容量为 1 的 latest-only 协调器。每轮冻结行情、
规则顺序、名称、自选分组和策略状态 generation；同资产的唯一策略集合共用一次
最大历史窗口读取和一次矩阵准备，同一策略被多条规则引用时只执行一次。
规则层仍分别应用 scope、评分区间、通知事件、冷却和选股池边缘。

价格、信号、异动、封单和成交量差等通用规则不进入 latest-only 邮箱，继续逐份
行情快照同步求值，避免策略计算慢时吞掉瞬时穿越。策略计算阶段不发送通知、不下单；
只有版本仍有效且成功发布的周期才由行情主线程执行外部副作用。

协调器事件携带 `strategy_cycle_id`、`strategy_cycle_state` 和冻结的
`strategy_priority`。模拟交易按同周期同证券统一裁决：

- 同股买卖冲突时退出优先；
- 多策略同时买入只保留一笔，持仓政策冻结主策略与全部归因策略；
- 多策略退出合并为一个退出意图，优先使用现持仓的主策略；
- 已持仓或已有待买订单时默认不加仓；
- 持仓数、单股和总敞口采用本周期匹配规则中最保守的非零限制；
- 部分失败或消费时超过 15 秒的周期只保留退出，不创建新买单。

不带周期 ID 的历史事件和直接调用路径继续沿用原逐规则行为。当前物理并发保持 1；
“五策略同轮运行”表示共享同一快照和账户决策，不等同五线程。策略组配置/状态 API、
前端编组、多租户任务接线、并发度 2 基准和真实交易日自动跟单观察仍未完成。
设计与阶段证据见[五策略方案](../../reports/five-strategy-parallel-20261019/plan.md)和
[实施记录](../../reports/five-strategy-parallel-20261019/implementation.md)。

模块命名空间句柄、文件读写及进程执行原语、通配和相对导入均会被拒绝。

AST 检查只拦截已知攻击模式; 多租户私有策略继续由 ComputeExecutor 在受限容器执行。
单机文件加载仍在本进程执行,不能把静态校验当作完整沙箱。

<a id="strategy-策略文件结构简述"></a>
### 策略文件结构(简述)

一个策略 `.py` 文件通常包含:

| 部分 | 作用 |
| :--- | :--- |
| `META` | 策略元信息(名称、参数、方向等),用户可在 UI 调整阈值 |
| `basic_filter(df, params)` | 模式 A:单日过滤,返回 `pl.Expr` |
| `filter_history(df, params)` | 模式 B:历史窗口过滤,返回 `pl.DataFrame`(配 `LOOKBACK_DAYS`) |
| `scoring` | 评分权重,总和 = 1.0 |
| `ENTRY_SIGNALS` / `EXIT_SIGNALS` | 进出场信号列(回测用) |

完整字段说明与示例见 [`strategy-guide.md`](../../backend/app/strategy/prompts/strategy-guide.md)。

<a id="strategy-参数分组显隐与预设"></a>
#### 参数分组、显隐与预设

策略设置、回测、优化器和 Walk-Forward 共用以下可选 META 参数字段；旧策略无需修改：

- `group`：相邻同名参数显示在同一组；没有组名时不显示标题。
- `visible_if`：`{"param": "mode", "in": ["advanced"]}`，也支持递归
  `{"all": [...]}` / `{"any": [...]}`。条件读取当前值，缺值时使用参数默认值；
  空 `all` 为真，空 `any` 为假。
- `option_applies`：如 `{"advanced": {"window": 12, "enabled": true}}`。
  主动选择该选项时一次性填写已声明的参数；不递归触发其他预设，不覆盖刚选择的选项。

隐藏参数仍保留、保存并传给策略；策略自身负责判断其适用条件，显隐不是执行逻辑。
扫描仅提交当前条件下可见、已勾选的参数，未扫描值使用面板中的固定值。
控制显隐的参数和带预设的选择器只能设为固定条件，切换后分别扫描，
避免同一网格混入不适用参数。切换条件不清除已有值或扫描范围。

## 2. 固定输入、试验族与样本外验证

第三批升级在原有策略、回测、步进优化和持久研究任务中接入入场叠加条件，
保留 SQL 租户隔离、受限计算容器与公共行情版本机制。

<a id="research-入场叠加条件"></a>
### 入场叠加条件

策略设置的 `overlay_filter` 是最多八条条件组成的列表，所有条件同时满足才允许入场。
支持既有条件编辑器中的字段、数值比较和字段比较；普通日线策略也可使用已登记的字符串字段。
矩阵及组合策略只接受数值字段。日线条件不用于分钟策略，以免使用尚未收盘的当日指标。

```json
{
  "overlay_filter": [
    {"left": "close", "op": ">", "right": "field:ma20", "leftDays": 0, "rightDays": 0},
    {"left": "close", "op": ">", "right": "field:close", "leftDays": 0, "rightDays": 1}
  ]
}
```

偏移为 0～60，按同一证券实际存在的交易记录向前计数，停牌缺行不占一根，
存在但字段为空的记录仍占一根。条件在完整历史窗口上计算，在入场评分和排序之前过滤，
不删除撮合价格行、不限制持有后的策略退出和风险退出。选股、实时监控与回测共用校验、
字段依赖和暖机需求；矩阵路径与 Polars 路径按相同输入语义计算。

缺值、非有限数值和不足偏移窗口不放行。缺少所需字段时，回测给出明确错误；
选股和监控关闭本轮入场并返回警告，继续传递能计算出的显式退出信号。
监控保留上轮候选池，避免因入场计算失败而制造 `pool_exit`。
无法计算策略自身所需输入的错误仍走原有失败路径。

设置保存、清空和恢复默认值会同步到回测、参数优化及步进优化入口。
条件及依赖进入历史计划、矩阵缓存配置和实时缓存窗口，避免重用另一组条件的结果。
自动入场事件携带规范化条件，沿用已有入场政策快照随订单、成交和持仓保存。
后续修改策略不会重写既有持仓的入场条件或风险政策。

<a id="research-冻结配置与试验族"></a>
### 冻结配置与试验族

优化开始时深拷贝配置，固定非扫描参数、条件、证券范围和回测参数。
各组试验、最佳参数完整重跑以及每折样本外计算分别获得独立的嵌套配置，
一组运行对配置的修改不会影响其他组。

优化结果的 `research` 包含：

- `family_id`：本次冻结配置的 SHA-256 指纹，用于识别相同配置，不代表全部历史调参的试验总数。
- `config`：优化输入；`backtest_config` 与 `selected_config` 保存实际回测参数及其默认值。
- `n_planned`、`n_attempted`、`n_succeeded`、`n_failed`、`n_cancelled`：实际执行情况。
- 每个 `results` 条目有 `trial_id`、执行顺序、扫描参数、完整参数、目标值、状态和失败原因。

最佳组合完整重跑只用于生成曲线和诊断，不额外计为一组试验。
无有效目标值的组合保留为 `invalid`，不能选为最佳结果。
取消后的优化结果明确标记不完整；现有 SQL 任务取消、过期租约和权限撤销仍丢弃迟到计算结果。

多租户任务沿用 `business.research_jobs` 的输入、元数据和结果，
`research.provenance` 指向任务 ID、完整输入快照指纹及已绑定公共行情版本。
源码、私有因子、信号和覆盖配置仍保存于原任务输入。更改条件或源码不能复用旧结果，
不同租户不能读取或复用对方任务。未绑定公共版本时记录为空，不声称该任务具备版本化行情重跑依据。

<a id="research-固定研究输入与历史可信度"></a>
### 固定研究输入与历史可信度

单机策略回测、参数优化、步进优化在子进程开始时固定一次输入，所有参数组、
最佳组合和全部折共用该版本。`data/research_inputs/<SHA-256>/` 保留全部已落地历史，
包含暖机、持仓退出窗口、财务观察版本、证券状态、扩展数据、私有策略/因子/信号
及策略覆盖配置。复用公共数据白名单，排除这些入口不消费的秒级行情、实时盘口、
竞价快照、市场快照及分析菜单，避免无关实时写入使历史任务无法固定输入。
不复制账户、偏好、密钥或扩展拉取配置。
不裁剪到请求日期，避免漏掉暖机或样本外窗口；原始行情与指标缓存不会被改写。

`.research_snapshot.json` 记录每个文件的 SHA-256/字节数、交易日历和执行环境指纹。
环境指纹涵盖后端 Python 源码、Python 版本及 Polars/NumPy/DuckDB/PyArrow 版本；
桌面包额外绑定嵌入源码清单和可执行文件。缺少 generation 的旧本地数据只在副本中
获得内容派生标识，不因此冒充已发布数据。矩阵缓存写在版本目录的独立缓存位置，
不能改变清单中的输入。任务结束再次核验，输入、代码或日历变化时不返回成功结果。

相同内容复用同一版本；跨周期复测应同时核对输入 ID、配置、策略哈希与构建。
工作进程任务可显式传入 `input_snapshot_id` 重放已保留版本；当前网页显示版本，
尚未提供历史版本选择器。旧结果缺少这些字段仍可查看，但不能据此证明使用同一输入。
直接调用研究服务而绕过工作进程时不自动复制数据，结果会提示没有绑定固定版本。
多租户继续使用既有不可变公共 release 和 SQL 私有输入；新公共发布清单记录全文件
`checksums`，相同文件复用上一不可变副本及哈希，不逐轮重扫历史内容。

单份输入最多 100,000 个文件、50 GiB；最多保留 20 个版本、100 GiB 输入。
输入额度不包含派生矩阵缓存和未完成的临时副本，运维仍须检查实际磁盘余量。
复制中源数据变更、取消、符号链接、读取失败、容量超限均停止任务，临时副本清理；
同目录发布使用跨进程锁防止并发越过保留上限。进程被强制终止留下的隐藏临时目录
不算已完成版本，须在确认没有任务使用后离线清理。不自动删除历史版本：
先导出结果及清单，将确认不再复测的整个版本离线归档，再整理原目录。
版本目录包含私有策略，不能作为公共行情发布或跨账户分享。

结果页分别报告：

- 历史证券状态未知比例：以实际回测窗口内的观测为分母，不包括没有行情的缺失证券。
- 历史退市证券缺失比例：目前没有完整历史股票池分母，显示“未知”，不能写成 0%。
- 财务原公告时间未知比例：以保留财务输入记录为分母；当前 provider 的原公告及修订
  可见时间均未认证，有输入时为 100%，无输入时为未知。公告日期字段存在不代表
  当前修订值在该日可见，采集时间也不能倒填为公告时间。

指定财务观察时点早于首次留档时返回空表，禁止回退到后来当前值。没有指定观察时点的
实时读取保持原行为。固定输入解决复测一致性，不能补造历史退市行情或原公告证据；
当前股票严格研究模式仍会拒绝历史股票池/财务时点未验证的输入。探索模式保留警告。

<a id="research-样本外验证"></a>
### 样本外验证

沿用现有 Walk-forward 服务：每折仅在训练区间选参数，训练强制组合仓位模式，
测试从训练结束次日开始，避免未平持仓借用测试区间价格选参。
测试沿用冻结条件和训练选出的参数，不读取测试收益重新选参。

每折保存 `training` 中的全部参数试验和校正结果，并保存 `validation` 的实际测试配置与状态。
测试失败或缺行情的折仍保留已完成训练记录，不混入有效折的收益聚合。
顶层 `research.n_attempted` 汇总实际训练试验次数，校正范围始终是各自训练网格。
原有全量独立模式的 OOS 曲线仍是候选样本收益曲线，不能解释为账户净值或独立验证样本。

<a id="research-dsr-的适用范围"></a>
### DSR 的适用范围

复用 `stats_v2.expected_max_sharpe` 与 `deflated_sharpe_psr`，不新增统计引擎。
每日账户收益的未年化夏普、偏度、普通峰度和样本数来自原撮合引擎的未取整组合净值，
轻量参数试验保留该统计块，无须为所有组合返回完整曲线。

仅在优化目标为夏普、至少两组全部成功、每日收益样本足够且长度一致、方差非退化时计算。
试验数来自本次实际参数网格，夏普方差由各组实际未年化夏普估计；
峰度和偏度使用实际收益分布，不用默认正态值填补。其他情形返回明确的未计算原因。
全量独立候选统计没有每日账户收益，不用其曲线替代组合收益计算 DSR。

结果标注 `scope=current_grid` 和独立试验近似，不估计参数组相关性，
不把历次调参、调整条件或多折试验悄悄算作独立试验，也不输出策略“可信”徽章。
优化和步进优化结果页可下载冻结配置及全部结果记录，便于核对训练、测试和前向观察。

## 3. 因子与策略挖掘

本文说明当前因子与策略挖掘的金融口径、执行边界、结果解释和运行要求。
入口为 `/factors?tab=mining`，核对日期：2026-10-23；下方性能数字属于原测量记录。

<a id="mining-功能边界"></a>
### 功能边界

当前研究已登记、具备可计算依赖的日频因子及用户选择的 matrix-native 日线策略。
请求校验动态读取注册表，自定义/复合因子也可入池；它完成以下闭环：

1. 在训练区间重新计算因子方向与统计。
2. 按日截面 Rank IC 计算因子相关性并去重。
3. 搜索最多四个因子的受控排名组合；进入 beam 搜索的因子按训练折综合分排序并截断到 `beam_width` 个，保证单因子打分后组合搜索仍有代理预算可用。
4. 用嵌套样本外验证比较新组合；用户选择的已有策略作为对照轨在每个 outer 测试窗独立评估，不参与因子竞争，也不会占用候选名额。
5. 将运行、事件和结果持久化，允许刷新后重连。
6. 将候选保存到研究候选库；只有用户显式确认且通过晋级门槛后才发布独立策略。

挖掘搜索本身不生成任意公式、不接受 AI 自由代码。合格数值扩展字段可以进入
注册表并按已有物化路径研究，但其历史分区、资产和时点约束仍有效；
快照值不注入多日历史。分钟入场优化与分钟因子仍是后续范围。

因子数量以运行时 `FACTOR_COLUMNS` 目录为准。当前目录与后续版本可能不同；单次请求硬上限为 48，不应把历史设计稿中的固定数量当作稳定 API 契约。

当前目录除价量技术类（动量、均线偏离、趋势、波动率、量价、价格位置、超买超卖）外，还包含三个 A 股实证维度：收益形态（`max_ret_20d` 彩票效应、`ret_skew_20d`、`up_days_20d`）、流动性（`amihud_20d` 非流动性、`turnover_z_60d` 换手异动）、涨停基因（`limit_up_count_20d/60d`，基于存储列 `consecutive_limit_ups` 计数，涨停判定沿用环境信号口径）。这些因子仍只用本地日频存储数据计算，不依赖扩展数据源。

财务因子（`pb_latest`、`roe_latest`、`gross_margin_latest`、`net_margin_latest`、
`revenue_yoy_latest`、`net_income_yoy_latest`、`debt_ratio_latest`）读取本地财务数据，
仅在公告日之后的交易日生效。公告前、无财务数据或无有效覆盖时保持空值/明确错误，
不填 0。训练折覆盖不足的财务因子可被淘汰，不阻塞其他有效因子。
同步保留报表历史与观察版本，但原公告和修订可得时间尚未认证；
公告日期门控不能单独证明严格 PIT，当前修订值不能倒填为当时已知值。
固定输入、严格/探索模式与未知比例见[研究配置](#research)。

<a id="mining-时间与收益口径"></a>
### 时间与收益口径

<a id="mining-全局交易日标签"></a>
#### 全局交易日标签

1、3、5 日 forward return 都按全局交易日轴精确连接。停牌或缺行不会把“下一条标的数据”误当成下一交易日。

周频使用每个 ISO 周的第一个实际交易日，月频使用每月第一个实际交易日。节假日不会导致整周漏掉调仓。

<a id="mining-t-1-市场环境"></a>
<a id="mining-t-1-环境"></a>
#### T-1 环境

交易日 T 只能使用上一交易日已经得到的环境标签 T-1。**统计与挖掘口径**聚合为三档：

```text
strong = strong + lean_strong
range  = range
weak   = lean_weak + weak
```

**策略回测的环境过滤**按原始五档匹配：勾选“强势”只允许 T-1 为 strong 的交易日入场，需要三档口径时必须同时勾选“强势+偏强”。挖掘内部的 strong/range/weak 环境拆分仍按上方三档聚合实现（显式枚举原始状态），两者互不影响。

正式区间缺少前驱交易日或前驱环境时会 fail-closed，不会用当日环境、最近自然日或默认环境补齐。

<a id="mining-成交和成本"></a>
#### 成交和成本

候选策略沿用现有回测撮合规则，包括 T+1、佣金、卖侧印花税、滑点以及涨跌停不可成交约束。因子统计中的 long-short spread 仅用于衡量因子区分能力，是理论价差，不表示 A 股可执行卖空。

<a id="mining-防止未来数据"></a>
### 防止未来数据

挖掘使用嵌套 walk-forward，而不是在完整样本上选择后再报告同一段表现：

- 每个 inner 训练折独立学习方向、计算统计、相关去重和组合搜索。
- inner test 只用于选择候选，不参与该折的训练计算。
- 选择完成后在完整 outer train 上重新训练。
- outer test 只进行一次最终样本外评估。
- 训练和测试之间保留 purge 与 embargo；默认 purge 为 30 个交易日。

任何 fold 缺数据、缺 T-1 环境或不能可靠撮合时都记录为 skipped 并给出原因，缺失指标返回 `null`，不会显示为 0。

<a id="mining-候选证据口径"></a>
### 候选证据口径

run 级的“有效折”统计只描述因子赛道：它按每折被选中的候选聚合，不是任何单个候选的样本量。单个候选的逐折证据由三类行组成，`folds.parquet` 的 `evaluation_kind` 区分：

- `selected`：该候选在该 outer 折经 inner 验证胜出后的 outer 测试结果。
- `cross`：该候选的定义在其他折胜出后，在本折补评的跨折结果。胜出定义会在所有 outer 折上评估，使单个候选的证据不再依赖“它恰好在哪里获胜”。
- `benchmark`：对照策略在该 outer 测试窗的独立评估，与因子赛道成败无关；即使因子赛道在某折没有任何候选完成内部验证，对照行仍会写入。

对照策略是固定定义，不需要逐折重拟合，因此每个 outer 折只评估一次；预算耗尽时写入带原因的 skipped 行，不会静默缺失。探索档（exploratory）结果固定为低置信度，只能保存为 pending 候选。

<a id="mining-晋级与发布门槛"></a>
### 晋级与发布门槛

保存（promote）始终允许，结果进入研究候选库 pending 状态。发布（publish）在服务端强制校验以下证据门槛，不满足即拒绝并返回原因列表：

- 非探索档置信度（exploratory 运行产生的候选不能发布）；
- 至少 2 个有效 outer 折；
- 正收益折比例不低于 2/3；
- 样本外 Sharpe 不低于 0.5；
- 最大回撤不劣于 -25%；
- 样本外交易数不低于 60。

门槛按 artifact 行指标在读取时计算，不改变历史 artifact 的 schema，因此旧运行的候选会得到相同的门槛判断。工作台会在候选上显示“达标/未达标”标记，未达标的候选“显式发布”按钮被禁用并展示原因。

<a id="mining-置信度"></a>
### 置信度

三个预算档使用不同的训练窗口：

| 档位 | 外层训练 | 外层测试 | 步长 | 用途 |
| --- | ---: | ---: | ---: | --- |
| exploratory | 126 | 63 | 63 | 数据较短时探索，只能作为低置信度 pending 候选 |
| balanced | 504 | 126 | 63 | 默认自动研究，至少需要 3 个 outer folds |
| strict | 756 | 126 | 126 | 更长训练窗，至少需要 3 个 outer folds |

探索性结果不是已验证策略。候选晋级仍需同时检查正收益折比例、样本外 Sharpe、最大回撤、交易数和环境样本覆盖；发布动作会按上文“晋级与发布门槛”在服务端强制执行同一组阈值。

<a id="mining-任务与资源隔离"></a>
### 任务与资源隔离

挖掘通过 `spawn` 子进程执行，不在 FastAPI 请求线程、实时行情回调线程或浏览器连接生命周期内运行。浏览器断开不会取消任务；刷新后可通过持久 run ID 重连。取消请求会进入 `cancelling`，界面应等待后端进入终态。

共享重任务限流容量为 2：普通回测、优化、walk-forward 和矩阵预热占 1，挖掘独占 2。因此一个挖掘任务不会与另一项大矩阵计算并发。

上面的共享 limiter 与本地 run store 属于独立模式，必须只由一个应用主进程负责
挖掘调度；不能将进程内容量直接乘 API worker 数。
完整多租户复用 SQL 持久研究任务、租约和独立 Research/Scheduled Worker，
任务执行经受限 Compute，API 可按 Compose 配置多进程。
部署与隔离见[完整部署](../../deploy/full/README.md)。

每个运行目录包含 manifest、compact summary、最近 256 条事件和四个 Parquet artifact。大面板、完整矩阵对象和逐折宽结果不会通过 worker IPC 返回。

<a id="mining-自动运行"></a>
### 自动运行

周度自动挖掘默认关闭，只允许 balanced 或 strict。启用后，它会在北京时间配置工作日及其后的同周工作日、日线 enriched 刷新和环境更新成功后尝试入队；如果配置日的数据流水线失败，后续工作日可以补跑。

同一 ISO 周使用确定性的 claim，只触发一次。已经生成运行记录的失败或 `skipped_prerequisite` 仍会占用该周 claim，不重复消耗资源。数据或 T-1 环境覆盖不足时会生成可见的 `skipped_prerequisite` 运行，不会静默降级到 exploratory。挖掘失败不改变已经成功的日度数据流水线状态。

自动任务只生成 pending 结果，永远不会自动发布策略。

<a id="mining-保存与发布"></a>
### 保存与发布

“保存候选”只从服务端已注册的 `candidates.parquet` 读取定义，并重新校验 artifact schema、canonical signature、原始请求中的因子/策略范围和当前策略兼容性，再写入研究候选库。客户端只能提交 run ID 与 candidate signature，不能在保存时重交权重、方向、公式或代码。保存按 `(origin_run_id, candidate_signature)` 幂等；如果候选库已写入但 artifact backlink 回写失败，重试只修复 backlink，不会创建重复候选。

“发布”是独立的显式动作：

- 已有策略候选返回原策略 ID，不复制或覆盖源文件。
- 因子组合候选由服务端根据 run ID 与 candidate signature 派生独立策略 ID；客户端不能提交策略 ID、权重、方向、公式或代码。
- 不同 run 即使得到相同组合，也会生成互相独立的策略文件；同一 run 与 signature 重试时只验证已有源码并修复 backlink。
- 发布过程执行 AST/META 校验、create-only 原子写入、引擎 reload、策略缓存失效和监控状态失效。
- reload 或运行时失效失败会回滚首次创建的新文件；backlink 回写失败不会删除已成功加载的策略，重试可修复 backlink。
- 发布不会修改共享 `factor_rank_research` 源码或 override。

发布仅表示把固定候选变成可使用策略，不代表样本外表现会在未来持续。

<a id="mining-性能口径"></a>
### 性能口径

相关矩阵按交易日计算 pairwise-finite Spearman，只聚合因子平方级的逐日结果，不物化百万行永久 rank 宽表。缺失集合不同的因子会先取共同 finite 样本再排名；无法估计的 pair 保持空值，不按零处理。

生产 runtime 只生成本次搜索 horizon 的一列 forward label，并在阶段间释放中间列。内存表示优化对照 run `46ed81d537e9404baa06324a3ac3a45f` 在 132.0 万行、243 个交易日、44 个因子上峰值 RSS 为 1.291 GiB，总耗时 25.140 秒；相对 2.395 GiB、37.358 秒的原始对照基线，RSS 和耗时分别下降 46.09% 和 32.70%，四个 Parquet artifact 逐项完全一致。

最终 `mining-v2` 额外修复了缺失掩码下的 pairwise Spearman 口径，因此 correlation artifact 与 v1 不再要求数值相等。最终 run `10574abb5d8e4b32ade7cbdd23975c45` 峰值 RSS 为 1.350 GiB、总耗时 40.699 秒，相对原始对照基线内存下降 43.63%、耗时增加 8.94%；仍满足 1.5 GiB 内存门槛和统计增强耗时不超过 30% 的目标。v2 的 Float32 聚合与 Float64 慢参考具有相同 pair counts、空值位置和 0.75 剪枝判断，相关系数最大绝对误差为 `1.70e-7`。

这些数字属于原挖掘实现的历史基准，不表示全部规模具有固定内存上界。原验证记录为
后端 `876 passed, 24 warnings`、挖掘回归 145 项及前端构建通过；
不作为 2026-10-23 全工作区的新测试结果。当前候选需按[测试指南](../testing.md)
重跑适用用例，本轮文档核对结果见[同步记录](../../reports/documentation-sync-20261023/verification.md)。

## 4. AI 策略迭代与人工研究流程

用 AI 承担「生成 — 诊断 — 修改」的重复劳动,**回测验证与上线决策永远由人完成**——与[挖掘模块](#mining)「候选显式发布、永不自动上线」同一纪律。

<a id="iteration-当前内置迭代2026-10-23"></a>
### 当前内置迭代（2026-10-23）

策略创建窗口已提供“AI 迭代（自动回测诊断优化）”。填写名称、规则和执行后端，
开启开关后执行生成→回测→诊断→修改，UI 最多四轮；预览每轮证据与最终代码，
点击“保存策略”才加入可用策略池。草稿使用独立 `ai_` ID，不能覆盖既有正式策略。
多租户在原私有定义与受限计算路径中执行，并复查权限。

接口为 `POST /api/strategies/ai/iterate`，`max_rounds` 范围 1–10、默认 4；
当前不对 API Token 开放。Codex CLI 不支持该工具调用路径，入口明确拒绝。
每轮 `stats` 描述改动前代码的回测基准；最终代码还需核对最终回测证据，不能将
上一轮数字当作新版收益。无有效回测时保留未知，不宣称改进或自动晋级。
实现见[AIStrategyIterator](../../backend/app/strategy/ai_iterator.py)及
[回归测试](../../backend/tests/test_ai_iterate.py)。

下面的台账、留出集和手工评审流程仍适用于长期研究；当前创建窗口没有自动完成
这些研究门禁。第 9 章描述的是尚未实现的完整工作台，不是上述已有开关。

<a id="iteration-0-适用边界先读"></a>
### 0. 适用边界(先读)

| 你想要的是 | 该用的东西 |
| :--- | :--- |
| 投入研究,让 AI 干代码活,自己拍板 | ✅ 本指南 |
| 不想研究,快速拿一个还行的策略 | [挖掘](#mining)(自动化搜索 + 显式发布) |
| 完全自动赚钱 | ❌ 不存在;本项目明确不做 AI 荐股 / 涨停预测 |

两条路径,同一套协议:

- **路径 A · 面板内置 AI(零代码)**:策略页创建窗口生成、修改或开启有界迭代；人复核最终回测与样本外证据后保存；
- **路径 B · 本机 AI 编程助手**:Trae / Codex / OpenCode / ZCode / WorkBuddy 等,用本指南的提示词卡片直接读写策略文件与台账,适合愿意碰文件的用户。

<a id="iteration-1-迭代闭环"></a>
### 1. 迭代闭环

```
冷启动(只做一次): 想法 → 生成 v1 → 基线回测 → 建台账(写入门槛,封存留出集)
每轮: ① 读台账 → ② 提假设 → ③ 改动 → ④ 扫描初筛 → ⑤ 回测 + 分年
      → 拟接受才触发 → ⑥ 终审(敏感性 / 样本外 / 蒙卡) → ⑦ 判定 → ⑧ 记账 → ⑨ 停止检查
```

<a id="iteration-两阶段先粗调后精调"></a>
#### 两阶段:先粗调,后精调

- **粗调期(约 v1~v4)**:每轮允许一个「改动主题」,可以是一组相关的结构修改(如"给入场加环境过滤");
- **精调期(v5 起)**:严格执行**单变量**,一轮只改一处;
- 切换标志:连续一轮结构改动不再带来大幅改善,即进入精调。

<a id="iteration-分层验证常规轮轻终审重"></a>
#### 分层验证:常规轮轻,终审重

- **常规轮**只跑:扫描初筛 + 核心回测 + 分年(分钟级);
- **终审**只在判定为「拟接受」时触发:参数敏感性 + 滚动样本外 + 蒙卡回撤;被回退的轮次不必烧终审。

<a id="iteration-2-迭代台账记忆"></a>
### 2. 迭代台账(记忆)

<a id="iteration-文件布局"></a>
#### 文件布局

```
data/strategies/custom/my_strategy.py            ← 当前生效版本(最新基线,引擎自动发现)
data/strategies/custom/.iterations/my_strategy/
  ├── LEDGER.md                                   ← 台账主文件
  ├── v1.py  v2.py ...                            ← 版本快照
  └── evidence/                                   ← 每轮证据包(可选留存)
```

引擎只扫描 `custom/` **顶层**的 `*.py`(下划线前缀跳过),`.iterations/` 子目录不会被当成策略加载,快照再多也不污染策略列表。

<a id="iteration-台账首页冷启动时写"></a>
#### 台账首页(冷启动时写)

```markdown
# my_strategy 迭代台账
- 思路: 破板次日低吸,博修复
- 区间: 2022-01-01 ~ 2026-06-30(最后 20% 为留出集,封存不用)
- 判定门槛: 全区间夏普 ≥ 基线+0.2 且 分年最差>0 且 样本外降幅<10% 且 命中数变化<50%
- 回退线: 样本外夏普降幅>20% 或 胜率<45% 或 敏感性陡变(±20% 扰动指标波动>30%)
- 基线(v1): 夏普 __ / 回撤 __ / 胜率 __ / 命中 __
- 待试清单: ① 止损 -0.05→-0.07 ② 过滤一字板 ③ 持有 5→10 日
```

<a id="iteration-每轮追加一节"></a>
#### 每轮追加一节

```markdown
## R3 · 2026-09-06(粗调)
- 假设: 破板次日胜率低源于未过滤一字板 → basic_filter 增加非一字板条件
- 改动: v2.py L47(+1 行);预期: 胜率↑,命中数↓
- 证据: 夏普 1.31→1.58 | 分年最差 0.42→0.71 | 样本外 1.12→1.35 | 命中 87→63
- 判定: ✅ 接受,快照 v3.py
- 负知识: 一字板过滤的贡献主要来自 2024 段,2022 段几乎无变化
- 下一步: 待试清单 ③
```

**负知识**(什么没用、为什么)是台账里最值钱的部分——它让 AI 和你都不再走回头路。

<a id="iteration-3-证据包喂给-ai-的输入"></a>
### 3. 证据包(喂给 AI 的输入)

诊断质量取决于输入质量。用固定格式组装(回测结果页导出概要 + 验证 / 归因页关键数字):

```
策略: my_strategy @ v3 | 区间: 2022-01~2026-06(留出集未用)
基线(v2): 夏普 1.31 / 回撤 -18.2% / 胜率 48% / 盈亏比 1.9 / 命中 87
本轮(v3): 夏普 1.58 / 回撤 -15.1% / 胜率 52% / 盈亏比 2.1 / 命中 63
分年夏普: 22:0.31 23:1.02 24:1.87 25:1.66 26YTD:1.43
参数敏感: 止损±20% 内夏普波动 ±0.4(陡) | 持有天数平缓
样本外(滚动): 1.35 / 0.98 / 1.12
因子归因: momentum_20d 胜1.02/败0.87 | turnover 胜2.1%/败3.4%(拖后腿)
```

**AI 诊断纪律**:先逐条复述证据 → 问题按证据强度排序 → 禁止引用证据里没有的现象 → 每个问题对应一处最小修改与预期指标。AI 的诊断是**参考意见**,不进判定链;判定链 = 门槛自动对照 → 人拍板。

<a id="iteration-4-门槛--留出集--停止规则"></a>
### 4. 门槛 · 留出集 · 停止规则

- **门槛先于结果写下**(冷启动时进台账),防止看完结果找理由;数字是示例,可自定,关键是提前锁定;
- **留出集终审**:迭代开始即封存最后 20% 区间,任何一轮都不许用;定型版本只在留出集上跑**一次**,通过才可进监控——这是对"多轮挑最优"多重检验的最终防线;
- **停止规则**:连续 2 轮无改善,或达成预设目标,或满 8 轮强制复盘。

<a id="iteration-5-版本快照与回退"></a>
### 5. 版本快照与回退

- 每次「接受」:当前文件复制为 `v{n}.py` 快照,台账记版本号;
- **回退 = 把快照复制回当前文件**(一行命令),台账追加回退原因;
- **A/B 对比**:旧版本参数存入回测页「候选」,新版本一键载入复测,同区间并排看。

<a id="iteration-6-提示词卡片路径-b"></a>
### 6. 提示词卡片(路径 B)

五张卡片,每次发送时末尾都追加**纪律卡**。

**① 冷启动卡**

```text
阅读 backend/app/strategy/prompts/strategy-guide.md,按规范在 data/strategies/custom/
新建策略文件,思路:____。随后在 data/strategies/custom/.iterations/<策略名>/ 建立
LEDGER.md,写入:思路、回测区间(封存最后 20% 为留出集)、判定门槛、v1 基线指标(我提供)、
待试清单 3~5 条。铁律:只生成这一个 .py,只 import polars as pl,
不改 backend/frontend/docs 的任何现有文件。
```

**② 迭代卡(每轮开头)**

```text
读 LEDGER.md 最后一轮 + 我贴的证据包,按「假设 → 改动 → 预期影响指标」格式输出本轮提案。
粗调期允许一个改动主题;精调期只许改一处。末尾更新待试清单。
```

**③ 诊断卡**

```text
只消费我贴的证据包,输出问题清单(按证据强度排序)与每条对应的最小修改建议。
不执行修改,不引用证据之外的现象。
```

**④ 复盘卡(停止时)**

```text
通读台账,汇总全部负知识,给出「定型 / 换方向 / 废弃」建议及理由。
若换方向,用一句话给出衍生新策略的思路。
```

**⑤ 纪律卡(任意卡片末尾追加)**

```text
纪律:一次只改一个主题(精调期一处);不顺手重构;不虚报指标;
样本外只用于判定,不用于调参;所有新想法先进待试清单。
```

<a id="iteration-8-迭代完成后的产出"></a>
### 8. 迭代完成后的产出

**会有,而且有三层:**

1. **定型版策略(最重要)**:就是 `data/strategies/custom/` 里那个策略文件的最终版——**同一个策略 ID 的演进结果**,引擎自动发现,选股扫描、回测、监控中心立即可用。迭代的本质是"让这个 ID 变得更好",不是生成一堆新 ID;
2. **快照链 + 台账**:`.iterations/` 完整保留每版快照与判定记录,随时回退、随时追溯"这个策略为什么长这样";快照不参与策略发现,不会污染策略列表;
3. **衍生新策略(可选)**:复盘判定「换方向」时,新思路作为一个**新策略文件(新 ID)**开启新一轮冷启动,新台账首页记一行血缘(如 `衍生自 my_strategy@v3`),旧策略与旧台账原地保留。

上线路径:留出集终审通过 → 监控中心配置该策略触发器 → 盘中实时检验,触发记录持久化。
