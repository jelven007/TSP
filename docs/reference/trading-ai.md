## 1. 模拟账户与撮合

> 状态: V1/V2/V3 主流程已实现。本文档记录当前实现、金融口径、
> API 与剩余边界；不能把“模拟成交”理解为真实可成交性证明。
> 遵循 [CONTRIBUTING.md](../../CONTRIBUTING.md) 的数据口径、插件化与测试矩阵要求。

<a id="paper-1-目标与非目标"></a>
### 1. 目标与非目标

**目标**

- 把「策略 → 信号 → 决策 → 收益」打通为实时闭环: 用户用虚拟资金跟单自己的策略/信号, 以真实行情价格模拟成交, 每天看到虚拟净值曲线与回合统计。
- 与回测互补: 回测重放历史, 模拟交易**实时向前**, 无未来函数, 验证的是「我现在敢不敢按这个信号操作」。

**非目标**

- 不接入券商、不做实盘下单、不提供任何资金通道。
- 不做高频/tick 级撮合模拟，当前为实时快照 + 日线开收盘价撮合。
- 不提供真实资金、券商账户或实盘委托。

<a id="paper-2-核心概念与账务模型"></a>
### 2. 核心概念与账务模型

| 概念 | 说明 |
|---|---|
| Account 账户 | 初始虚拟资金 + 费用参数 + 状态(active/frozen)，支持多账户隔离 |
| Order 订单 | 买/卖意向; 来源 manual / auto(规则触发); 含订单类型与时效 |
| Exit intent 退出待办 | 自动方向的全平目标; 独立于事件回执和单次卖单, 持久保留到完成或取消 |
| Fill 成交 | 订单的一次实际成交(价格、数量、费用); **append-only 台账** |
| Position 持仓 | 由成交台账推导物化(avg_cost、可卖数量), 可随时重建 |
| NAV 净值 | cash + Σ(qty × 市价) + 应收资产; 收盘后用日线收盘价定版, 盘中用实时价估算 |
| 回合 Round-trip | FIFO 配对的开->平周期, 统计胜率/盈亏比/持有天数 |

**账务正确性原则**(镜像财务报表口径): 成交台账是唯一事实源, 持仓与净值全部可由台账重放推导; 任何修复动作以「冲正成交」记录, 不允许直接改持仓文件。

<a id="paper-3-数据模型与存储"></a>
### 3. 数据模型与存储

沿用 `app/strategy/lots.py` 的域模块模式: 每实体一个 JSON +
`atomic_write_text` 原子写，目录挂在 `data_dir` 下，API 下单、行情撮合和盘后
结算共用域内 `RLock`。旧版单账户目录会在首次访问时幂等迁移到 `default` 账户。

```
data/paper/
  accounts/{account_id}/
    account.json                   # 初始资金、现金、费用、状态、涨跌停排队开关
    orders/order_{id}.json         # pending / filled / cancelled / expired
    fills.jsonl                    # append-only 成交与 corporate_action 台账
    positions.json                 # 物化持仓，可由 fills.jsonl 重建
    nav/daily.jsonl                # 每交易日一条定版净值，含可用时的沪深300收盘
    auto_rules/arule_{id}.json     # 自动跟单规则
    event/{hash}.json              # 带 id/ts 的监控事件处理回执
    exit/{hash}.json               # pending / submitted 自动退出待办
    exit_archive/{hash}.json       # completed / cancelled 退出历史
```

完整多租户模式复用 `PaperSession` 写事务和既有 RLS。自动规则、回执、退出待办
分别存入 `paper_auto:{account}`、`paper_event:{account}`、`paper_exit:{account}` 文档命名空间；
退出终态移入 `paper_exit_archive:{account}`，订单和成交继续使用原模拟交易表。
文件模式通过原子写和原子重命名归档；新卖单在首次落盘时即带 `exit_intent_id`，
即使在订单写入后、待办更新前退出进程，重启也能重新关联。轮询只读取活跃退出，
完整历史由 `paper_auto.load_exit_intents(..., active_only=False)` 按账户读取。

关键字段口径:

- **价格一律不复权 raw 价**(与真实交易一致); 持仓市值用 `raw_close`。
- **公司行为**: 新账户按登记日持仓、现金到账日及股份上市日分别记录红利、送转与
  配股缴款；缺失日期证据时暂停相关入账与撮合，不生成当日定版净值。存量账户
  保留因子估算与旧账本重放，不自动转换。数据契约、认购、应收资产和回滚边界见
  [公司行为账务](#corporate)。rustdx 当前登记/到账/上市日期未知，不能直接认证清算。
- **费用**: `commission_pct`(双边, 默认万 2.5, 最低 5 元)、`stamp_tax_pct`(卖出印花税, 默认千 1)、`slippage_bps`(默认 5)。
  模拟交易采用账户固定税率，回测可按历史日期取税率；红利按税前金额记录，个人红利税未模拟。

<a id="paper-4-撮合规则金融口径-必须逐条测试"></a>
### 4. 撮合规则(金融口径, 必须逐条测试)

| 规则 | 口径 |
|---|---|
| 即时市价单(盘中) | 以订单创建后的**下一次股票实时快照价**成交 + 滑点；当日未收到快照时由盘后结算按首个合格交易日收盘价兜底 |
| 次日开盘单 | 当前交易日首份新鲜 `raw_open` 到达时入账 + 滑点；要求订单/排队早于 09:30，缺字段或除权日回退盘后结算；09:30 后创建的订单不会回填当日开盘 |
| 当日收盘单 | 订单创建后首个尚未打印的交易日 `raw_close` 成交；15:00 后创建的订单不会回填当日收盘 |
| 买入数量 | 100 股整数倍；资金不足按可用现金向下取整到百股, 不足一手则拒绝 |
| T+1 | 当日买入份额次日方可卖; `Position.available_qty` 在日终结算解锁 |
| 涨跌停 | 默认把触及涨停的买单 / 跌停的卖单置为 `expired` 并留痕；股票按成交日 SCD2 状态识别 ST，账户可开启「排队次日重试」，最多顺延 3 个交易日 |
| 停牌 | 无法取价即不成交, 按顺延规则处理 |
| 撤单 | 仅 `pending` 可撤; 已成交不可逆(只能反向平仓) |

模拟交易仅接受股票，其他资产类型在下单入口拒绝。
所有时间戳取北京墙钟；盘后结算随交易日管道执行。

当日开收盘、前收盘及沪深 300 基准价格通过统一 `scan_daily_parquet`
读取日线。新旧分区可混有 `quote_ts` 等附加列，历史缺列由存储 schema 补齐，
无需迁移已有 Parquet；缺少有效价格时仍按原规则跳过成交或结算。

<a id="paper-5-运行时挂点全部复用现有引擎"></a>
### 5. 运行时挂点(全部复用现有引擎)

```
盘中:  quote_service._evaluate_monitors 的同一轮
       ├─ 核对退出待办的规则与持仓周期, 撤销失效的退出单
       ├─ 遍历全部账户，处理 pending 即时单(股票实时快照价)
       ├─ 自动规则监听逐证券策略事件/通用监控事件 → 生成订单
       └─ 没有新事件也重试退出待办, 入场仍按跟单规则冷却

盘后:  daily_pipeline stage: paper_settle
       ├─ 公司行为事件入账，再撮合开盘单、收盘单及未成交即时单
       ├─ 收盘权益登记，上市日/T+1 可卖数量由批次日期计算
       ├─ 无权益阻断时写 nav/daily 定版(含基准 000300.SH 同日收盘)
       ├─ 对账退出状态, 重试可提交的 next_open / close 退出单
       └─ 异常 warning 留痕并软失败，不中断其他管道阶段
```

- `MonitorRuleEngine.evaluate(..., execution_events=[])` 在同一次策略计算中追加
  逐证券执行事件。所选事件类型、初始基线、同根 K 线去重和选股池边缘判定保持一致；
  通知仍可按超过 5 只汇总并执行通知冷却，执行输出保留每只证券和价格。
  独立行情服务和受限计算容器均传递该输出；策略通知不会再作为第二份下单输入。
- 独立行情服务中的策略事件由 `StrategyGroupCoordinator` 产出周期 ID、周期状态和
  冻结规则优先级。通用价格/信号规则仍逐行情快照评估，不进入 latest-only 邮箱。
  策略周期超过 15 秒或存在部分失败时不创建新买单，已有退出待办继续重试。
- 带周期 ID 的策略事件在账户锁/事务内按 `(cycle_id, symbol)` 仲裁。退出优先；
  多买只保留一个主策略并冻结全部归因；多卖合并一个退出意图。落选和冲突候选写入
  未执行原因并保存处理回执，事件重放不重复决策。
- 组合入场默认拒绝已有持仓或待买标的加仓；本周期所有匹配入场规则的非零
  `max_positions`、`max_symbol_exposure_pct`和`max_total_exposure_pct`取最保守值，
  每笔订单仍通过 `portfolio_budget`按持仓、待买、现金、滑点和费用重新计算。
  待卖成交前不释放仓位和敞口。入场政策保存`primary_strategy_id`、
  `attribution_strategy_ids`及`strategy_cycle_id`，首笔成交后不可改写。
- 上述组合裁决只作用于带周期 ID 的协调器策略事件。不带周期 ID 的旧策略事件、
  固定方向规则和通用监控事件保持原逐规则兼容行为。
- 自动跟单规则形态:
  `{match_kind: strategy|rule, match_id, side: buy|sell|auto, size_mode: fixed_amount|pct_equity, size_value, order_type, cooldown_days, max_positions, candidate_priority, max_symbol_exposure_pct, max_total_exposure_pct, risk_follow}`。
- `side=auto` 仅用于跟策略：`buy_signal` / `pool_entry` 买入，
  `sell_signal` / `pool_exit` 按账户该标的全部持仓卖出；其他事件忽略。
  买入按金额或权益比例计算，自动退出不受冷却、买入金额和最大持仓限制，
  仍接受原撮合域的 T+1、待成交卖单、冻结和数量校验。先保存退出待办；
  全量不可卖或有其他待成交卖单时等待，后续轮询自动重试，不改为部分卖出。
  其他卖单部分减少持仓后，重试按该持仓周期的剩余数量全平。
- 退出状态为 `pending` → `submitted` → `completed`，失败或撤单可回到 `pending`。
  即时退出须有当前有效行情；开盘/收盘退出可无实时行情提交，继续遵守原有成交时刻限制。
  全平订单过期后保留待办；已失败的即时退出若仍处于跌停价格约束中，等待行情恢复，
  避免每轮生成必然拒绝的订单。账户冻结暂停创建和撮合，解冻后继续。
- 停用、删除自动规则，或修改匹配来源、方向、订单类型，会取消其活跃待办和关联的
  pending 退出单；重新启用不会恢复旧待办，新的退出事件仍可创建新待办。
  仅改名称、买入金额、买入冷却或持仓上限不影响既有全平目标。
  单独撤销一张自动退出订单只取消该次尝试；永久停止该规则的退出应停用或删除规则。
- 持仓 `cycle_id` 取从零建仓的首笔买入订单 ID，由成交台账重放产生，
  部分卖出、加仓及数量调整保持该 ID。全平后再次建仓使用新 ID；
  原退出待办失效并撤销旧 pending 退出单。旧持仓缓存缺少 ID 时从台账重建。
  活跃退出期间，自动买入同一证券会被跳过，避免入场和退出相互冲突。
- `max_positions` 是非负整数，`0` 表示该规则不限；按账户当前正数量持仓与
  pending 买单的标的并集计数，包含手动单和其他规则的订单。
  达限后只阻止新标的买入，已有标的加仓和卖出不受影响。
  撤销/过期买单及已全平标的释放名额；待成交卖单不提前释放持仓名额。
- 旧规则或旧客户端省略新增字段时保留 `side=buy`、`max_positions=0`；
  前端新建策略规则和批量策略账户默认选择自动方向。固定卖出先按固定金额或
  权益比例换算数量，再以「当日 T+1 可卖数量 − 同账户同标的 pending 卖单数量」
  封顶并按 100 股取整；可卖为零时记录 `no_sellable_qty`，不生成订单。
  数量检查和下单仍在同一账户写锁/事务内，不跨账户借用持仓。
  批量来源含监控规则时，必须显式选择固定方向。
- 多租户模式在同一 SQL 写事务内完成名额检查、事件回执和下单；
  被忽略、冷却、达限或拒绝的匹配事件也保留回执，重放不再触发。
  固定方向和入场再次尝试仍需要新事件；自动全平的重试独立推进退出待办，
  不依赖重放原事件。待办、订单、回执与自动下单告警一起提交或回滚。
  Worker 在私有计算完成后再次检查行情年龄，失效行情不创建新入场或即时退出单。
- 自动下单和成交事件复用监控中心的告警存储、SSE、语音/系统通知及
  Webhook/邮件通道，不新增一套推送管道。

<a id="paper-风控政策候选排序与开盘入账第二批"></a>
#### 风控政策、候选排序与开盘入账（第二批）

`risk_policy.py` 统一回测四种撮合路径和模拟交易的止损、固定止盈、移动止损、
回撤止盈参数与触发线。显式 `None` 禁用对应参数；组合校验与百分比归一化共用。
保护线取最高值，跳空用实际开盘价，回撤线使用本次观察之前已知的峰值。

策略执行事件携带有效 `entry_policy`（版本、策略 ID、参数、风控政策、计算日期）
及评分。买单和成交台账保存深拷贝；从零建仓的首笔成交确定本轮政策和入场价格，
加仓、部分卖出及重建不覆盖政策，全平后新建仓使用新政策。
缺少快照的旧持仓不会被套用当前策略；受限计算容器产出元数据，Worker 无须执行私有策略代码。

策略 `overrides.entry_risk` 可增加成交溢价上限、冻结信号日ATR/低点及计划价差风险额度。
监控事件逐证券保存原始尺度参考；成交时再验证溢价和保护距离，风险预算只缩减
原申请数量，委托保留 `requested_qty`。开启这些政策必须启用 `risk_follow`，
且不允许对已有同股持仓加仓；旧持仓不补造参考。
首笔成交的 `frozen_stop_price` 存入模拟交易台账，重建和已知除权按原政策与价格尺度调整；
回测成交记录中对应的原始尺度字段为 `raw_frozen_stop_price`。
计划风险不包含费用和跳空缓冲，实际损失仍受T+1、跌停和流动性影响。
该预算与回测共用纯函数；模拟交易现有百股申报实现不等于回测已校准的全部科创板数量规则。
字段、比例单位和兼容边界见[策略指南](research.md#strategy)。

`risk_follow=true` 允许按入场政策持续管理该规则的持仓。实时行情和盘后结算即使
没有新策略信号，也更新持久峰值并保存风险退出意图；T+1、冻结、待卖单、跌停和撤单
复用全平重试。策略后续修改不重写入场政策。规则停用/删除或关闭风控后取消风险退出；
重新启用后只按新的有效观察重新判断风险。持有期从入场日之后按公布的沪深交易日计数，
包括停牌期间的交易日；未覆盖年份不猜测节假日。

`candidate_priority` 支持 `event`（旧规则默认）、`score`、`symbol`。
评分从高到低，同分按证券代码，缺分/非有限分数最后；退出先于所有买入。
同规则同证券在一轮中只创建一笔买单，避免买入信号与入池事件重复分配。
前端新建规则默认评分优先。`max_symbol_exposure_pct` 与 `max_total_exposure_pct`
均为 0~100 的权益百分比，0 不限制，按账户全部持仓和待买单计算，
包含手动单、其他规则和同股加仓；待卖单成交前不释放额度。
估值优先本轮原始行情，再取最近已落盘原始收盘价，最后以成本估算。
待买单预留滑点和佣金；缺参考价的待买单阻止新的自动分配。
自动买入按现金和仓位余量缩到百股，委托和实际成交均复检仓位与费用；
跳空导致超限时拒单留痕，后续重新入场须有新事件。

实时 `next_open` 入账只消费日期为当日、时间戳年龄不超过 15 秒的原始开盘价，
拒绝明确标为本机接收时间的快照，不使用复权 `open` 替代缺失 `raw_open`。
开盘后创建或排队的单、无法解析创建时刻的旧单及当日有除权事件的单沿用盘后结算。
股票可提前开盘入账，同日买入仍受 T+1 限制；盘后重跑不会重复成交。

回测按完整 OHLC 推断日内触线，模拟交易只用实际观察到的原始价格，并在后续有效行情
撮合即时退出，盘后发现风险也不会补造盘中成交。模拟交易会保存当日受 T+1 限制的风险，
而回测当日新仓不执行日内风险退出；快照间遗漏、执行时差、成交滑点和这项 T+1
策略差异仍可能使收益不同。除权账务未完成时暂停旧持仓的新风险判定。
盘口排队和部分成交仍属于后续批次。现金分红已接入事件账务，但仍取决于日期证据，
个人红利税不在当前模拟范围。

<a id="paper-研究配置与前向快照第三批"></a>
#### 研究配置与前向快照（第三批）

入场叠加条件接入选股、实时监控、日线回测、参数优化与步进优化，先过滤再评分。
显式退出和风险退出不受条件限制；缺字段关闭入场并提示原因，监控不据此制造移出候选池事件。
入场事件将规范化 `overlay_filter` 写入原有政策快照，订单、成交与持仓继续保留入场时的配置。

优化结果保存实际参数试验、完整配置与失败原因，每折样本外验证保留训练明细和测试配置。
沿用 SQL 持久研究任务及公共行情版本绑定，配置变化不能复用旧结果。
DSR 只用完整夏普网格的真实每日组合收益统计计算，明确标记本次网格和独立试验近似，
不替代样本外验证。配置、记录字段与边界详见 [研究配置与试验记录](research.md#research)。

<a id="paper-诊断与体验估值标记回合口径与未执行原因第四批"></a>
#### 诊断与体验：估值标记、回合口径与未执行原因（第四批）

总览估值永远是估算口径，与收盘定版净值分开。`overview` 为每个持仓标注价源
（`live` 实时快照 / `daily_close` 最近日线收盘 / `cost` 无行情退回成本占位），
并返回 `valuation`：整体口径、数据时间 `quote_ts`、覆盖 `covered/total` 与缺价 `missing`。
任一持仓缺当前行情退回成本时整体口径保守降级为 `cost`。前端净值曲线仍标「按交易日收盘定版」，
总览另挂估值徽章标注口径、数据时间与覆盖，二者不混用。

回合统计区分两层口径：配对片段（`round_trips`，一次卖出与一个买入批次的 FIFO 配对，
`kind="pairing"`，`cycle_seq` 标注所属持仓周期）与持仓周期（`position_cycles`，从零建仓到
清零的完整周期，收益率按周期总成本资金加权）。`stats` 沿用历史的片段字段
（`rounds`/`win_rate`/`profit_loss_ratio`/`avg_holding_days`），并新增 `cycles` 块
（周期数、周期胜率、资金加权收益率）；`/api/paper/rounds` 并列返回两层明细，不把相关片段当独立样本。

自动跟单每轮被跳过的候选记入按账户的有界列表（`load_auto_skips`）：冷却、持仓名额已满、
缺有效参考价、缺入场政策快照、可买数量为 0、同轮重复、下单被拒等，各带人类可读文案与明细。
它只用于诊断「为什么没下单」，与成交和退出待办分开，不影响撮合。前端在账户面板展示未执行原因列表。

### 7. 前端设计

「模拟交易 Paper」是侧边栏一级页面，当前以多账户对比为默认视图:

- **对比总览**:账户数量、合计虚拟资产、平均收益、收益榜单、前 8 名归一化净值叠加；表头可排序，点行展开账户。

- **账户操作**:现金/市值/总资产/盈亏、净值曲线 vs 沪深300、持仓表、订单与成交台账、冻结/解冻、费用与撮合设置。
- **下单**:股票联想搜索，按数量或金额下单，支持即时/次日开盘/当日收盘。

- **研究对比**:将当前账户实盘向前统计与已保存的策略回测候选并列比较。
- **导出**:全部成交台账导出 CSV。

<a id="paper-8-统计口径与回测对齐"></a>
### 8. 统计口径(与回测对齐)

- 回合配对: FIFO; 胜率 = 盈利回合数 / 总回合; 盈亏比 = 平均盈利 / 平均亏损
- 最大回撤基于 nav/daily 定版序列
- 基准: `000300.SH` 同期归一化(数据已有); 盘中估算净值不参与统计, 只展示

<a id="paper-9-边界并发与风控"></a>
### 9. 边界、并发与风控

- **写并发**: 域模块内全局写锁; 盘中 evaluate 与手动下单竞争同一把锁(镜像 mining_manager 的互斥模式)
- **账户限制**: 每账户持仓标的数上限 50；买入不得超过可用现金，不提供杠杆；账户之间账务完全隔离。
- **冻结**: 账户 frozen 后拒绝新订单, 持仓只读; 保留数据可重建
- **数据缺失**: 缺行情/缺因子一律留痕 warning + 顺延, 绝不臆造成交价(金融数据错误原则)
- **停用**: 可冻结账户并隐藏菜单；数据目录独立为 `data/paper/`。删除运行数据前必须先备份并停止服务。

## 2. 公司行为、应收与权益

本功能把价格复权和账户权益分开。`adj_factor` 继续供指标与回测使用；
`corporate_actions` 是独立路由的数据集，供模拟交易记录现金、实际股份及配股缴款。
它不会从价格因子反推分红和送转数量。

<a id="corporate-数据来源与可信度"></a>
### 数据来源与可信度

设置页的「公司行为」能力默认路由到 rustdx。盘后日线管道同步该能力，再进行
模拟交易结算及公共数据发布；请求失败保留上一份数据并记录阶段错误，不跨源回退。
新数据进入 `corporate_actions/all.parquet`，公共发布保持只读版本目录。
同一证券、资产类型、除权日只能有一份聚合事件；跨源同日冲突拒绝写入。
单次失败或重复 ID 不接受为完整批次。当前上限 100,000 个事件。

rustdx 的 TDX category=1 只提供除权日期及每十股分红、送转、配股数量和配股价。
适配器把数量转换为每股口径，保留未知的登记日、支付日、上市日。
**rustdx 当前这些日期没有认证证据，不能直接完成真实分红账务。**
事件会显示待补证；缺少事件记录也不能证明没有公司行为。

Python Provider 可声明 `corporate_actions` 并实现：

```python
get_corporate_actions(symbols, start_time, end_time, asset_type="stock") -> pl.DataFrame
```

请求失败必须抛错，空帧仅表示该范围无事件。自定义 HTTP 源也可配置此数据集，
复用字段映射、限流和重试；任何批次错误拒绝整轮发布。字段契约以
`backend/app/data_providers/corporate_actions.py` 的 `CorporateAction` 为准：

| 字段 | 口径 |
| --- | --- |
| id / symbol / asset_type / source | 稳定事件 ID、沪深证券代码、stock、来源 |
| ex_date / record_date | 除权日、权益登记日；登记必须早于除权 |
| cash_per_share / cash_pay_date | 每股税前现金红利（元）、到账日 |
| bonus_per_share / bonus_listing_date | 每股新增送转股份、上市可卖日 |
| rights_per_share / rights_price | 每股可认购数量、每股缴款价（元） |
| rights_start_date / rights_end_date / rights_listing_date | 缴款起止日与上市日；缴款可早于除权 |
| dates_verified / evidence | 日期是否有可核验来源及其引用；不能只把除权日复制到其他日期 |

需要的日期/价格为空、无日期证据或出现零碎股且缺少确切分配规则时，暂停相关
事件入账及撮合，不写当日定版净值。已登记事件被源端修订时同样暂停，
账本保留原事件快照，不能通过覆盖源文件改写已发权益；需核对并作显式冲正。
当前未提供自动冲正界面或事件修订审批流程。

<a id="corporate-账户行为"></a>
### 账户行为

新账户保存 `corporate_action_mode=events`。存量账户缺该字段时沿用
`legacy_factor`；旧 `corp_action` 记录仍能原样重放。
不会把已按因子调整的账户自动切到事件模式，避免同一次权益重复计算。

新账务追加 `kind=corporate_action`、`action_id`、`stage`：

1. 登记日收盘后记录当时持仓，或从历史台账重建登记日收盘持仓。除权日新买入
   不享受本次权益；卖出后仍保留此前已登记的红利。
2. 除权日撮合前确认应收红利和实际送转股份。红利进入应收资产，不计可用现金；
   送转股进入持仓但在上市前锁定。现金到账日转入可用现金。
3. 配股默认不认购。用户在有效缴款期主动选择数量，一次缴款，不能借用其他
   账户资金或占用已为待买订单预留的资金。不允许修改已缴款数量；相同请求重试
   不重复扣款。冻结账户不能认购。
4. 已缴配股在上市前作为应收股份：除权前按缴款成本估值，除权后有行情则按
   原始价估值，缺行情按成本估算。上市日转持仓并可卖，成本增加实际缴款。
5. 可卖批次按上市日期与买入 T+1 分别约束。FIFO 卖出跳过尚未上市批次；
   零股可随全部持仓一次卖出，不允许分拆零股卖单。

现金金额按十进制四舍五入到分。送转摊薄每股成本但保持总成本；配股增加总成本；
现金分红保留原持仓成本并单独列入现金收入。总资产为现金、持仓市值和应收资产之和。
应收股权计入组合仓位占用，应收现金不供下单消费。未认购配股权未估值，
因此不能把放弃配股前后的资产差异当作账务守恒证明。

已有配对片段/持仓周期统计继续统计交易价差；`stats.corporate_income` 单列已到账的
税前红利，不把红利作为一笔独立赢单。总资产收益包含这笔收入。
账户印花税仍为固定 `stamp_tax_pct`，只影响新成交；与回测按历史日期选税率不同。
个人持有期限相关红利税、零碎股代售收入、配股撤回/退款暂未模拟，不能把
税前模拟结果当成券商实际清算单。

<a id="corporate-api恢复与缓存"></a>
### API、恢复与缓存

- `GET /api/paper/corporate-actions?account=...` 返回当前账户交易范围相关事件、
  已入账阶段、认购资格及阻断原因。
- `POST /api/paper/corporate-actions/subscribe?account=...` 接收
  `{action_id, qty}`，复用原模拟交易写权限及租户事务。
- 台账仍是唯一事实源。现金、持仓、应收均可重放；文件模式在台账追加后发生中断，
  下轮根据最后完成标记重建。多租户在原 PostgreSQL 事务中整体提交或回滚。
- `(action_id, stage)` 保证每账户一次入账；旧 `(symbol, date)` 因子键保留。
  原租户导入也支持两种账本，成交分页不把公司行为计入成交笔数。
- 源文件按时间戳/大小缓存并按证券索引，最多保留四份读取快照。同步写入后清理
  该缓存；行情热路径不访问 Provider，不在无变化轮询中重写持仓。
- 前端认购成功使原 `paper` 查询前缀失效，刷新现金、净值估算、持仓与权益记录。
  日内已确认事件随原模拟交易行情入口推进；未知或尚未调整的事件暂停相关风险判断。

回退代码前应先停止新写入并备份账户数据。旧版本不认识新账本类型，不能直接
用旧程序读取包含 `corporate_action` 的账户；应恢复同一备份时点的代码及私有数据。

<a id="ai-ai-接口协议"></a>
## 3. AI 响应、工具与取消

在「设置 → AI → 接口协议」选择 Chat Completions 或 Responses，保存后生效。
初始值及旧配置仍使用 Chat Completions。协议独立于服务商预设，不根据模型名称、
URL 或错误猜测；不支持的端点、鉴权错误和断流均报错，不自动切换协议。
原有测试按钮先保存当前表单，再发起测试。

<a id="ai-适配边界"></a>
### 适配边界

`services/ai_provider.py` 保留 `generate_ai_text`、`generate_ai_text_with_tools`
及 `stream_ai_text` 的契约，Responses 共用 `services/ai_responses.py`。
助手保留既有 Chat/Gemini 流式适配；选择 Responses 时也调用同一 Responses
适配器。工具上层继续使用 `tool_calls`、`role:tool`、`tool_call_id`，
动作确认和每次工具执行前的权限复查不变。仅支持本地声明的 function 工具，
不开放供应商内置浏览器、终端或其他工具。

接口使用 `/responses`，`max_tokens` 映射成 `max_output_tokens`；
显式预算仍按配置封顶，报告调用传 `None` 时沿用服务商默认上限。
Responses 助手轮次使用配置的输出上限。OpenAI 的推理强度映射为
`reasoning.effort`；兼容服务不额外添加该参数。只有 400 明确拒绝 temperature
或 reasoning 时才逐项移除重试，每项至多一次；不删除工具、`store=false`
或输出预算。SDK 仍只对开始响应前的暂时性错误作原有有限重试。

<a id="ai-工具往返及隔离"></a>
### 工具往返及隔离

Responses 请求始终 `store=false`，不使用 `previous_response_id`。
请求 `reasoning.encrypted_content`，把响应原生 output（含加密推理项）仅保存在
当前生成任务的消息列表，以 `_responses_output` 随下一轮输入回传。
工具结果按原 `call_id` 转为 `function_call_output`，不重造关联 ID。
本字段不发送到浏览器、不写入会话历史，也不存在全局响应 ID 缓存。
既有 Chat 工具 schema 的可选参数保持可选，未显式启用 strict 时传 `strict=false`。

完整响应才授权本轮工具执行：`completed` 终态、完整且唯一的 call_id、
已声明的工具名、完整 JSON 对象参数必须同时满足。`incomplete`（包括长度和
过滤原因）、`failed`、缺失终态、空正文且无工具、拒绝内容均报错。
工具分片或 `output_item.done` 不单独授权执行，只有完整 `response.output`
是本轮工具清单。一次响应的全部工具先校验，通过后才逐个执行。
工具迭代期间切换为 Chat 协议时停止任务，重新发起才使用新协议。

<a id="ai-流式与恢复"></a>
### 流式与恢复

正文 delta 逐步显示，最终响应校验一致性；只有最终正文而没有 delta 时补发一次。
已显示部分正文后遇到截断也报错，不能作为完整报告或已完成工具轮次。
流开始后不重放请求；调用方取消、断开、停止消费或异常时关闭流和 HTTP 客户端。
用户重试会建立新任务；已执行的工具仍由各自既有去重/确认机制控制，
本适配器不承诺跨任务工具事务。

改动仅影响 AI 配置读取、secrets 文件缓存签名和前端 settings 查询。
不影响行情、指标、研究缓存、generation、公共发布或 SSE 行情协议。
回退时选择 Chat Completions 并保存即可；旧客户端保存其他配置不会清空协议。
环境变量协议非法会明确报错，应修正配置；不静默退回默认值。

验证使用真实 OpenAI SDK + 隔离 HTTP/SSE 夹具，覆盖并发隔离、工具往返、
空/截断/错误、旧配置、取消和旧 Chat/Gemini 回归。没有调用付费 AI 服务；
真实服务商的具体模型兼容性需使用该服务商支持的协议进行连接测试。

<a id="sessions-ai-助手会话同步"></a>
## 4. 助手会话同步与冲突

打开助手时会读取当前账户、当前租户的服务端记录；面板可见时每 30 秒及窗口重新
获得焦点时刷新。生成期间只保留本机草稿，生成结束后同步。工具足迹可以跨设备查看，
但历史中的执行中/待确认状态会变为已取消，不能从历史重新执行旧动作。

每个账户在每个租户内最多保留 20 个会话，每个会话最近 200 条消息，整组最多
4 MiB。新建第 21 个会话会淘汰最旧会话；超过字节上限时保存失败，须下载草稿、
删除部分历史后重试。删除及淘汰会同步到其他设备。

首次读取旧浏览器历史时，只有服务端从未保存过该组记录（revision 为 0）才自动
导入。已有服务端记录，包括已经删空的历史，会触发冲突处理，避免旧设备恢复已删除
内容。同步失败时仍可在本机使用助手，但不能据此认为其他设备已收到新内容。

冲突时不会自动覆盖任一侧：

1. 可点击“下载本机草稿”导出 JSON。
2. “改用服务端记录”读取远端历史，并将当前本机草稿保留到同一账户分区的
   `assistant.sessions.conflict-backup.v1`。本地存储不足导致备份失败时不替换当前内容。
   该备份只保留最近一次冲突，建议先下载。

关闭页面前尚未同步的内容依赖浏览器存储；隐私模式或存储空间耗尽时只能暂存在内存。
跨设备同步不包含当前打开会话、面板宽度、页面上下文和正在执行的生成任务。

<a id="sessions-存储和协议"></a>
### 存储和协议

既有扩展路由提供 `GET /api/custom/assistant/sessions` 和同路径 `PUT`。
响应及写入体均为 `{revision, sessions}`；PUT 必须携带读取到的 revision，版本不符
返回 409。删除通过携带删后列表的同一 PUT 完成，空列表仍保留递增 revision。
请求中的账户或租户字段不作为归属依据；响应使用 `Cache-Control: no-store`。

多租户模式复用 `TenantDocuments`：namespace 为 `assistant_sessions`，记录 ID 为
认证上下文的 user_id，租户由 RLS 和现有业务事务限定。同租户不同账户互不可见；
同账户在不同租户也分别保存。读写遵守现有 `business:read/write` 权限和来源校验。
没有租户上下文时拒绝请求，不回退到单机存储。

单机模式在 `data/user_data/assistant_sessions.sqlite3` 按旧账户 ID 保存；无账户的
桌面模式和旧单密码模式使用单机归属。SQLite 事务保证多个进程间的版本比较和替换
原子执行，不采用全局共享 JSON。旧单机 API Token 不能访问会话同步。数据库文件
包含私有历史，应沿用私有用户数据的备份与权限规则，不进入公共行情发布。

回滚代码时保留数据库和 `assistant_sessions` 文档；旧前端仍能读取
`assistant.sessions.v1` 的 sessions/activeId。服务端记录不自动删除，不需要数据库
schema 迁移。该能力通过现有后端扩展路由接入（L2），前端直接修改助手自身状态
（L3）；没有修改核心注册器、行情缓存或研究任务恢复链路。
