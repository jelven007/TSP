# S01 当前实现

名称 `s01`，稳定 ID `custom_mvxxcs01`，自定义股票分钟策略。
本页是其需求、开发、测试和操作说明的唯一规则正文，参数核验日期为 2026-11-25。
核验依据为本地、线上保存源码、覆盖配置、所选信号及实际调用链。
内置模板 ID `s01` 是另一份定义，不能用其默认值解释本策略。

当前源码入口为 [s01_signal_sections.py](../../examples/strategies/s01_signal_sections.py)；
信号值来自策略关联的保存定义，修改信号后须重新核对本页。
运行身份见[版本基线](../version-baseline.md)；
源码、配置核验不表示自然调度、页面、成交或收益已经重新验收。

## 定义来源与执行顺序

保存源码负责基础过滤、评分、执行能力与信号引用；保存覆盖负责当前股票范围、
信号选择等用户设置；关联信号的保存参数负责实际入场／出场时钟和阈值。
通用模板默认值与源码的适配参数基线都不能替代本页已核实的保存值。
当前核对的本地与线上保存定义、覆盖及所选信号一致。
运行身份以实际保存定义为准；工作区文件更新不表示运行保存源码已经同步。
原文摘要、整理差异和本次验证回执归工程交付，不作为策略规则重复维护。

源码中的 `META` 声明执行能力，`BASIC_FILTER` 声明前日资格，
`ENTRY_SIGNALS / EXIT_SIGNALS` 声明信号引用。`trigger_parameter_defaults` 是
仍被适配器校验的参数基线，不是当前所选通用信号的实际阈值；
当前入场和出场表以关联信号保存值为准。

| 顺序 | 输入、计算与输出 | 主要函数 |
| --- | --- | --- |
| 1. 固定执行定义 | Worker 在租户只读事务内读取源码、覆盖、信号、监控世代、按日归档和公共行情发布 ID | `FullWorker.prepare`、`execution_snapshot`、`task_windows` |
| 2. 建立完整池 | 证券目录与时点状态证据确定各策略自身范围；行情缺失仅进入覆盖诊断 | `trusted_scope`、`build_pool` |
| 3. 冻结前日资格 | 完成源日 T−1 日线经过基础过滤和原始评分，保存目标日 T 的预选及精确昨收 | `compute_selections`、`select_rows`、`enrich_selection`、`DailySelections.save` |
| 4. 发布完成分钟 | Platform 将原子落盘分钟发布为不可变输入，Worker／Broker 绑定同一发布 ID | `SelectedMinuteProcess.advance`、`PublicPublisher.publish_minute`、`ComputeBroker.command` |
| 5. 广度阶段 | 14:45:15 起读取完整池的 14:45 价格和精确昨收，计算上涨比例与缺失覆盖 | `evaluate_breadth_phase`、`_evaluate_independent(phase="breadth")` |
| 6. 个股阶段 | 14:46 起只读取冻结预选的完成分钟与冻结昨收；数值交集、启用的 MA、候选评分在一次阶段内完成 | `evaluate_snapshot`、`_evaluate_optional`、`selected_entries` |
| 7. 汇合与保存 | 两侧正常完成且通过才发布买名单；按阶段合并状态，重查世代、定义指纹和截止后提交归档及通知 | `merge_state`、`merge_daily`、`join_buy`、`fence_tasks`、`FullWorker._evaluate` |
| 8. 次日卖信号 | 前日成功买名单供卖页使用，实际账户供持仓执行使用；检查下一交易日、停复牌、首次分钟触发及清仓时钟 | `sell_roster`、`evaluate_sell_task`、`optional_exit_hits`、`morning_liquidation.evaluate` |

此表顺序是数据依赖关系。步骤 5、6 各有计算进程和回执，个股阶段不等待广度完成；
步骤 6 内部的数值、1 分 MA、5 分 MA 是一次顺序计算，不是三个独立冻结阶段。
当前两项 MA 都关闭，回执显示跳过；步骤 7 才决定对外发布。

## 股票范围与前日预选

完整当日股票池按 `strategy_scope_v4` 建立：股票范围中的板块与自选分组取并集，
按该区域的 ST、停牌选择处理。当前选中沪主板、深主板、创业板、科创板，
排除 ST 和停牌，没有自选分组。缺行情、数值筛选、评分、最终命中和展示上限都不能缩小池。

以下数值取目标交易日 T 的精确前交易日 T−1，边界含等号，缺值不通过：

| 条件 | 当前保存值 | 输入与单位 |
| --- | --- | --- |
| 价格 | 12～100 元 | T−1 原始收盘价 |
| 涨跌幅 | 4%～15% | T−1 日涨跌幅；行情存小数，过滤转换为百分数 |
| 振幅 | ≤12% | T−1 日振幅 |
| 成交额 | ≥1 亿元 | T−1 日成交额，源码单位元 |
| 上市年龄 | ≥60 天 | T−1 参考日的上市年龄 |

换手率、总市值、流通市值及上述指标的其他上下限没有启用。
基础数值过滤启用，`data_reference=previous_trade_day`；覆盖只改股票范围字段，
其余继承策略源码。停牌、ST 状态按范围的时点证据处理，不能用缺行情猜测停牌。

盘后预选使用定版日线，默认 21:00 开始，为精确下一交易日冻结选名单；
普通策略的监控提交窗口为北京时间 21:00～22:00（含边界）。
预选不提前应用次日入场信号，也不按展示上限截断归档。
预选同时冻结精确 T−1 的公司行为标记 `reference_prior_ex_date`：
已记录该日除权除息的股票在 21:00 预选时剔除，但仍保留在完整当日股票池中，
沿用原源码的 `prior_ex_date` 排除口径，不额外要求事件日期认证字段。
旧预选缺少此字段时，只从本次绑定的只读公司行为目录补充运行输入，
不重读全市场日线、不改写旧预选；显式 false 或 null 按未排除处理。
买入投影保留相同标记的排除校验。冻结后补录的事件不会自动改写既有归档，
须重新生成受影响且尚未使用的预选，才能使新增证据进入该名单。
逐股参考异常保存代码、原因、缺失及覆盖数量，其余有效股票继续；
整份不可定位证据错误、范围内全无有效日线须明确失败。

## 排名

策略声明 `scoring_mode=strategy`，评分由源码生成，通用评分覆盖不替换它。
系统因子 `intraday_range_amount_score`：

`score = −(high−low)/prev_close + 0.001×ln(amount)`

`amount` 为元；振幅为小数比例，使用自然对数，不加 1、不归一化。
盘后预选使用 T−1 日高低价、成交额及 T−2 昨收；
盘中买信号使用 T 当日截至启动分钟的累计高低价、成交额及 T−1 昨收。
原始分数降序，同分代码升序。缺评分输入保留未知，不删掉已合格预选成员。
源码结果上限为 10000，当前无展示上限覆盖；该上限不参与完整池身份。

## 入场信号

当前只选择 `csgi_late_session_strength_s01`，名称 `s01_尾盘建仓`，
模板为通用 `late_session_strength`。

| 参数 | 当前保存值 | 实际含义 |
| --- | --- | --- |
| `time` | 14:45:00 | 启动时间；固定输入分钟标签 14:45 |
| `evaluation_delay_minutes` | 1 | 等待 60 秒，最早 14:46:00 确认 |
| `pool_up_min_pct` | 65 | 完整范围中有效成员的上涨占比 ≥65% |
| `change_min_pct / change_max_pct` | 2 / 3 | 14:45 收盘价相对精确昨收涨幅 2%～3% |
| `amount_min_100m` | 1 | 当日可用完成分钟累计成交额 ≥1 亿元 |
| `amplitude_max_pct` | 5.5 | 累计最高价与最低价之差÷昨收 ≤5.5% |
| `end_time` | 15:00:00 | 保存的模板结束时间 |

1 分 MA5、5 分 MA5、换手率和量比均为 null，关闭对应条件。
所有启用的个股数值条件取交集，涨幅及阈值边界含等号。
当前没有市场有效股票数参数或数量门槛。

上涨严格指涨幅 >0；分母为完整范围中同时具有有效指定分钟价格及精确昨收的成员。
完整池、有效数、缺失代码与占比单独保存；没有有效成员是输入不足。
当前信号要求有效的 14:45 分钟价格；累计高低价和成交额使用 09:31～11:30、
13:01～14:45 已完成可用分钟，同股同时间取最后一条，成交额不重复累计，不补造缺口。
不要求固定根数；等待确认不把输入右端点推到 14:46。

S01 声明 `entry_phase_policy=independent_v1`，两项计算各自独立：
启动时间＋15 秒（当前 14:45:15）按本策略完整当日股票池计算上涨占比；
启动时间＋保存确认延迟（当前 14:46:00）按当天冻结预选名单计算个股条件。
个股阶段不等待广度完成，不重复筛选前日资格；使用预选成员冻结的精确昨收。
两项正常完成且同时满足才生成买名单。
正式运行由 ComputeBroker 为每策略的广度、预选股参数分别启动独立计算进程；
广度入口不加载用户策略源码，个股请求只携带本策略源码和冻结输入。
关键时段在原 CPU／内存总预算内保留一个个股计算槽（有效并发至少为 2 时）。
`PhaseInbox` 不等待在途阶段，每个阶段自己的派发时刻加 60 秒是绝对期限；
当次排队和计算另受剩余有效窗口限制。
客户端清理等待及首次汇合后的通知请求不在这 60 秒内，不能据此承诺整轮提交耗时。
超时／取消先回收进程再释放槽，
失败阶段保留可重试回执，另一阶段已完成的回执及内部状态按所属阶段合并。
启用权威输入的 Full 自动监控复用 S02 的封存、镜像、校验与阶段调度机制。线上从
不可变公共发布读取输入，按交易日、保存定义、算法摘要及信号绑定同一份完整池和当天冻结预选；
两阶段分别封存，首次封存后同一身份不接受行情修订覆盖。本地校验并接收相同清单，
未同步期间保留 `waiting_input`，不另用本机行情计算。双方 Compute 只读取封存数据，
阶段回执保留 `input_sha256`。

广度只读启动分钟和精确 T−1 原始日线，不重算历史指标；
个股使用 09:31 至启动分钟的交易时段可用前缀，启动行及已启用的 MA 窗口须校验，
不把累计条件变成全天固定分钟根数门槛。前日参考缺失、启动行缺失或连续必需窗有缺口时，
在有效窗内等待并修复，不能以普通或优先采集的完成时钟证明缺行不可用。
同股同日经两次不同序号的成功完整请求仍缺必需依赖，或已有可定位的非法输入证据时，
才隔离该成员。两种情况都保留完整池身份、缺失代码和原因；全无有效成员明确失败。
关闭权威输入的兼容调用仍由绑定的公共发布提供行情；该旧路径的普通采集完成时钟
仅能解除广度的到齐守卫。历史回放不改写原盘中回执。
广度正常未达门槛即业务拒绝，但个股计算仍独立完成并保留回执；
输入失败由监控任务修复并在有效窗口重试，不能把确认时刻当成修复截止。
成功与正常零命中保存终态，重复调用复用已存回执。
个股缺启动行与全天前缀有可用分钟间断的语义不同：前者必须完成输入校验，
后者只使用实际完成且可用的分钟，不补造。价格、昨收或启用字段异常可逐股隔离，
缺失成员及数量随回执保存。
正常冻结后，之后补齐的成员不会自动追加。单侧输入失败只重试该侧；
个股阶段重试会重新执行内部数值和启用的 MA，不复用失败尝试的中间筛选结果。
数值与 MA 等内核子步骤的实际起止、单调时钟耗时及处理／通过／缺失数量
来自 `progress.steps`。阶段汇总的 `scheduled_at` 是计划时间，
`started_at` 是首次生成阶段回执的时间，`history[].started_at` 是本次回执记录时间，
均不证明容器或子计算实际何时开始；`completed_at` 表示形成终态回执的时间，
不表示归档已提交或已经成交。等待回执也计入尝试数，
判断是否曾失败须检查 `first_error`、`history` 和子步骤状态，不能只看最终成功。

引擎先注入通用信号，再以 `_s01_skip_entry=True` 和冻结预选调用源码投影候选，
避免同时施加源码参数基线中的备用入场阈值。候选按信号的启动分钟标签使用
有效 OHLC、累计成交额和冻结昨收计算原始分数，不要求再次加载两条前日日线。
权威链路绑定当前尾盘信号，不接受另需股本、量比日线或分组的输入。
其他执行路径仍按所选信号准备其依赖；无冻结预选的原生／历史适配路径保留原契约。
最终买名单只从当天已保存预选成员中确认；缺预选明确等待或失败。
实时新入场以 T 日 14:55:00 为总截止，整点允许，超过拒绝新买入或入池。
该总截止独立于保存的 15:00 模板结束时间，不追改历史冻结回测。

## 出场信号

当前只选择 `csgi_morning_liquidation_s01`，名称 `s01_早盘清仓`，
模板为通用 `morning_liquidation`。

| 参数 | 当前保存值 | 实际含义 |
| --- | --- | --- |
| `start_time` | 11:15:00 | 从此时开始检查提前出场 |
| `decline_3m_pct` | 0.2 | 3 分钟跌幅 ≥0.2% |
| `volume_ratio_min` | 1.5 | 最近 3 根均量÷此前 10 根均量 ≥1.5 |
| `time` | 11:26:00 | 未提前触发时产生时钟清仓信号 |
| `fallback_time` | 13:30:00 | 到点停止卖出，撤销余单、保留余股 |

涨幅、跌幅条件为 null，成本止盈／止损未启用。
放量下跌的两项须同时满足：
`decline = (1−close[t]/close[t−3])×100`；
`volume_ratio = mean(volume[t−2:t])/mean(volume[t−12:t−3])`。
使用 13 根连续完成分钟，时间间隔逐根为 60 秒；跌幅用末 4 根的有限正价格，
量为有限非负数，前 10 根均量必须 >0。窗口不跨缺口或午休，
可使用 11:15 之前的回看分钟；同股同分钟取最后一条。

优先返回第一条真实分钟触发；11:26 前未触发，时钟分支仍可在缺行情时产生信号。
13:30 是截止，不产生另一轮兜底卖出信号；截止后的历史触发可用于诊断，
`deadline_elapsed` 阻止执行端重开卖出窗口。
按买入后的精确下一交易日检查，实际持仓另受可卖数量和 T+1 约束。
已确认停牌保留持仓，复牌使用明确停复牌证据独立退出。

## 子计算与异常处理

| 子过程／异常 | 当前实际处理 | 回执或持久化边界 |
| --- | --- | --- |
| 非已确认交易日、监控未启用 | 不生成相应到期动作；不自行启用监控 | `plan`、`strategy_windows` |
| 证券目录不可用、完整池缺身份 | 输入错误；不能改用命中名单或有行情的子集建池 | `trusted_scope`、`daily_pool_snapshots.error` |
| 前日收盘参考缺失、重复、非法价格或定版时钟异常 | 可定位时逐股隔离，其余有效股票继续；整份结构错误明确失败 | `reference_errors`、预选 `coverage.invalid_symbols/missing_symbols` |
| 范围非空但全无有效前日日线 | 预选失败；有效日线经阈值过滤为零才是成功空预选 | `compute_selections.errors`、`valid_selection` |
| 预选缺失、日期不符、源日不是精确 T−1 | 个股输入失败并等待有效归档；分钟补数不能制造预选 | `_evaluate_independent`、`request_phase_repairs` |
| 已保存成功空预选 | 个股正常零结果并冻结，记录处理／通过数为零 | `conditions_rejected` |
| 同股同分钟重复 | 取最后一行，再做累计高低价与成交额；不重复累加 | `_evaluate_optional`、`selected_entries` |
| 权威输入未就绪或缺启动行但无缺失证据 | 保持等待，补齐必需依赖；本地缺镜像不回退独立行情 | `waiting_input`、阶段输入覆盖 |
| 真实坏值或有完整采集证明的缺失 | 逐股隔离，完整池、缺失代码、有效数及上下界单独保留 | `input_excluded_symbols`、`pool_total/pool_usable/missing_symbols/pool_up_pct` |
| 广度全无有效成员 | 输入不足，阶段失败并修复重试；不产生 0% 的成功回执 | `waiting_data`、阶段 `errors` |
| 广度正常低于 65% | 正常业务拒绝并冻结该侧；个股阶段仍独立完成 | `breadth_rejected`、阶段 `rejected` |
| 部分股票累计字段缺失、非有限值、负成交额或无效高低价 | 该股不能通过对应启用条件；保存缺失数量，其他股票继续 | `change` 步骤 `missing/passed` |
| 全部数值候选缺少启用依赖 | 个股阶段失败并修复重试；阈值外正常淘汰仍为正常零命中 | `change.state=failed` |
| 未到 14:46、窗口尚未开始 | 等待，不把未确认输出当作成功空名单 | `waiting_start/waiting_confirmation` |
| 已关闭条件 | 不筛选、不要求专用数据；当前 MA、换手率、量比均跳过 | `steps.*.state=skipped` |
| 开启 MA 后部分／全部缺连续窗口 | 部分缺窗逐股跳过；全部候选缺窗使个股阶段失败并整体重试 | `ma_skipped_symbols`、`ma1/ma5` 回执 |
| Provider 补数失败、同发布版本补数在途 | 保存修复错误或等待；新发布 ID 允许未完成阶段重新校验输入 | `repair`、`wait_for_repairs` |
| 排队满、计算异常、回执缺失、超时或取消 | 保存失败回执；Broker 回收容器及子进程后释放槽，已完成另一侧保持 | `failed_phase_results`、`_compute_timing`、`merge_state` |
| 普通监控计算失败 | 已完成的自定义阶段和状态保持，另记录普通监控错误 | `FullWorker._evaluate` |
| 汇合时超过 14:55 | 不发布新买入，记录过期；广度计算窗口不含 14:55 整秒，个股及汇合整秒可通过 | `plan`、`join_buy`、`fence_tasks` |
| 计算期间定义／监控世代／任务租约变化 | 拒绝迟到提交，不覆盖新配置和状态 | `assert_generation`、`fingerprint`、`valid_claim` |
| 分钟复制期间源变化、基线无效、容量不足、并发发布抢先 | 保持已有 `current` 指针，保存错误并重试；旧发布不能回滚新分钟 | `publish_minute`、`_commit` |
| 卖页无前日归档／明确成功空归档 | 缺归档保留原因；有明确归档身份的空名单可成功为零 | `sell_roster`、`evaluate_sell_task` |
| 卖信号缺买入日期或交易日历 | 逐股跳过并诊断；不能用自然日推断下一交易日 | `morning_liquidation.evaluate.diagnostics` |
| 卖信号分钟缺口、量非法、前 10 根均量为零 | 不确认该窗口的放量下跌；继续后续有效窗口，11:26 时钟分支仍可触发 | `_optional_minute_hit` |
| 当前已到 13:30 或之后 | 不新开卖出窗口；保留首次触发诊断，余股和停牌持仓继续保留 | `deadline_elapsed`、执行截止 |

阶段终态包含正常成功、正常拒绝、取消和过期；可修复的 `failed` 不算终态。
默认失败计划间隔为 3 秒，卖观察为 30 秒；实际执行还受调度、修复和计算资源影响，
不能从计划间隔推断完成耗时。首次错误、最近最多 32 次尝试以及真实完成回执均保留。

## 卖／选／买与成交

`META.result_sections=signals`：卖读取同策略精确前交易日的成功买信号归档；
选读取目标日完整冻结预选；买从该预选中确认当日入场。
卖名单、持仓出场信号和实际卖出成交各自独立，三页名单不等同成交。
历史查询、无摘要、缺归档、正常空名单须分别显示状态。
策略页面删除 S01 的「策略说明」折叠内容；卖／选／买之后固定显示一项「上涨占比」，
三页使用本策略同交易日保存的广度回执，零值显示 `0.00%`，
缺回执或日期不匹配显示 `—`；浏览器不额外计算或加载完整池。
触发器选择由 `optional_v1` 接入，可取消或多选；多入场信号须同股、同评估时点全部满足，
空选走基础候选，出场按最早命中的所选信号处理。当前保存值各为单选。

所有自定义策略共用分钟成交规则：建仓取该分钟最高价，清仓取该分钟最低价；
容量由真实分钟量与分别保存的建仓／清仓参与率计算，按股数单位向下取整。
公共表单新建默认两项各 10%，不是本次读取的已保存回测参数。
信号确认后从下一可成交分钟开始；午休不成交，缺分钟不延长截止，
不能从信号价格推断成交价格、股数或完成状态。
资金、仓位、费用及跟单属于公共回测／账户配置，见[操作说明](../../操作说明书.md#91-策略回测)。
本次没有新运行收益回测；原冻结参数、结果与账本保持原身份。
