## 2. 当前功能与边界

已发布主线包括三组任务连接、失效会话来源核验、指数日/周/月完整本地历史读取
和实时轮询 1～10 秒整数控件。六周期 K 线、自选关系、持久策略归档及七项
Provider 路由等功能的源码入口见[功能地图](architecture.md#capabilities)。

发布验收记录同时保留 301110.SZ 三四月 5,520 个历史缺失键，
以及任务报告中的其他未返回键。任务 `succeeded`、请求为零或界面 100%
均不能认证全部历史已经初始化。

当前模式为模块化单体及完整单机多租户七角色实现。100 用户单次混合负载、
SSE 客户端扇出和持续活跃业务容量是不同证据；
第二步持续窗口与第三步万人目标仍按[阶段计划](planning/phase2-implementation-plan.md)
独立签收。Kafka/Flink/ClickHouse/Redis/TOS 多节点目标不因文档存在而成为当前部署依赖。

## 3. 应用版本规则

主应用版本采用 `a.b.cd`：`a=0..9`、`b=0..9`、`cd=0..99`，末段不补零。
本地迭代、提交、功能分支推送及本地合并不递增应用版本。
变更集成到远程 `main` 后，CI 对一次主线 push 自动递增一次；
功能、修复、文档和构建配置遵循同一规则。

完整算法、并发写回、重跑去重、标签与产物固定规则见
[CONTRIBUTING 10.1](../CONTRIBUTING.md#101-主线版本规则)。
版本分配先于质量门；分配了版本号不表示测试、发布或部署已经通过。
第三方依赖、独立 MCP 包、原生桥接和历史报告不跟随应用自动改号。

本地检查：

```bash
python3 scripts/check_version.py --current VERSION
```

不得手动改版本来解决文档或功能分支的一致性问题。

## 4. 交付身份与状态

每次可复现交付同时记录应用版本、完整 Git SHA、环境/schema、
镜像 digest 或安装包 SHA-256，以及同身份的测试、发布、恢复和切换证据。
不使用“最新版”替代这些标识。

| 状态 | 判断依据 |
| --- | --- |
| 已实现 | 当前源码和契约支持该行为 |
| 本地验证 | 明确的本地差异、环境、命令和结果 |
| 主线通过 | 自动版本提交通过对应 CI |
| 产物已发布 | 相同提交的选定平台产物通过验收并冻结 |
| 环境已升级 | 实际切换、登录、业务、数据和重启验证 |
| 容量/历史已签收 | 对应数据窗口、持续负载与完整性证据 |

`main`、Git Tag、Release 和生产版本可以不同。标签和已有冻结资产不可强制移动；
升级使用对应代码、原生组件、schema 与数据备份。
远程权限和协作规则见[工程参考](reference/engineering.md#collaboration)。
