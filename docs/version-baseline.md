## 2. 应用版本规则

主应用版本采用`a.b.cd`，末段不补零。本地迭代、提交、功能分支推送和本地合并不加号。
远程main每次集成push由CI自动递增一次；版本分配、质量门、发布及部署分别判断。
完整规则见[CONTRIBUTING 10.1](../CONTRIBUTING.md#101-主线版本规则)。

```bash
python3 scripts/check_version.py --current VERSION
```

不手改VERSION或锁文件来消除开发与运行环境差异。

## 3. 状态与维护

| 状态 | 必要依据 |
| --- | --- |
| 已实现 | 当前源码与契约支持 |
| 本地验证 | 明确环境、命令及本次结果 |
| 主线通过 | 固定自动版本提交通过CI |
| 产物已发布 | 同提交产物验收并冻结 |
| 环境已升级 | 实际切换、登录、数据及重启验证 |
| 容量／历史已签收 | 对应真实窗口、负载及完整性证据 |

发布候选规则维护在本页，环境切换的完整提交、安装快照、schema、digest及实际状态
记录在本轮验收交付件，避免把发布前采集值冒充新环境身份。
旧安装过程不再追加到主手册；当前验收及必要不可变证据见[交付入口](../deliverables/README.md)。

清理前核对指针、挂载、进程、独立Git工作和恢复依赖。本地正式运行单元保留且不留
部署备份；线上保留当前运行单元及最近一份完整、恢复验证通过的备份。
故障恢复期间在用备份先保护，验收后按数量清理。
当前数据、受控配置、未完成开发及审计不作为缓存删除，历史研究文件按用户清理授权处理。
