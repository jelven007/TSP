## 3. 应用版本规则

主应用版本采用 `a.b.cd`：`a=0..9`、`b=0..9`、`cd=0..99`，末段不补零。
本地迭代、提交、功能分支推送及本地合并不递增应用版本。
变更集成到远程 `main` 后，CI 对一次主线 push 自动递增一次；
功能、修复、文档和构建配置遵循同一规则。

完整算法、并发写回、重跑去重、标签与产物固定规则见
[CONTRIBUTING 10.1](../CONTRIBUTING.md#101-主线版本规则)。
版本分配先于质量门；分配了版本号不表示测试、发布或部署已经通过。
第三方依赖、独立 MCP 包、原生桥接和历史报告不跟随应用自动改号。

本地检查：

```bash
python3 scripts/check_version.py --current VERSION
```

不得手动改版本来解决文档或功能分支的一致性问题。

## 4. 交付身份与状态

镜像 digest 或安装包 SHA-256，以及同身份的测试、发布、恢复和切换证据。
不使用“最新版”替代这些标识。

| 状态 | 判断依据 |

| 环境已升级 | 实际切换、登录、业务、数据和重启验证 |
| 容量/历史已签收 | 对应数据窗口、持续负载与完整性证据 |

`main`、Git Tag、Release 和生产版本可以不同。标签和已有冻结资产不可强制移动；
