# 策略指南

策略是选股引擎、回测、监控的基础。本文介绍策略体系与三种扩展方式。

完整策略开发规范(AI 生成与手写)见 [`backend/app/strategy/prompts/strategy-guide.md`](../backend/app/strategy/prompts/strategy-guide.md)。

---

## 内置策略

**22 个公开内置策略**,各自保留独立 ID 和参数,通过 `matrix_native` 矩阵协议执行
(`backend/app/strategy/builtin/`)。策略池可按以下六类交易逻辑筛选和批量加入:

| 类型 | 策略 |
| :--- | :--- |
| 趋势跟随 | MA 金叉 · MACD 金叉放量 · 均线多头 · 低波动龙头 |
| 放量突破 | 量价齐升 · 布林突破 · 放量创60日新高 · 平台整理突破 · 均线粘合突破 |
| 趋势回踩 | 缩量回踩 · 均线回踩反弹 · RSI 中轴回踩 |
| 超跌修复 | 新低反转 · 超跌反弹 · 超跌反转 · 长下影反击 · MACD 零下回升 |
| 强势延续 | 高换手拉升 · 强势高开 · 逼近涨停 |
| 涨停生态 | 涨停基因活跃股 · 连板股 |

分类仅表示交易意图,不表示多个策略可以独立分散风险。两套 RSI 超跌和两套
MA20 回踩共用计算,保留各自的确认、评分、退出、ETF 支持及历史参数单位。
自定义、AI 和旧版响应中没有分类的策略仍可从“未分类”选择。

MA 金叉默认增加“要求MA60近5个交易日不下降”过滤,按该证券的有效交易日
计算并预热65根K线。参数 `require_ma60_non_declining=false` 可恢复原入场规则,
其他旧参数和用户主动关闭的状态继续生效。该过滤仅有探索性历史样本中的
相对改善证据,五年连续回测仍亏损;不能视为可独立盈利或已通过实盘验证。
完整数据限制、22策略诊断、失败试验及分期结果见
[五年研究报告](../reports/default-strategies-five-year-20261017/analysis.md)。

2026-10-11 精简了三个重复变体：

| 已删除 ID | 家族代表 | 原因 |
| :--- | :--- | :--- |
| `trend_breakout` | `breakout_new_high_60d` | 同为60日收盘新高加放量，主要区别是门槛、评分与基础过滤 |
| `limit_up_momentum` | `consecutive_limit_ups` | 连板阈值变体；代表策略的 `min_boards` 可表达首板与多板研究 |
| `broken_board_recovery` | `consecutive_limit_ups` | 实际仅筛放量涨停，没有实现断板及反包历史结构 |

代表策略默认参数不变，旧 ID 不自动重定向。历史回测记录保留；重跑已删除策略需使用原版本源码。
升级前应检查自定义叠加策略、监控和模拟盘自动规则是否引用旧 ID，显式解除或改写后再热重载，
避免不同条件被静默替换。两种 RSI 超跌、两种均线回踩以及不同突破机制仍分别保留，
因为其实际候选与触发时点存在明显差异。策略保留不等于已经验证可盈利。

### 可选入场候选

19项内置策略提供 `entry_variant` 参数，默认 `original` 保留原版。首轮共31个
候选，覆盖首次触发、平台均价、回踩/新低的延后确认、收盘位置和零轴分层；
每策略最多两个，不能解释为已验证盈利的推荐配置。完整清单及研究边界见
[升级实施记录](../reports/strategy-optimization-20261019/implementation.md)。

新低和回踩的两阶段候选先冻结形态日高低点，随后1—3个市场交易日内收盘
突破高点才确认；影线候选只等待下一交易日。跌破低点优先取消，停牌计入到期，
确认日不重新要求新低或缩量。信号确认后仍按所选成交时点执行，保留T+1、
开盘封板拒单和统一退出优先。旧仓位继续沿用入场政策快照。

平台候选的高、低、收盘价和成交量使用同一组完整有效K线；缺任何必要字段
就整根跳过，历史有效根数不足时不产生平台信号。原版定义保持兼容。

低波动龙头的宽基相对强度和一进二分钟承接尚无完整冻结数据；当前连板策略
仍表示收盘后的接力观察。入场形态候选沿用原退出、评分和仓位，默认规则
不会因为一轮历史胜率较高而自动更新。

### 可选成交与风险政策

策略设置的「交易参数」新增入场风险控制，保存在 `overrides.entry_risk`。
缺省全部关闭；配置通过现有参数缓存、回测/优化配置和监控事件快照传递。
这是核心撮合能力，不是新的公共插件接口。

| 配置 | 单位及行为 |
| --- | --- |
| `max_entry_premium_pct` | 小数制，例如0.03；实际拟成交价格不超过信号观察价格的103%，不满足即放弃本次入场 |
| `stop_atr_multiple` | 信号日14期ATR的倍数；入场时冻结保护位＝成交价格−倍数×信号日ATR |
| `stop_signal_low` | 冻结已确认信号日低点；两阶段入场使用确认日，不是之前的形态日低点 |
| `risk_per_trade_pct` | 小数制，例如0.005；计划价差损失不超过权益的0.5%，只缩减现有资金/仓位规则允许的数量 |

新增保护位与原固定/移动保护共同执行，以更严格的价格为准。持仓后不随ATR变化
放宽；若入场价已低于结构保护位、参考值无效或缺失，拒绝该笔交易。
复权历史矩阵在同一复权尺度内计算，最终申报数量仍以当日原始价换算。
交易明细新增 `raw_frozen_stop_price`，保留原始保护价格便于复核。
独立候选模式不分配账户资金，风险金额限制只用于组合仓位和模拟盘。

模拟盘需开启「跟随策略风控」。监控逐证券保存信号时观察到的价格、ATR和低点，
换算为原始价格并随订单/成交留档；成交时再次检查溢价和风险数量。
已知除权事件用于同步价格尺度，参考日期无效时拒单。成交台账重建保留冻结保护位；
已有持仓不加仓，避免新旧政策混用。旧持仓不补写当前政策。
日线政策不支持分钟策略的当日最终OHLC参考；缺少前一信号日参考时拒绝成交。

风险金额指计划价差损失，不含费用，也不能保证跳空、T+1或跌停后实际损失不超额。
六项优先策略分别登记ATR2倍、信号日低点和0.5%风险三个单主题；强势高开单独
登记3%/5%溢价上限。连同31个形态候选及22个原版共73次，未验证前不自动改默认。

### 买入资格与退出优先

- `exclude_st=true` 在信号日筛选，并在实际成交日按历史证券状态再次复核。
  次日买单缺行情或受停牌/限价约束时不延续到复牌日；已持仓证券仍可估值和卖出。
- `exclude_new_days=N` 按正式上市日期计算自然日年龄，上市当天为 0，
  年龄达到 N 才允许入场。设为 0/空值或关闭基础过滤可禁用；开启时上市日期缺失不放行。
  上市日期取证券维表的正式 IPO 日期，不能用行情窗口起点或旧 ST 回填记录的首条行情日期。
  此项仅适用于股票，ETF/指数自动中和。
- 同一根信号 K 线上入场和退出同时成立时，退出优先，先删除入场再评分、延迟成交。
  该规则用于矩阵策略、Polars 策略及叠加回测；退出通知继续保留。
- 成交日复核仅使用证券资格，不用当天收盘价、成交额等未来信息复核次日开盘买点。
  分钟回放中的价格指标仍来自 T-1，证券资格使用 T 日状态。
- 历史 ST 状态不完整时，兼容模式仍保留原有回退并报告治理缺口；
  `strict_research=true` 拒绝状态覆盖不足的回测。成交资格拦截计入 `execution.buy_ineligible`。
  矩阵磁盘缓存升级为 v8，上市日期变更会使缓存失效。
  回测配置记录 `entry_policy_version`；旧规则产生的选股缓存和“今日曾命中”缓存自动失效。

### 开盘限价与待卖

股票日线撮合按成交价格检查当日涨跌停价。开盘涨停后盘中打开，不能证明开盘买单
成交；该买单记为 `buy_limit_up`，不延续为后续日期的买单。开盘跌停的卖单和跳空
止损同样不能按开盘价卖出，记为 `sell_limit_down` 并保留退出意图待后续可成交时处理。
盘中止损价高于跌停价时，不因后来收盘跌停而拒绝该次退出。

组合按开盘跳空风控、开盘计划卖出、开盘买入、日内风控/收盘卖出、收盘买入
的顺序处理。日内卖出不能释放资金或仓位供当天开盘使用；配仓估值使用当时
已知价格。分钟价覆盖/日线分钟细化没有完整账户事件顺序时，先预留买入额度，
不借用同日时序未知的卖出收入。收盘或分钟买入不继承入场前的日最高价作为
移动保护峰值；当天新仓继续受T+1约束。

限价从原始参考价计算，再转换到回测 OHLC 的复权尺度。适用历史 ST 规则、注册制
新股窗口和当日有明确日期的权威限价；未来或无日期的证券最新限价不覆盖历史。
矩阵加载时保存这些约束，窗口切分和缓存读取继续保留。已有分钟回放使用其成交时点
校验。ETF 不套用股票的新增限价检查。结果配置记录
`execution_model_version=raw_price_frozen_entry_risk_v6`，与旧模型结果区分。

下一根市场K线缺少该股票数据时，买单过期并计入 `execution.buy_expired`；
卖出意图继续保留。受阻天数按日期去重，同根K线不重复提交已经被拒的退出。
独立候选模式的期末未平仓记录保存在 `stats.unclosed_positions`，另列数量和
未实现盈亏，不强制构造一笔无法成交的平仓，也不计入已实现胜率/PF。

旧数据无法建立参考价时仍保留原收盘封板标记的兼容约束；历史状态未知和上市窗口
缺完整日历的兼容近似不能作为严格成交验收证据。日线 OHLC 本身不证明排队成交。

### 最低佣金与入场申报数量

策略回测、矩阵回测、分钟策略的日线账户撮合及优化任务共用
`minimum_commission`（每笔每边，元）和 `transfer_fee_pct`（双边小数费率）。
二者默认0兼容旧配置；按实际券商费表填写，佣金已包含的规费不得重复计入。
买入配仓先预留最低佣金及其他买入费用；卖出税费只影响卖出腿。
结果记录 `cost_model_version=cn_stock_tax_minimum_commission_v2`。

入场数量用当日原始价格计算：科创板至少200股、以1股递增、单笔限价申报最多10万股；
其他现有沪深股票按100股递增。依据为[上交所科创板申报数量说明](https://edu.sse.com.cn/tib/qa/)。
ETF仍使用其既有100份单位且不套用科创板规则。
`raw_entry_shares`、`raw_entry_price`保存入场申报量与原始价；旧`shares`和
`entry_price`继续作为复权收益模型的等价单位，供历史消费方使用。
回测持仓和收益沿用连续复权序列，并非包含分红税、配股和逐笔股份变动的实物交割账本；
这些结果不能替代实际账户交割验证。

### 价格、评分与交易统计

绝对价格、总市值和流通市值过滤使用信号日 `raw_close`；趋势和收益指标继续使用
复权价格。股本沿用数据层按公告时间提供的历史值及既有降级规则，不在策略层替换成
最新股本。旧输入完全没有原始价列时兼容使用 `close`，这不表示满足严格历史研究要求；
已有原始价列中的空值不回填为复权价。启用市值限制但股本缺失时拒绝入选。

有非零权重的评分字段都必须可计算。整列依赖缺失明确报错；个别股票的空值、
NaN 或无穷值会排除该股票的入场资格，并在其余候选的归一化前剔除。
真实零分仍可入选。上述规则由选股、普通回测、矩阵回测共用，缺评分不会删除
持仓估值行或已有退出信号。升级会失效旧的选股与“今日曾命中”缓存，
保留历史回测记录和用户参数。

新执行回测返回以下明确指标，优化器和步进优化也可选择对应目标：

| 字段 | 定义 |
| --- | --- |
| `profit_factor_amount` | 已平仓净盈利金额总和 / 净亏损金额绝对值总和 |
| `payoff_ratio` | 平均盈利交易收益率 / 平均亏损交易收益率绝对值，零收益不计入两侧均值 |
| `net_expectancy` | 全部已平仓交易净收益率均值，包含零收益 |
| `n_wins` / `n_losses` / `n_flat` | 净收益率大于 / 小于 / 等于零的交易数 |

金额缺失时不会用收益率伪造金额 PF；没有亏损时分母为零，比例显示为缺失值。
旧 `profit_factor` 为兼容保留原算法（非正收益参与亏损均值），界面优先展示新的
`payoff_ratio`，旧结果不追溯改写。CSV 分列导出两种口径。胜率的分母始终包含
零收益已平仓交易；浮动持仓另由账户净值体现。历史净期望不是未来盈利承诺。

### 滚动验证的窗口与持仓边界

步进优化页面新任务默认训练504、测试126、步进126个交易日，并隔离30个交易日。
`window_unit=trading_days` 按本地 enriched 日线分区日期的条数切窗，跳过节假日；
日期列表与哈希写入结果 `window_policy`。它是观测日历，不能证明全市场缺失分区、
退市股票或历史状态已经补齐。没有足够真实日期时拒绝任务，不推算工作日。
服务器范围保护继续按实际自然日跨度限制单折内存规模。

旧配置缺少 `window_unit` 时保持 `calendar_days`，按原闭区间自然日跨度计算；
例如旧 `train_days=252` 表示相隔252个自然日的两个端点，不是252个交易日。
`purge_days` 默认0，单位与窗口一致，隔离期内不选参也不计算测试收益。

训练折和测试折均使用组合仓位模式，只使用各自窗口内的行情。旧请求中的 `full`
会明确记录为请求模式，实际模式记录为 `position`，不向后借行情平仓。
期末可成交才退出，无法退出的持仓留在本折净值和未平仓统计中。
组合输出未平仓数量、未实现盈亏和待卖数量；缺行情尚未生成退出意图的持仓
也计入未平仓，轻量优化结果保留这些诊断字段。
独立候选回测也按市场交易日计算持有期限；个股最后一根行情不能代替全市场期末，
后续停牌或缺行情的仓位保留为未平仓，不倒退到最后有行情那天强制卖出。
撮合结果版本为 `raw_price_frozen_entry_risk_v6`。

仅日期完整、测试窗不重叠、所有窗口末尾没有未平仓时计算独立折复利。
其他情况保留逐折收益与退化，复利收益为null，附不可聚合原因。
独立折复利不代表真实连续换参账户。已参与策略开发的历史区间即使滚动计算，
仍属于探索性诊断，不能重新宣称为未使用的样本外证据。

内置目录 `backend/app/strategy/builtin/` 还包含一个仅供挖掘 worker 使用的受控因子排名研究模板。它不出现在普通选股列表，也不能通过普通策略 API 直接运行或保存 override；挖掘结果发布时会生成独立策略。详见 [因子与策略挖掘](./mining.md)。

内置目录 `backend/app/strategy/builtin/` 由项目维护,**AI 生成的策略不会落入此目录**。

### 实时事件与模拟盘自动退出

实时监控复用一次策略计算，分别输出通知和逐证券执行事件。通知超过 5 只时仍汇总，
执行事件保留每只证券的 `strategy_id`、`type`、`symbol`、`price` 和信号；
通知冷却不会吞掉新的执行边缘。同根 K 线信号去重、首次快照基线以及监控规则
`notify_events` 选择继续生效，Worker 重启后恢复监控状态。

模拟盘 `side=auto` 把卖出信号或出池事件保存为全平待办。T+1、已有待卖单、
缺行情和撮合失败时保留目标，后续轮询无需新信号即可重试。待办绑定当前持仓周期；
再次建仓、自动规则停用/删除或修改执行配置会使旧待办失效。
详细状态、取消与成交时刻契约见[模拟盘实现说明](./paper-trading-plan.md#5-运行时挂点全部复用现有引擎)。

逐证券执行事件同时携带评分、原始交易价格和当时有效的风控参数快照。
模拟盘新建策略跟单规则可按评分优先分配名额，并设置单股和账户总仓位上限；
待买单、手动持仓和加仓计入额度。开启“跟随入场时策略风控”后，
止损、止盈、移动风控和交易日持有期以该持仓周期首笔成交政策为准，
后续调整策略不会改变已有持仓政策。无入场快照的旧持仓从下一轮新开仓生效。
回测和模拟盘共用风险触发线，实时退出依赖实际观察到的价格和随后可成交的行情；
完整日线 OHLC 与实时采样产生的执行差异见[风控政策说明](./paper-trading-plan.md#风控政策候选排序与开盘入账第二批)。

### 策略组实时求值与组合裁决

独立行情服务中的策略监控已使用容量为 1 的 latest-only 协调器。每轮冻结行情、
规则顺序、名称、自选分组和策略状态 generation；同资产的唯一策略集合共用一次
最大历史窗口读取和一次矩阵准备，同一策略被多条规则引用时只执行一次。
规则层仍分别应用 scope、评分区间、通知事件、冷却和选股池边缘。

价格、信号、异动、封单和成交量差等通用规则不进入 latest-only 邮箱，继续逐份
行情快照同步求值，避免策略计算慢时吞掉瞬时穿越。策略计算阶段不发送通知、不下单；
只有版本仍有效且成功发布的周期才由行情主线程执行外部副作用。

协调器事件携带 `strategy_cycle_id`、`strategy_cycle_state` 和冻结的
`strategy_priority`。模拟盘按同周期同证券统一裁决：

- 同股买卖冲突时退出优先；
- 多策略同时买入只保留一笔，持仓政策冻结主策略与全部归因策略；
- 多策略退出合并为一个退出意图，优先使用现持仓的主策略；
- 已持仓或已有待买订单时默认不加仓；
- 持仓数、单股和总敞口采用本周期匹配规则中最保守的非零限制；
- 部分失败或消费时超过 15 秒的周期只保留退出，不创建新买单。

不带周期 ID 的历史事件和直接调用路径继续沿用原逐规则行为。当前物理并发保持 1；
“五策略同轮运行”表示共享同一快照和账户决策，不等同五线程。策略组配置/状态 API、
前端编组、多租户任务接线、并发度 2 基准和真实交易日自动跟单观察仍未完成。
设计与阶段证据见[五策略方案](../reports/five-strategy-parallel-20261019/plan.md)和
[实施记录](../reports/five-strategy-parallel-20261019/implementation.md)。

## 扩展策略的三种方式

### 🎛️ 方式一:自定义信号(不写代码)

在选股页 UI 上用 `字段 + 操作符 + 阈值` 组合,编译成 Polars 表达式热加载。适合:

- 快速验证一个简单的筛选思路(如 `RSI < 30 AND 量比 > 2`)
- 不熟悉 Python 但想自定义筛选条件

底层实现在 `backend/app/strategy/custom_signals.py`。

### 🤖 方式二:AI 生成

一句话描述思路,LLM 读取精简运行时指南生成完整策略文件:

1. **配置 AI 接口**(留空即关闭,见 [configuration.md → AI](./configuration.md#ai可选)):
   ```ini
   AI_PROVIDER=openai_compat
   AI_BASE_URL=https://api.deepseek.com/v1
   AI_API_KEY=sk-...
   AI_MODEL=deepseek-chat
   ```
2. 在选股页打开「AI 策略生成器」,用自然语言描述你的策略思路
3. 前端流式接收生成代码,后端经 `ast` 安全校验后返回结果; 保存及文件加载时再次校验
4. 保存后落入 `data/strategies/ai/`,文件名/ID 用 `ai_` 前缀

生成策略相关提示词位于 `backend/app/strategy/prompts/`:

- `strategy-guide-compact.md` — AI 运行时精简指南(用于降低长请求超时概率)
- `strategy-guide.md` — 完整策略开发规范(供人工开发和详细参考)
- `strategy-builder-step2.md` — 步骤 2 提示词模板(修改已有策略)
- `strategy-example.md` — 从零创建强势反包策略的三步演示

> 💡 **文件与范围铁律**:AI 生成的策略只生成一个 `.py` 文件,只 `import polars as pl`,绝不修改 `backend/`、`docs/`、`frontend/` 等现有文件。

生成之后的持续改进(假设—验证—判定闭环),见 [AI 策略迭代指南](./strategy-iteration.md)。

### 📝 方式三:自定义编写 / 代码迁移

可以在选股页「自定义编写」中直接编辑策略代码并保存,新建自定义策略会落入 `data/strategies/custom/`,文件名/ID 用 `custom_` 前缀。也可以手动把已有策略改写为 Polars 文件后放入该目录,引擎会自动发现。

手写策略需遵循 [`strategy-guide.md`](../backend/app/strategy/prompts/strategy-guide.md) 的文件结构(META / basic_filter / scoring / ENTRY_SIGNALS / filter 等),完整规范见该文档。

策略代码仅能导入校验器白名单中的模块。危险内建函数的引用和别名
(如 `run = eval`、`g = getattr`)、dunder 属性及字符串拼接、
模块命名空间句柄、文件读写及进程执行原语、通配和相对导入均会被拒绝。
读取行情应使用策略数据上下文或 `app.strategy.market_data`,不要自行读写文件。
普通行情列 `market.open`、`__name__ == "__main__"` 和说明性文档字符串仍可使用。

引擎会同时校验同目录下的 `_*.py` 辅助文件,辅助文件也不能使用 `vars()` 等内省入口。
主文件或辅助文件无法读取、无法按 UTF-8 解码、存在语法错误或校验异常时,
引擎停止加载并报告错误。旧策略若依赖上述被禁用能力,需改为显式参数及公开数据接口。
AST 检查只拦截已知攻击模式; 多租户私有策略继续由 ComputeExecutor 在受限容器执行。
单机文件加载仍在本进程执行,不能把静态校验当作完整沙箱。

## 策略文件结构(简述)

一个策略 `.py` 文件通常包含:

| 部分 | 作用 |
| :--- | :--- |
| `META` | 策略元信息(名称、参数、方向等),用户可在 UI 调整阈值 |
| `basic_filter(df, params)` | 模式 A:单日过滤,返回 `pl.Expr` |
| `filter_history(df, params)` | 模式 B:历史窗口过滤,返回 `pl.DataFrame`(配 `LOOKBACK_DAYS`) |
| `scoring` | 评分权重,总和 = 1.0 |
| `ENTRY_SIGNALS` / `EXIT_SIGNALS` | 进出场信号列(回测用) |

完整字段说明与示例见 [`strategy-guide.md`](../backend/app/strategy/prompts/strategy-guide.md)。

### 参数分组、显隐与预设

策略设置、回测、优化器和 Walk-Forward 共用以下可选 META 参数字段；旧策略无需修改：

- `group`：相邻同名参数显示在同一组；没有组名时不显示标题。
- `visible_if`：`{"param": "mode", "in": ["advanced"]}`，也支持递归
  `{"all": [...]}` / `{"any": [...]}`。条件读取当前值，缺值时使用参数默认值；
  空 `all` 为真，空 `any` 为假。
- `option_applies`：如 `{"advanced": {"window": 12, "enabled": true}}`。
  主动选择该选项时一次性填写已声明的参数；不递归触发其他预设，不覆盖刚选择的选项。

隐藏参数仍保留、保存并传给策略；策略自身负责判断其适用条件，显隐不是执行逻辑。
扫描仅提交当前条件下可见、已勾选的参数，未扫描值使用面板中的固定值。
控制显隐的参数和带预设的选择器只能设为固定条件，切换后分别扫描，
避免同一网格混入不适用参数。切换条件不清除已有值或扫描范围。
