# TSP Cell 发布说明 · 2026-10-13

本次交付为基于 TSP 0.3.11 的独立 Cell 功能候选，数据库 schema 为 v4。
主应用版本号保持 0.3.11。本文记录代码交付，不表示已发布镜像、创建版本标签或上线。

## 适用范围

- 独立后端入口：`app.cell.main:create_app --factory`。
- 工作空间前端：以 `VITE_CELL_MODE=true` 构建。
- API、实时监控、策略、通知及自动交易 Worker 使用独立 Cell 数据库。
- 行情通过平台只读门面复用标准化服务，Cell 不直接建立行情源连接。
- 原后端入口、桌面端和现有线上入口保持原有业务行为；仅升级原入口不会获得租户隔离。

## 新增

- 固定租户到 Cell 的映射、工作空间目录及 routing epoch 校验。
- owner/admin/member/viewer 四级权限、最后一个 owner 保护、租户绑定 Token。
- PostgreSQL 事务内租户上下文、强制 RLS 和复合租户主键/外键。
- 邮箱登录、服务端会话、登录失败限流、成员管理及 Token 创建/撤销。
- 工作空间前端及缓存隔离，自选证券与分组、策略参数和运行记录、告警及模拟盘。
- 平台内置日线策略目录、版本化参数、冻结输入、持久化任务、取消和执行结果。
- 策略子进程隔离、超时、租约和执行版本保护，执行前及提交前复核授权。
- 价格/涨跌幅监控、持久化冷却和行情序号去重、工作空间收件箱。
- 模拟账户、资金及持仓占用、T+1、费用、滑点、涨跌停、后续报价撮合、撤单和跨日到期。
- 邮件/Webhook 通知 Outbox、失败重试、死信、投递记录与管理员手动重试。
- 模拟策略自动交易：定时选股、交易信号、预算和持仓限制、每日订单配额、止盈止损。
- 独立部署 Dockerfile/Compose、显式迁移和旧账号/自选导入工具、Cell CI。

## 修复

- 非交易日允许开启实时行情。系统保存开启状态并等待下一交易日，休市期间不拉取、
  不写入当日分区；若检测到历史完整性问题，修复任务继续在后台执行。
- 工作日节假日不再误显示为“交易中”，数据页显示“已开启 · 等待交易日”，
  实时监控设置显示“已开启，等待下一交易日”。交易日仍保留原有完整性门禁。

## 调度与容量优化

- 事务内唤醒和活跃工作索引替换全租户轮询，空闲租户不进入评估链路。
- 跨 Worker 租约、到期接管、唤醒版本保护、公平领取和 Cell 共享并发槽位。
- 并行读取租户订阅、合并报价请求、批量写入当前规则状态、复用线程池。
- Cell 与租户容量准入在数据库锁内核算，超额写入返回 `429 cell_capacity_exceeded`；
  暂停、撤单等减少负载的操作继续可用。
- 新租户按预期负载选择 Cell；支持负载导出、目录快照同步及只读拆分方案。
  拆分方案不会隐式改变已有 placement 或搬迁业务数据。

## 行为与配置变化

| 配置/行为 | 默认值与约束 |
| --- | --- |
| 实时复查间隔 | `TSP_CELL_REALTIME_INTERVAL=1` 秒 |
| Compose 实时 Worker | 32 并发，身份和业务连接池各 16 |
| Cell 登记租户上限 | 1000 |
| Cell 实时负载上限 | 200 单位 |
| 单租户实时负载上限 | 100 单位 |
| 负载计量 | 每规则证券引用 1 单位；待成交订单 4 单位；自动交易每最大持仓名额 4 单位 |
| Cell 并发槽位 | 实时 32、策略 4、通知 8、自动交易 8，多个副本共享 |
| 邮件/Webhook | 默认关闭；仅管理员会话配置，启用只影响后续新提醒 |
| 通知网络 | 单次读写 5 秒，独立投递进程总时长最多 8 秒 |
| 通知重试 | 最多 6 次，临时错误退避重试，永久错误进入死信 |
| 自动交易 | 默认关闭，只作用于虚拟模拟账户 |

邮件服务使用运维配置的全局 SMTP，认证密码只进入通知 Worker。
Webhook 仅允许批准的 HTTPS origin，不跟随重定向。
通知使用稳定投递编号，但外部成功与数据库确认不是分布式原子事务，
属于至少一次投递；接收端需去重，邮件 Message-ID 不保证所有邮箱自动去重。

自动选股要求当日新鲜交易报价，日线观察截止为前一日；订单参考行情晚于信号，
成交行情晚于订单参考序号。预算包含滑点和佣金，成交跳价超预算使订单到期。
暂停/修改规则或创建者撤权取消待处理自动信号及订单，已成交持仓保留。

## 数据兼容与迁移

- 新 Cell 服务必须使用 schema v4；启动不自动初始化或迁移数据库。
- 迁移按 v1→v4 顺序保存 checksum，可幂等重跑，校验和变化会拒绝执行。
- 使用独立迁移角色，运行角色不能为超级用户、BYPASSRLS 或业务表所有者。
- v4 保留旧 Cell 负载；超额 Cell 可减少负载，增加负载被拒绝，需要规划拆分。
- 旧账号和自选只能通过显式离线导入迁移，成员关系和 owner 需明确指定。
- 原会话、全局 Token、SMTP/AI/交易凭据及其他旧业务数据不自动迁移。
- 行情继续共享；新的租户业务数据与旧全局数据路径保持独立。
- 两库操作不宣称跨数据库原子性；失败须核对后重试，不直接覆盖用户数据。

压测环境为 macOS Worker、PostgreSQL 17.11 aarch64、专用 Colima 2 CPU/2 GiB，
标准化模拟报价加入 20ms 调用延迟。两秒结论限定在以上样本，不能据此承诺
真实行情网络、多证券、长交易台账或 50 个 Cell 同时运行的生产 SLA。

最终完整镜像构建受 Docker Hub TLS 超时影响；容器验证使用既有依赖镜像覆盖
最新 Cell 源码。发布环境仍需从最终提交重新构建完整镜像并运行 CI。
测试仅使用本地通知接收端/SMTP 替身，没有向真实用户发送消息。

## 升级

1. 对身份库和各 Cell 业务库备份，并保留原服务版本与配置。
2. 暂停待升级 Cell 的 Worker 和业务写入，使用迁移角色升级两库到 v4。
3. 配置独立 Cell ID、运行角色 DSN、共享行情 URL/Token，按需设置 SMTP 和 Webhook origin。
4. 从候选提交构建 Cell API/Worker，配置容量后启动独立入口；构建过程使用锁文件。
5. 验证健康、登录、工作空间隔离、策略、监控及模拟盘，复测实际网络与负载。
6. 完成生产验收后再切换流量；自动交易和外发通知按工作空间显式启用。

迁移命令、配置及业务 API 详见 [Cell 架构与运维说明](../cell-architecture.md)。

## 回滚

原入口未切换时可停止独立 Cell 服务，保留 Cell 数据供后续核对。
已有 Cell 升级后不能将 v4 数据库直接交给旧 schema 服务；
须停写并从发布前完整备份恢复数据库，再切回匹配的代码和配置。
尚未实现自动 schema 降级、在线租户搬迁或跨库业务回滚。

## 已知限制

- 未切换生产入口，未创建发布标签、远端镜像或公开 Release。
- 未验收真实交易时段、多 Cell 总容量和独立故障域。
- 尚无 JetStream、跨 Cell 行情推送、授权副本或 SSE/WS。
- 完整回测、租户密钥/KMS、旧模拟盘数据迁移及在线换组尚未接入。
- 自动交易仅为模拟盘，不包含券商订单、真实资金交易、盘口排队或部分成交。
- 股票策略与模拟结果用于研究，不构成投资建议或收益保证。
