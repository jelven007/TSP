# 当前验收边界

数据就绪卡片的同版本安装证据只适用于当时的发布单元。自然交易日的 08:30／09:00
独立核验、15:35→15:45 及尾盘分钟发布仍按各自新回执签收；周末读取历史回执不能替代。
停复牌覆盖不完整与历史行情补缺是两项独立观察。

旧调查、研究和过程计划已经清理。这里保留需要按当前版本重新核验的边界，
不把历史失败宣称为本次已修复，也不把旧通过数宣称为当前验收。

| 范围 | 依据 | 验收边界 |
| --- | --- | --- |
| 持续运行与容量 | [阶段计划](phase2-implementation-plan.md)、[验收要求](../testing.md#acceptance) | 当前正式版本的完整自然交易日、持续负载、网络和资源余量分别签收 |
| S02历史查询 | [S02契约](../reference/s02.md)、[验收要求](../testing.md#acceptance) | 80ms RTT／50Mbps、并发真实绘制、持续最大负载和至少30%余量；既有安装不等于这些条件通过 |
| 行情来源与量额 | [覆盖契约](../reference/minute-quality-coverage.md) | 按当前发布和真实源端逐项裁定；旧覆盖率、缺口数量和当前Provider不能反推历史来源 |
| 停复牌自动发现 | [市场数据契约](../reference/market-data.md) | 实现、隔离验证、自然调度和完整历史补齐分别判断 |
| 多节点及万人目标 | [目标架构](../architecture.md#target) | 按实际容量触发建设，不能描述为已实现或已签收 |

未完成开发保留自己的工作计划及源码，文件整理不启动数据修复、部署、容量实验或收益回测。
