# 虚拟账户（模拟盘）实现说明

> 状态: V1/V2/V3 主流程已实现。本文档记录当前实现、金融口径、
> API 与剩余边界；不能把“模拟成交”理解为真实可成交性证明。
> 遵循 [CONTRIBUTING.md](../CONTRIBUTING.md) 的数据口径、插件化与测试矩阵要求。

## 1. 目标与非目标

**目标**

- 把「策略 → 信号 → 决策 → 收益」打通为实时闭环: 用户用虚拟资金跟单自己的策略/信号, 以真实行情价格模拟成交, 每天看到虚拟净值曲线与回合统计。
- 与回测互补: 回测重放历史, 模拟盘**实时向前**, 无未来函数, 验证的是「我现在敢不敢按这个信号操作」。

**非目标**

- 不接入券商、不做实盘下单、不提供任何资金通道。
- 不做高频/tick 级撮合模拟，当前为实时快照 + 日线开收盘价撮合。
- 不提供真实资金、券商账户或实盘委托。

## 2. 核心概念与账务模型

| 概念 | 说明 |
|---|---|
| Account 账户 | 初始虚拟资金 + 费用参数 + 状态(active/frozen)，支持多账户隔离 |
| Order 订单 | 买/卖意向; 来源 manual / auto(规则触发); 含订单类型与时效 |
| Exit intent 退出待办 | 自动方向的全平目标; 独立于事件回执和单次卖单, 持久保留到完成或取消 |
| Fill 成交 | 订单的一次实际成交(价格、数量、费用); **append-only 台账** |
| Position 持仓 | 由成交台账推导物化(avg_cost、可卖数量), 可随时重建 |
| NAV 净值 | cash + Σ(qty × 市价) + 应收资产; 收盘后用日线收盘价定版, 盘中用实时价估算 |
| 回合 Round-trip | FIFO 配对的开->平周期, 统计胜率/盈亏比/持有天数 |

**账务正确性原则**(镜像财务报表口径): 成交台账是唯一事实源, 持仓与净值全部可由台账重放推导; 任何修复动作以「冲正成交」记录, 不允许直接改持仓文件。

## 3. 数据模型与存储

沿用 `app/strategy/lots.py` 的域模块模式: 每实体一个 JSON +
`atomic_write_text` 原子写，目录挂在 `data_dir` 下，API 下单、行情撮合和盘后
结算共用域内 `RLock`。旧版单账户目录会在首次访问时幂等迁移到 `default` 账户。

```
data/paper/
  accounts/{account_id}/
    account.json                   # 初始资金、现金、费用、状态、涨跌停排队开关
    orders/order_{id}.json         # pending / filled / cancelled / expired
    fills.jsonl                    # append-only 成交与 corporate_action 台账
    positions.json                 # 物化持仓，可由 fills.jsonl 重建
    nav/daily.jsonl                # 每交易日一条定版净值，含可用时的沪深300收盘
    auto_rules/arule_{id}.json     # 自动跟单规则
    event/{hash}.json              # 带 id/ts 的监控事件处理回执
    exit/{hash}.json               # pending / submitted 自动退出待办
    exit_archive/{hash}.json       # completed / cancelled 退出历史
```

完整多租户模式复用 `PaperSession` 写事务和既有 RLS。自动规则、回执、退出待办
分别存入 `paper_auto:{account}`、`paper_event:{account}`、`paper_exit:{account}` 文档命名空间；
退出终态移入 `paper_exit_archive:{account}`，订单和成交继续使用原模拟盘表。
文件模式通过原子写和原子重命名归档；新卖单在首次落盘时即带 `exit_intent_id`，
即使在订单写入后、待办更新前退出进程，重启也能重新关联。轮询只读取活跃退出，
完整历史由 `paper_auto.load_exit_intents(..., active_only=False)` 按账户读取。

关键字段口径:

- **价格一律不复权 raw 价**(与真实交易一致); 持仓市值用 `raw_close`。
- **公司行为**: 新账户按登记日持仓、现金到账日及股份上市日分别记录红利、送转与
  配股缴款；缺失日期证据时暂停相关入账与撮合，不生成当日定版净值。存量账户
  保留因子估算与旧账本重放，不自动转换。数据契约、认购、应收资产和回滚边界见
  [公司行为账务](corporate-actions.md)。rustdx 当前登记/到账/上市日期未知，不能直接认证清算。
- **费用**: `commission_pct`(双边, 默认万 2.5, 最低 5 元)、`stamp_tax_pct`(卖出印花税, 默认千 1)、`slippage_bps`(默认 5)。
  模拟盘采用账户固定税率，回测可按历史日期取税率；红利按税前金额记录，个人红利税未模拟。

## 4. 撮合规则(金融口径, 必须逐条测试)

| 规则 | 口径 |
|---|---|
| 即时市价单(盘中) | 以订单创建后的**下一次股票实时快照价**成交 + 滑点；当日未收到快照时由盘后结算按首个合格交易日收盘价兜底 |
| 次日开盘单 | 当前交易日首份新鲜 `raw_open` 到达时入账 + 滑点；要求订单/排队早于 09:30，缺字段或除权日回退盘后结算；09:30 后创建的订单不会回填当日开盘 |
| 当日收盘单 | 订单创建后首个尚未打印的交易日 `raw_close` 成交；15:00 后创建的订单不会回填当日收盘 |
| 买入数量 | 100 股整数倍(ETF 同); 资金不足按可用现金向下取整到百股, 不足一手则拒绝 |
| T+1 | 当日买入份额次日方可卖; `Position.available_qty` 在日终结算解锁 |
| 涨跌停 | 默认把触及涨停的买单 / 跌停的卖单置为 `expired` 并留痕；股票按成交日 SCD2 状态识别 ST，账户可开启「排队次日重试」，最多顺延 3 个交易日 |
| 停牌 | 无法取价即不成交, 按顺延规则处理 |
| 撤单 | 仅 `pending` 可撤; 已成交不可逆(只能反向平仓) |

ETF 不进入股票实时快照撮合池，因此 ETF 即时单会自动转为次日开盘单。
所有时间戳取北京墙钟；盘后结算随交易日管道执行。

当日开收盘、前收盘及沪深 300 基准价格通过统一 `scan_daily_parquet`
读取日线。新旧分区可混有 `quote_ts` 等附加列，历史缺列由存储 schema 补齐，
无需迁移已有 Parquet；缺少有效价格时仍按原规则跳过成交或结算。

## 5. 运行时挂点(全部复用现有引擎)

```
盘中:  quote_service._evaluate_monitors 的同一轮
       ├─ 核对退出待办的规则与持仓周期, 撤销失效的退出单
       ├─ 遍历全部账户，处理 pending 即时单(股票实时快照价)
       ├─ 自动规则监听逐证券策略事件/通用监控事件 → 生成订单
       └─ 没有新事件也重试退出待办, 入场仍按跟单规则冷却

盘后:  daily_pipeline stage: paper_settle
       ├─ 公司行为事件入账，再撮合开盘单、收盘单及未成交即时单
       ├─ 收盘权益登记，上市日/T+1 可卖数量由批次日期计算
       ├─ 无权益阻断时写 nav/daily 定版(含基准 000300.SH 同日收盘)
       ├─ 对账退出状态, 重试可提交的 next_open / close 退出单
       └─ 异常 warning 留痕并软失败，不中断其他管道阶段
```

- `MonitorRuleEngine.evaluate(..., execution_events=[])` 在同一次策略计算中追加
  逐证券执行事件。所选事件类型、初始基线、同根 K 线去重和选股池边缘判定保持一致；
  通知仍可按超过 5 只汇总并执行通知冷却，执行输出保留每只证券和价格。
  独立行情服务和受限计算容器均传递该输出；策略通知不会再作为第二份下单输入。
- 自动跟单规则形态:
  `{match_kind: strategy|rule, match_id, side: buy|sell|auto, size_mode: fixed_amount|pct_equity, size_value, order_type, cooldown_days, max_positions, candidate_priority, max_symbol_exposure_pct, max_total_exposure_pct, risk_follow}`。
- `side=auto` 仅用于跟策略：`buy_signal` / `pool_entry` 买入，
  `sell_signal` / `pool_exit` 按账户该标的全部持仓卖出；其他事件忽略。
  买入按金额或权益比例计算，自动退出不受冷却、买入金额和最大持仓限制，
  仍接受原撮合域的 T+1、待成交卖单、冻结和数量校验。先保存退出待办；
  全量不可卖或有其他待成交卖单时等待，后续轮询自动重试，不改为部分卖出。
  其他卖单部分减少持仓后，重试按该持仓周期的剩余数量全平。
- 退出状态为 `pending` → `submitted` → `completed`，失败或撤单可回到 `pending`。
  即时退出须有当前有效行情；开盘/收盘退出可无实时行情提交，继续遵守原有成交时刻限制。
  全平订单过期后保留待办；已失败的即时退出若仍处于跌停价格约束中，等待行情恢复，
  避免每轮生成必然拒绝的订单。账户冻结暂停创建和撮合，解冻后继续。
- 停用、删除自动规则，或修改匹配来源、方向、订单类型，会取消其活跃待办和关联的
  pending 退出单；重新启用不会恢复旧待办，新的退出事件仍可创建新待办。
  仅改名称、买入金额、买入冷却或持仓上限不影响既有全平目标。
  单独撤销一张自动退出订单只取消该次尝试；永久停止该规则的退出应停用或删除规则。
- 持仓 `cycle_id` 取从零建仓的首笔买入订单 ID，由成交台账重放产生，
  部分卖出、加仓及数量调整保持该 ID。全平后再次建仓使用新 ID；
  原退出待办失效并撤销旧 pending 退出单。旧持仓缓存缺少 ID 时从台账重建。
  活跃退出期间，自动买入同一证券会被跳过，避免入场和退出相互冲突。
- `max_positions` 是非负整数，`0` 表示该规则不限；按账户当前正数量持仓与
  pending 买单的标的并集计数，包含手动单和其他规则的订单。
  达限后只阻止新标的买入，已有标的加仓和卖出不受影响。
  撤销/过期买单及已全平标的释放名额；待成交卖单不提前释放持仓名额。
- 旧规则或旧客户端省略新增字段时保留 `side=buy`、`max_positions=0`；
  前端新建策略规则和批量策略账户默认选择自动方向。固定卖出先按固定金额或
  权益比例换算数量，再以「当日 T+1 可卖数量 − 同账户同标的 pending 卖单数量」
  封顶并按 100 股取整；可卖为零时记录 `no_sellable_qty`，不生成订单。
  数量检查和下单仍在同一账户写锁/事务内，不跨账户借用持仓。
  批量来源含监控规则时，必须显式选择固定方向。
- 多租户模式在同一 SQL 写事务内完成名额检查、事件回执和下单；
  被忽略、冷却、达限或拒绝的匹配事件也保留回执，重放不再触发。
  固定方向和入场再次尝试仍需要新事件；自动全平的重试独立推进退出待办，
  不依赖重放原事件。待办、订单、回执与自动下单告警一起提交或回滚。
  Worker 在私有计算完成后再次检查行情年龄，失效行情不创建新入场或即时退出单。
- 自动下单和成交事件复用监控中心的告警存储、SSE、语音/系统通知及
  Webhook/邮件通道，不新增一套推送管道。

### 风控政策、候选排序与开盘入账（第二批）

`risk_policy.py` 统一回测四种撮合路径和模拟盘的止损、固定止盈、移动止损、
回撤止盈参数与触发线。显式 `None` 禁用对应参数；组合校验与百分比归一化共用。
保护线取最高值，跳空用实际开盘价，回撤线使用本次观察之前已知的峰值。

策略执行事件携带有效 `entry_policy`（版本、策略 ID、参数、风控政策、计算日期）
及评分。买单和成交台账保存深拷贝；从零建仓的首笔成交确定本轮政策和入场价格，
加仓、部分卖出及重建不覆盖政策，全平后新建仓使用新政策。
缺少快照的旧持仓不会被套用当前策略；受限计算容器产出元数据，Worker 无须执行私有策略代码。

`risk_follow=true` 允许按入场政策持续管理该规则的持仓。实时行情和盘后结算即使
没有新策略信号，也更新持久峰值并保存风险退出意图；T+1、冻结、待卖单、跌停和撤单
复用全平重试。策略后续修改不重写入场政策。规则停用/删除或关闭风控后取消风险退出；
重新启用后只按新的有效观察重新判断风险。持有期从入场日之后按公布的沪深交易日计数，
包括停牌期间的交易日；未覆盖年份不猜测节假日。

`candidate_priority` 支持 `event`（旧规则默认）、`score`、`symbol`。
评分从高到低，同分按证券代码，缺分/非有限分数最后；退出先于所有买入。
同规则同证券在一轮中只创建一笔买单，避免买入信号与入池事件重复分配。
前端新建规则默认评分优先。`max_symbol_exposure_pct` 与 `max_total_exposure_pct`
均为 0~100 的权益百分比，0 不限制，按账户全部持仓和待买单计算，
包含手动单、其他规则和同股加仓；待卖单成交前不释放额度。
估值优先本轮原始行情，再取最近已落盘原始收盘价，最后以成本估算。
待买单预留滑点和佣金；缺参考价的待买单阻止新的自动分配。
自动买入按现金和仓位余量缩到百股，委托和实际成交均复检仓位与费用；
跳空导致超限时拒单留痕，后续重新入场须有新事件。

实时 `next_open` 入账只消费日期为当日、时间戳年龄不超过 15 秒的原始开盘价，
拒绝明确标为本机接收时间的快照，不使用复权 `open` 替代缺失 `raw_open`。
开盘后创建或排队的单、无法解析创建时刻的旧单及当日有除权事件的单沿用盘后结算。
股票和 ETF 均可提前开盘入账，同日买入仍受 T+1 限制；盘后重跑不会重复成交。

回测按完整 OHLC 推断日内触线，模拟盘只用实际观察到的原始价格，并在后续有效行情
撮合即时退出，盘后发现风险也不会补造盘中成交。模拟盘会保存当日受 T+1 限制的风险，
而回测当日新仓不执行日内风险退出；快照间遗漏、执行时差、成交滑点和这项 T+1
策略差异仍可能使收益不同。除权账务未完成时暂停旧持仓的新风险判定。
盘口排队和部分成交仍属于后续批次。现金分红已接入事件账务，但仍取决于日期证据，
个人红利税不在当前模拟范围。

### 研究配置与前向快照（第三批）

入场叠加条件接入选股、实时监控、日线回测、参数优化与步进优化，先过滤再评分。
显式退出和风险退出不受条件限制；缺字段关闭入场并提示原因，监控不据此制造移出候选池事件。
入场事件将规范化 `overlay_filter` 写入原有政策快照，订单、成交与持仓继续保留入场时的配置。

优化结果保存实际参数试验、完整配置与失败原因，每折样本外验证保留训练明细和测试配置。
沿用 SQL 持久研究任务及公共行情版本绑定，配置变化不能复用旧结果。
DSR 只用完整夏普网格的真实每日组合收益统计计算，明确标记本次网格和独立试验近似，
不替代样本外验证。配置、记录字段与边界详见 [研究配置与试验记录](research-configuration.md)。

### 诊断与体验：估值标记、回合口径与未执行原因（第四批）

总览估值永远是估算口径，与收盘定版净值分开。`overview` 为每个持仓标注价源
（`live` 实时快照 / `daily_close` 最近日线收盘 / `cost` 无行情退回成本占位），
并返回 `valuation`：整体口径、数据时间 `quote_ts`、覆盖 `covered/total` 与缺价 `missing`。
任一持仓缺当前行情退回成本时整体口径保守降级为 `cost`。前端净值曲线仍标「按交易日收盘定版」，
总览另挂估值徽章标注口径、数据时间与覆盖，二者不混用。

回合统计区分两层口径：配对片段（`round_trips`，一次卖出与一个买入批次的 FIFO 配对，
`kind="pairing"`，`cycle_seq` 标注所属持仓周期）与持仓周期（`position_cycles`，从零建仓到
清零的完整周期，收益率按周期总成本资金加权）。`stats` 沿用历史的片段字段
（`rounds`/`win_rate`/`profit_loss_ratio`/`avg_holding_days`），并新增 `cycles` 块
（周期数、周期胜率、资金加权收益率）；`/api/paper/rounds` 并列返回两层明细，不把相关片段当独立样本。

自动跟单每轮被跳过的候选记入按账户的有界列表（`load_auto_skips`）：冷却、持仓名额已满、
缺有效参考价、缺入场政策快照、可买数量为 0、同轮重复、下单被拒等，各带人类可读文案与明细。
它只用于诊断「为什么没下单」，与成交和退出待办分开，不影响撮合。前端在账户面板展示未执行原因列表。

## 6. API 设计(`/api/paper/*`, 薄胶水 + 域模块)

| 方法 | 路径 | 说明 |
|---|---|---|
| GET / POST | `/api/paper/account` | 读取/创建账户；`account` 查询参数选择账户 |
| GET | `/api/paper/accounts` | 账户列表与最新净值摘要 |

## 7. 前端设计

「模拟盘 Paper」是侧边栏一级页面，当前以多账户对比为默认视图:

- **对比总览**:账户数量、合计虚拟资产、平均收益、收益榜单、前 8 名归一化净值叠加；表头可排序，点行展开账户。
- **批量构造**:选择多个策略或监控规则，以相同本金、费用、方向、仓位、最大持仓和订单类型批量创建账户，保证对比条件一致。
- **账户操作**:现金/市值/总资产/盈亏、净值曲线 vs 沪深300、持仓表、订单与成交台账、冻结/解冻、费用与撮合设置。
- **下单**:股票/ETF 联想搜索，按数量或金额下单，支持即时/次日开盘/当日收盘。
- **自动跟单**:按账户维护规则，匹配策略或监控规则，可启停和删除；策略支持自动方向和退出全平，规则摘要展示方向、仓位与最大持仓。
- **研究对比**:将当前账户实盘向前统计与已保存的策略回测候选并列比较。
- **导出**:全部成交台账导出 CSV。

## 8. 统计口径(与回测对齐)

- 回合配对: FIFO; 胜率 = 盈利回合数 / 总回合; 盈亏比 = 平均盈利 / 平均亏损
- 最大回撤基于 nav/daily 定版序列
- 基准: `000300.SH` 同期归一化(数据已有); 盘中估算净值不参与统计, 只展示

## 9. 边界、并发与风控

- **写并发**: 域模块内全局写锁; 盘中 evaluate 与手动下单竞争同一把锁(镜像 mining_manager 的互斥模式)
- **账户限制**: 每账户持仓标的数上限 50；买入不得超过可用现金，不提供杠杆；账户之间账务完全隔离。
- **冻结**: 账户 frozen 后拒绝新订单, 持仓只读; 保留数据可重建
- **数据缺失**: 缺行情/缺因子一律留痕 warning + 顺延, 绝不臆造成交价(金融数据错误原则)
- **停用**: 可冻结账户并隐藏菜单；数据目录独立为 `data/paper/`。删除运行数据前必须先备份并停止服务。
