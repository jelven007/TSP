# TSP v0.4.14 需求基线

本文档定义 TSP `0.4.14` 的产品目标、范围和版本级验收条件。它回答“为什么做、
为谁做、必须做到什么”；页面操作见[操作说明书](../操作说明书.md)，实现边界见
[当前架构](./architecture.md)，验证方法见[测试与验收](./testing.md)。源码候选、
稳定标签和生产部署不是同一状态，具体以[版本基线](./version-baseline.md)为准。

## 1. 产品定位

TSP 是面向量化研究者、策略开发者和内部研究团队的本地优先 A 股量化工作台。系统围绕统一数据
口径，覆盖数据采集、市场研究、策略筛选、回测验证、监控提醒、模拟交易、复盘和
开放接口。

产品必须满足以下原则：

- 用户数据保存在自己的运行环境；独立模式使用本地文件，完整多租户模式使用 PostgreSQL。
- 完整单机多租户提供管理员/租户权限、个人租户初始化和私有业务隔离；一期已完成 100 用户验收。
- 火山引擎生产环境已运行 PostgreSQL schema v6、独立 Gateway、Platform、四类 Worker
  和受限 Compute Broker；源码主线仍须通过 CI 后才能替代已部署的固定镜像。
- 数据源可以替换，但上层策略、指标和回测使用稳定的内部字段与单位。
- 研究结论可追溯到数据窗口、策略参数和成交假设。
- 缺少数据能力时明确提示或停止，不能静默混用其他来源形成错误结果。
- 产品用于研究与模拟，不构成投资建议，也不连接券商执行实盘交易。

## 2. 目标用户与核心场景

| 用户 | 主要目标 | 核心场景 |
| --- | --- | --- |
| 个人量化研究者 | 用统一口径完成选股、验证和复盘 | 同步数据、运行策略、回测、因子检验、导出结果 |
| A 股短线研究者 | 跟踪情绪、连板和异动 | 竞价快照、盘中异动、偏移异动、市场阶段、监控提醒 |
| 策略开发者 | 扩展策略、因子和数据源 | 自定义信号、策略文件、Provider 插件、开放 API |
| 本地部署者 | 可控地运行和维护服务 | Docker/桌面/Dev 部署、配置、备份、恢复、升级 |
| AI 工具使用者 | 通过受控接口查询和触发动作 | AI 助手、Token、SSE、MCP 工具 |

## 3. 版本目标

当前版本目标是形成可本地运行的数据与研究闭环：

1. 七类标准数据能力可以独立选择 Provider，并向上层输出统一契约。
2. 日线、分钟、实时、竞价、财务等数据进入统一存储和计算链路。
3. 策略、因子、回测、监控、模拟盘和复盘能够复用同一数据口径。
4. 核心能力通过 Web UI、开放 API 和 MCP 暴露，并受认证和权限控制。
5. 后端、前端和发布产物具备可重复的自动化构建与测试入口。

## 4. 功能需求

### 4.1 数据与能力路由

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| `FR-DATA-01` | 系统按能力选择数据源，而不是把全站绑定到单一供应商 | 设置页显示能力候选源、生效源和 `usable` 状态 |

| `FR-DATA-03` | 支持日 K、除权因子、分钟 K、全市场分钟、实时行情、五档盘口和财务七类能力 | 能力矩阵来自后端注册表，前端不维护平行清单 |
| `FR-DATA-04` | 支持个股、ETF 和核心指数数据 | 资产类型在存储、查询和缓存键中可区分 |
| `FR-DATA-05` | 日线和 enriched 数据可增量同步，也可按明确范围重建 | 任务状态、进度和失败原因可见，失败不发布半成品；修正任务只在 Parquet 写入或分区删除期间短暂暂停实时行情 |
| `FR-DATA-06` | 可按交易日归档集合竞价终态快照，并可配置保存 09:15–09:25 秒级过程 | 当前要求实时行情生效源为 rustdx；秒级窗口支持 `full`/`preopen`；仅完整性校验通过的数据作为有效归档 |
| `FR-DATA-07` | 页面能查看各类数据覆盖范围和同步状态 | 数据页可区分未配置、无能力、无数据、运行中和失败 |
| `FR-DATA-08` | 名称、ST/风险警示和上市状态按历史时点使用 | 每次成功目录同步维护 SCD2；首次采集前明确标记未知，不用当前状态伪装历史事实 |

### 4.3 策略、因子与回测

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| `FR-STRATEGY-01` | 内置策略、自定义信号和 AI 生成策略使用统一执行入口 | 选股与回测对同一策略使用一致的候选和排序逻辑 |
| `FR-STRATEGY-02` | 支持日线策略和分钟策略 | 系统按策略声明周期路由，数据不足时拒绝伪精确结果 |
| `FR-STRATEGY-03` | 内置策略可登记可选入场候选与入场风险政策，同时保持默认兼容 | 公开策略 ID 和原默认参数不变；成交溢价、ATR/信号低点保护与权益风险预算缺省关闭，缺参考时拒绝入场 |
| `FR-FACTOR-01` | 支持因子检验、因子库、DSL 编辑、组合和挖掘 | 因子版本、窗口、方向和检验结果可追溯 |
| `FR-FACTOR-02` | 挖掘结果不会自动成为生产策略 | 候选必须经用户显式确认后发布 |
| `FR-BACKTEST-01` | 回测支持费用、滑点、T+1 和涨跌停不可成交等 A 股约束 | 成交明细能解释信号日、成交日、价格和费用 |
| `FR-BACKTEST-02` | 支持参数敏感性和滚动样本外验证 | 训练区间与验证区间不重叠泄漏 |
| `FR-BACKTEST-03` | 支持结果导出、保存候选和载入复测 | 导出的概要、净值和交易明细与页面结果一致 |
| `FR-BACKTEST-04` | 回测成交与统计使用可复核的价格、评分、数量、费用和期末持仓口径 | 绝对价格使用原始价；缺评分不参与入场；开盘封板、最低佣金、申报单位、买单过期及未平仓均有明确结果；金额 PF、盈亏比与净期望分开 |

### 4.4 监控、模拟盘与复盘

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| `FR-MONITOR-01` | 支持策略、信号、价格和异动规则 | 规则作用域、逻辑关系、冷却和启停状态可配置 |
| `FR-MONITOR-02` | 支持页面提醒、语音和已配置的外部通知 | 通知失败不阻塞行情主循环，触发记录可查询 |
| `FR-MONITOR-03` | 同轮策略监控共享不可变行情、历史窗口和市场矩阵 | 通用规则仍逐快照求值；同一策略每周期最多执行一次；最新快照邮箱容量为 1，旧计划和超过 15 秒的入场结果不提交 |
| `FR-PAPER-01` | 支持多个虚拟账户、手动下单和自动跟单 | 账户资金、持仓、订单、成交和净值相互可核对 |
| `FR-PAPER-02` | 模拟成交遵守 T+1、费用、滑点和涨跌停限制 | 拒单和未成交原因明确，不伪装成成功 |
| `FR-PAPER-03` | 支持盘后净值定版、账户比较和成交台账导出 | 重复结算具备幂等边界，导出内容可复核 |
| `FR-PAPER-04` | 协调器策略事件进入统一账户组合裁决 | 同周期同股只形成一个决策；买卖冲突退出优先；主策略与全部归因冻结；持仓、待买和最保守账户限额共同约束；部分失败或陈旧周期不新开仓 |
| `FR-REVIEW-01` | 支持盘后复盘生成、保存、下载和通知 | AI 或外部数据不可用时给出可诊断失败信息 |

## 5. 数据与量化约束

以下约束属于验收的一部分，不是实现建议：

- enriched 的技术分析价格与涨跌停判断使用的原始价格必须明确区分。
- 比例、百分数、金额、股数与“手”必须在 Provider 边界转换并用测试固定。
- 交易窗口按实际交易日和北京时间处理，不能依赖服务器本地时区。
- 历史财务和股本数据只能在其公告可见时间之后使用。
- 日线信号不能声称在同日未知价格成交；分钟回测只能使用当时已到达的数据。
- Provider 缺少能力、返回空数据或请求失败时，不得静默跨源补齐。
- 数据刷新先构建完整结果，再通过 generation 或原子替换发布，读取方不得看到半成品。

详细契约见[贡献与复审指南](../CONTRIBUTING.md)。

## 6. 非功能需求

| 编号 | 需求 | 当前验收方式 |
| --- | --- | --- |
| `NFR-01` | 本地单机可部署 | Docker 单容器、桌面包或 Dev 模式可以启动 |
| `NFR-02` | 运行数据持久化 | `DATA_DIR` 可挂载并可执行停机备份、恢复演练 |
| `NFR-03` | 运行状态一致 | 独立模式保持单 Uvicorn worker；完整多租户模式使用持久任务、租户事件和数据库事务，API 与实时网关按既定多进程拓扑运行 |
| `NFR-04` | 自动化质量门禁 | CI 执行后端全量测试、前端测试、lint 和 build |
| `NFR-05` | 失败可诊断 | 健康检查、日志、任务状态和页面错误能定位主要故障层 |
| `NFR-06` | 向后兼容 | 历史配置、策略 JSON、Parquet 和 API 变化需兼容或提供迁移说明 |
| `NFR-07` | 最小权限 | 公网部署启用邮箱账户认证，开放接口 Token 按 scope 授权 |
| `NFR-08` | 可恢复 | 发布前备份可恢复，升级失败有版本镜像或提交可回退 |
| `NFR-09` | 任务状态一致 | 持久任务使用共享状态机；取消和进程中断与业务失败可区分 |
| `NFR-10` | 远程主线自动递增版本 | 本地迭代和功能分支推送不改版本；远程集成到 `main` 后 CI 自动递增一次并同步包元数据、锁文件和当前文档；重跑不重复加号，质量门与镜像使用同一版本提交 |
| `NFR-11` | 公共行情读路径不得触发同步补数 | API/Platform 生产角色遇到缺失历史时快速返回 `503 market_history_unavailable`；只有独立模式可以请求内补数 |
| `NFR-12` | 公共行情发布必须完整 | stock/ETF/index 最新原始日分区存在时，同日 enriched 分区必须存在且覆盖全部原始标的；校验失败不得切换 `current` |
| `NFR-13` | Worker 健康口径一致 | Supervisor 与 API readiness 按 Worker 类型使用同一 freshness；租约续期不伪装业务调度进展 |
| `NFR-14` | Compute 容量有界且可诊断 | Broker 实际启动无网络沙箱探针；并发满只允许短时有界等待；失败仅保留受限 stderr 尾部 |
| `NFR-15` | 16 GiB 单机资源可验算 | 正式预算固定应用内存、单 Compute 上限和数据库连接上界；更改进程、池或并发必须重新验算 |
| `NFR-16` | 备份、保留和告警可执行 | 停写后双库备份必须实际恢复到临时库验证；release 清理保护在用研究版本且默认 dry-run；健康、重启和磁盘事件记录 firing/resolved |
| `NFR-17` | 持续验收不混淆证据 | 当前执行 24 小时百用户主动/被动观察及独立完整交易日验收；旧 72 小时中止窗口保留但不并入结论，24 小时通过不得声明 72 小时认证 |
| `NFR-18` | 策略组运行有界、确定且不阻塞行情热路径 | 一个活动周期加一个最新待处理周期；物理并发默认 1；计算无通知和下单副作用，成功发布后再串行执行组合裁决 |
| `NFR-19` | 页面数据更新保持局部、身份范围隔离 | 行情、设置、策略及账户变化只刷新受影响查询或重挂载当前账户范围；除显式登录跳转外不得用 `window.location.reload()` 恢复状态 |

本版本不承诺未经测量的吞吐量、可用性百分比或恢复时长。需要 SLA 的部署者应在
自己的数据规模、网络和硬件上测量并另行约定。

## 7. 明确非目标

当前版本不包含以下能力：

- 券商交易接入、自动实盘下单或收益承诺。
- 万人横向扩展和十万用户远期容量属于二期后续范围；完整单机多租户属于当前已实现能力，见[一期实施](./phase1-implementation.md)。
- 独立运行模式下由多个 Uvicorn worker 共享进程内任务、SSE、缓存或调度状态。
- 对所有 Provider 提供相同数据覆盖或可用性保证。
- 历史竞价、龙虎榜等能力在所有数据源上的无条件可用。
- 自动灰度、自动数据库迁移、自动备份恢复或自动业务回滚。
- 将回测、AI 解读或模拟盘结果视为投资建议。
- 将“五策略同轮运行”解释为五线程或五进程；当前物理并发保持 1，是否开放 2
  需要独立 P95、RSS 和 Swap 基准。
- 策略组配置/状态 API、前端编组、多租户计算任务接线和真实交易日自动跟单验收；
  当前只接入独立行情服务中的策略监控与模拟盘组合裁决。

## 8. 版本验收

版本候选必须完成以下验收后才能发布：

1. 所有功能需求的受影响验收项有自动化测试或可复现的人工记录。
2. 后端全量测试通过；前端测试、lint 和生产构建通过。
3. 数据源至少完成契约级测试；发布声明涉及真实数据可用性时，另做受控烟测。
4. 核心流程完成一次人工验收：登录、数据能力检测、同步、选股、回测、监控、
   模拟盘、开放 Token。
5. 版本号、变更说明、配置变更、兼容性、备份和回滚步骤已复核。
6. 文档导航和相对链接有效，新增或变更功能已同步到用户、开发、测试或运维文档。
7. 发布产物完成安装/启动、`GET /health`、核心页面和数据目录持久化烟测。

详细执行清单见[测试与验收](./testing.md)和
[发布与上线运营](./release-operations.md)。

## 9. 需求追踪与变更

- 功能需求使用本文件中的稳定编号；测试、Issue 或 PR 可引用对应编号。
- 新增用户可见能力时，先更新范围与验收标准，再更新设计和实现。
- 改变数据口径、成交假设、权限或兼容边界时，必须在 PR 中单独列出。
