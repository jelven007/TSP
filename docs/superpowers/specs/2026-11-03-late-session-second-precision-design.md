# 尾盘建仓功能性秒级时间设计

## 目标

将自定义“尾盘建仓”信号的启动时间改为功能性秒级时间：

- 使用公共 `TimePicker` 的秒模式，显示和保存 `HH:mm:ss`。
- 精确启动时间用于计算启动后 90 秒的确认时点。
- 分钟行情仍按完整分钟 K 线计算，不虚构秒级 K 线。
- 保留现有整分钟定义、六项参数和分钟执行边界。

## 时间语义

以用户选择 `14:30:20` 为例：

| 时点 | 语义 |
| --- | --- |
| `14:30:20` | 精确启动时间，保存到信号参数 `time` |
| `14:30:00` | 向下取整后的启动分钟 K 线标签，价格、全池广度及双周期 MA5 均截止该分钟 |
| `14:31:50` | 精确确认时间，即启动时间加 90 秒 |
| 后续可执行分钟 | 沿现有分钟执行规则向上对齐，不增加秒级撮合能力 |

允许范围为 `13:00:00`～`14:58:00`，包含两端。由此：

- `14:57:59` 合法。
- `14:58:00` 合法。
- `14:58:01` 及之后非法，避免确认和后续分钟执行越过现有收盘边界。

新保存或编辑后的尾盘建仓定义固定使用 90 秒确认。冻结的旧 0 秒、60 秒定义继续按原整分钟语义读取；只有 90 秒定义允许非零秒启动，避免旧定义在分钟 K 尚未完成时提前评估。

## 实现范围

### 前端

- `CustomSignalDialog` 的尾盘启动时间启用 `showSeconds`。
- 不再截断秒或自动补 `:00`，直接保存公共控件返回的 `HH:mm:ss`。
- 校验改为完整秒格式和 `13:00:00`～`14:58:00` 范围。
- 帮助文本同时展示精确启动时间、分钟 K 截止和精确确认时间。
- 摘要继续显示保存的启动时间，并将 K 线截止显示为向下取整后的分钟。

### 后端

- `parameters()` 接受 90 秒定义中的非零秒启动，保持格式、范围和时区校验。
- `evaluation_time()` 使用精确启动时间加确认延迟。
- `bar_time()` 将启动时间向下取整到分钟，作为分钟数据标签。
- 评估、全池公告观察、实时完成门闸和历史回放继续分别使用确认时点与分钟标签。
- 不新增字段、schema、Provider 能力或专用 S01/S02 执行规则。

## 兼容与失败处理

- 现有 `xx:xx:00` 定义的结果不变。
- 旧 0 秒、60 秒定义若出现非零秒参数则拒绝，避免产生无法证明的分钟完成语义。
- 缺少向下取整后分钟 K、完整股票池、昨收或连续 MA5 窗口时仍不触发。
- API 和前端使用相同范围；非法值明确提示，不静默取整保存。
- 本次只改变启动时钟精度，不运行策略、下单或回测。

## 测试设计

先增加失败测试，再实现：

1. 前端选择 `14:30:20`，显示精确秒、确认时间 `14:31:50`，保存并重开仍为 `14:30:20`。
2. Escape 放弃秒级草稿；确认只更新表单，不提前保存。
3. `14:58:00` 可保存，`14:58:01` 被拒绝。
4. 后端 90 秒定义接受 `14:30:20`，分钟标签为 `14:30:00`，确认时点为 `14:31:50`。
5. `14:31:49` 尚不可评估，`14:31:50` 可以评估，且只消费 `14:30:00` 及此前数据。
6. 旧 0 秒、60 秒定义保持整分钟兼容，非零秒失败。
7. API 回放保留精确确认时间和分钟标签；分钟执行不借用未完成行情。
8. 浅色/深色、桌面/窄屏实际页面验证秒列、取消、确认、保存重开和边界错误。
